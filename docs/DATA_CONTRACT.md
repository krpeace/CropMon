# 데이터 계약 (DATA_CONTRACT)

계산 저장소(croplib-dp, Python)가 Supabase에 올리는 자료와, 이 웹이 읽는 자료의 약속입니다. 테이블을 바꾸면 이 문서와 `supabase/migrations/`를 같은 PR에서 고치고 버전을 올립니다. `src/infra/supabase/contract.test.ts`가 이 문서의 테이블 목록과 마이그레이션이 같은지 자동으로 검사합니다.

## 현재 버전: v1.5 (2026-10-28)

- 11/06 공개에 필요한 공개 테이블 14개(v1 9개 + v1.1 재배 방식별 Kc `crop_kc_sets` + v1.3 3일 전망 요약 `water_outlook_summary` + v1.4 적산온도 `heat_daily`·적산일사 `sun_daily` + v1.5 작물 공통 토양 물 상태 `soil_water_daily`)와, 연결 확인용 `app_health`가 있습니다 (총 15개 테이블).
- 회원제 개인 테이블(내 농장, 관수 기록, 농장별 보정값)은 1/1 회원 공개에 맞춰 v2로 더합니다.
- 작물 공통(흙만 본 물 상태)은 v1.5에서 더했습니다. "기준작물(잔디)" 대신 **"작물 공통"**으로 부르며, 고정 조건(겉흙 깊이 0.5 m, 증발 수요 = ETo × 1.0, p = 0.40, 3/1에 Dr = 0(포장용수량)으로 시작, 지표유출·모관상승 0, FAO-56 식 (84)~(88))으로 계산합니다.
- 적산온도·적산일사는 v1.4에서 더했습니다. 평년은 지난 10년(2016–2025) 같은 날의 평균입니다(cropweather 방식). 기상청 공식 30년 평년값(1991–2020)은 아직 쓰지 않습니다.
- 사전 자료(실제 값): 지점·작물·작형·토성은 `supabase/migrations/20261024010000_seed_dictionaries.sql`, 재배 방식별 Kc와 기본 계산 조건은 `20261024030000_seed_kc_sets.sql`, 추정 토성 3종 및 작물 공통(common)은 `20261028010000_seed_soil_estimates.sql`에 있습니다. 값을 고칠 때는 기존 파일들을 고치지 않고 새 파일을 더합니다. 기본 계산 조건의 TAW·RAW는 사과 130·65 mm, 여름배추 65·29.25 mm입니다(양토, 뿌리깊이 사과 1.0 m·배추 0.5 m).

## 공통 규칙

- **이름:** 영문 소문자와 밑줄. 단위가 있는 값은 이름 끝에 단위를 붙입니다 (`eto_mm`, `tmax_c`, `rh_mean_pct`). 화면이 단위를 추측할 필요가 없게 하려는 것입니다.
- **날짜와 시각:** 날짜는 한국 날짜(`date`), 시각은 시간대 포함(`timestamptz`)입니다.
- **결측:** 값이 없으면 빈 칸(null)으로 두고 0을 넣지 않습니다. 화면은 null을 "자료 없음"으로 보여 줍니다. 채운 값은 `filled = true`로 표시해 "채운 값"을 구분합니다.
- **계산 버전:** 계산 결과에는 `calc_version`(croplib-dp 버전)을 남겨, 식을 고친 뒤에도 어느 계산으로 나온 값인지 알 수 있게 합니다.
- **권한:** 모든 테이블에 RLS를 켭니다. 비회원(`anon`)과 회원(`authenticated`)은 읽기만 가능하고, 쓰기는 croplib-dp의 서버 키(service role)만 합니다. 서버 키는 이 저장소의 화면 코드에 넣지 않습니다.
- **값의 범위:** 범위 검사(예: ETo 0~15 mm/d)는 croplib-dp가 올리기 전에 합니다. DB는 키, 연결, 이름이 정해진 칸처럼 구조만 막습니다. 범위 규칙을 고칠 때 DB를 바꾸지 않아도 되게 하려는 것입니다.
- **원자료:** 시각별 예보와 API 응답 원문은 DB가 아니라 Storage의 비공개 버킷 `raw`에 압축해 둡니다(v1.2에서 버킷을 만듦). 비회원·회원은 읽을 수 없고, croplib-dp의 서버 키만 씁니다. 위치는 `forecast_runs.raw_path`에 남깁니다.
- **2계층:** FAO-56 표준값(`crops`, `crop_seasons`, `crop_kc_sets`, `soil_types`)과 농장별 보정값(v2의 `crop_overrides`)을 따로 둡니다. 사용자가 고친 작기 시작일도 보정값 층에 저장하고, 표준값은 바꾸지 않습니다.

## 토양수분 상태 판정

`water_balance_daily`와 `water_outlook`의 `status`에는 아래 코드를 저장합니다. 화면 이름은 `src/domain/water-status.ts`가 붙입니다. 서비스 엑셀과 같은 기준이며, 위에서부터 차례로 판정합니다.

| 코드      | 토양수분 상태 | 조건                             | 판정하는 날      |
| --------- | ------------- | -------------------------------- | ---------------- |
| `dormant` | 휴면기        | 생육기 밖 (Kc ≤ 0)               | 관측·예보        |
| `wet`     | 과습          | 생육기이고 Dr이 0 (0.05 mm 미만) | 관측 물수지 날만 |
| `normal`  | 보통          | 0 < Dr < 여유 기준               | 관측·예보        |
| `caution` | 주의          | 여유 기준 ≤ Dr < RAW             | 관측·예보        |
| `need`    | 관수 필요     | Dr ≥ RAW                         | 관측·예보        |

- **여유 기준:** 지금은 RAW × 0.5입니다.
- **과습은 관측 물수지 날만 판정합니다.** 예보로 진행한 날(`water_outlook`)에는 과습을 판정하지 않으므로, 이 표의 `status`에는 `wet`이 들어갈 수 없습니다.
- 이 기준은 이론 근거가 아직 약해서 서비스를 운영하면서 다듬습니다. 판정 규칙과 여유 기준은 croplib-dp 계산 코드에 있고, 바꾸면 `calc_version`을 올려 어느 규칙으로 낸 판정인지 남깁니다. 코드 이름이 그대로면 테이블 구조는 바뀌지 않습니다.
- 디자인 시안의 "아직 여유"는 주의(`caution`), "토양 수분 충분"은 보통(`normal`), "과습 경고"는 과습(`wet`)입니다. 시안의 예시 값(춘천 사과 Dr 31 / RAW 35 → 주의, 태백 사과 Dr 9 / RAW 35 → 보통)이 이 기준과 맞습니다.
- 3일 전망 요약(`status_start`)의 휴면기는 회차 발표 날짜(한국 날짜)의 Kc로 판정합니다. 작기 마지막 다음 날 아침에 관수를 권하거나, 작기 첫날 아침에 휴면기로 나오는 하루 어긋남을 막기 위해서입니다 (croplib-dp 결정 0015).

## 흙 물 상태 판정 (작물 공통)

`soil_water_daily`의 `status`에는 아래 코드를 저장합니다. 화면 이름은 이 표를 따릅니다. 위에서부터 처음 맞는 것으로 판정하며, 판정은 croplib-dp가 하고 화면은 이름만 붙입니다. 작물용 `status`(`need`, `caution`, `normal`, `wet`, `dormant`)와는 **섞지 않습니다** (표가 다르고 코드도 다릅니다).

| 코드       | 화면 이름 | 조건                                                           |
| ---------- | --------- | -------------------------------------------------------------- |
| `winter`   | 겨울철    | 12~2월 (판정 안 함)                                            |
| `pool`     | 물 고임   | 그날 끝 Dr = 0 (0.05 mm 미만) 이고, 그날 또는 전날 `dp_mm` ≥ 1 |
| `ample`    | 충분      | `aw_pct` ≥ 80                                                  |
| `fair`     | 보통      | 60 ≤ `aw_pct` < 80                                             |
| `dry`      | 건조      | 30 ≤ `aw_pct` < 60                                             |
| `very_dry` | 매우 건조 | `aw_pct` < 30                                                  |

- 60%는 RAW 경계(p = 0.40), 30%는 증발산이 절반으로 줄어드는 점(Ks = 0.5)입니다. 80%는 화면 구분용입니다.
- 비가 없으면 건조까지 남은 날(`days_to_dry`)은 `fair`일 때만 채웁니다.

## 테이블별 열

만드는 파일은 `supabase/migrations/20261024000000_data_contract_v1.sql`입니다. `crop_kc_sets`와 `scenarios.kc_set_id`는 `20261024020000_data_contract_v1_1.sql`, `app_health`는 `20261022000000_app_health.sql`입니다. `water_outlook.lead_day`의 범위와 Storage 버킷 `raw`는 `20261024040000_data_contract_v1_2.sql`이 고치고, `water_outlook_summary`는 `20261025000000_data_contract_v1_3.sql`, `heat_daily`·`sun_daily`와 작물 사전의 `t_base_c`·`gdd_stages`는 `20261026000000_data_contract_v1_4.sql`이 만듭니다. `soil_water_daily` 표와 `soil_types.is_estimated` 열은 `20261028000000_data_contract_v1_5.sql`이 만들고, 추정 토성 3종 값과 작물 공통(common) 사전은 `20261028010000_seed_soil_estimates.sql`이 넣습니다.

| `sort_order`         | 정수            | 화면 목록 순서                                                                                  |

### `public.crops`

작물 사전입니다. 작물에 따라 정해지는 값만 둡니다. 작형에 따라 달라지는 값은 `crop_seasons`에 둡니다.

| 열                           | 형식          | 뜻                                                           |
| ---------------------------- | ------------- | ------------------------------------------------------------ |
| `crop_id`                    | 문자, 키      | "apple", "kimchi_cabbage"                                    |
| `name_ko`                    | 문자          | 사과, 배추                                                   |
| `kc_ini`, `kc_mid`, `kc_end` | 수            | 기본 재배 방식의 작물계수 (사본). 계산은 `crop_kc_sets`를 씀 |
| `zr_m`                       | 수            | 뿌리깊이 (m)                                                 |
| `p`                          | 수            | 수분고갈계수, 0~1                                            |
| `h_m`                        | 수, 비어도 됨 | 작물 높이 (m)                                                |
| `source`                     | 문자          | 근거 (예: FAO-56 Table 12)                                   |
| `t_base_c`                   | 수, 비어도 됨 | 적산온도 기준온도 (℃, v1.4). 사과·배추 4                     |
| `gdd_stages`                 | 정수 목록     | 적산온도 단계 (℃·일, v1.4). 사과 500~4000, 배추 300~1200     |

- 배추의 `crop_id`는 cropwater 작물 사전과 같은 `kimchi_cabbage`입니다. cropwater의 `cabbage`는 양배추입니다.
- 화면 주소(`?crop=cabbage`)의 배추 이름은 DB의 `kimchi_cabbage`와 다릅니다. DB를 읽는 화면 서비스를 만들 때 맞춥니다.
- v1.1부터 Kc는 재배 방식별 표 `crop_kc_sets`에 있습니다. 이 표의 Kc 칸은 예전 SQL을 다시 실행해도 오류가 나지 않게 남겨 둔 사본이며, 사전 자료가 기본 재배 방식 값으로 맞춥니다(사과 0.50 / 1.20 / 0.95).
- 작물 공통의 적산온도를 기록하기 위해 `crop_id = 'common'`('작물 공통', Kc 1.0, Zr 0.5 m, p 0.40, 기준온도 5℃, 적산온도 단계 [1000, 2000]℃·일) 행이 포함되어 있습니다 (결정 0020, v1.5).

### `public.crop_seasons`

작형 사전입니다. 사과 같은 과수는 한 해에 생육기가 하나입니다. 배추 같은 채소는 같은 작물이라도 봄·여름·가을·월동 작형마다 심는 때와 생육 기간이 다릅니다. 그래서 작물과 작형을 나눕니다. 나중에 고추·무 같은 작형 작물을 더할 때도 이 표에 줄만 늘리면 됩니다.

| 열                                          | 형식            | 뜻                                                      |
| ------------------------------------------- | --------------- | ------------------------------------------------------- |
| `season_type_id`                            | 문자, 키        | "apple-main", "kimchi_cabbage-summer"                   |
| `crop_id`                                   | 문자            | `crops`를 가리킴                                        |
| `name_ko`                                   | 문자            | 사과, 여름배추(고랭지)                                  |
| `start_mmdd`                                | 문자, 비어도 됨 | 기본 시작일 "MM-DD". 아직 안 정했으면 빈 칸             |
| `l_ini_d`, `l_dev_d`, `l_mid_d`, `l_late_d` | 정수, 비어도 됨 | 생육단계 일수 (초기·발달·중기·후기). 합이 생육 기간     |
| `is_default`                                | 참/거짓         | 작물별 기본 작형 (작물마다 하나). 비회원 화면에 보여 줌 |
| `source`                                    | 문자            | 근거                                                    |

- 값이 빈 작형은 화면 선택지에 나오지 않습니다.
- 처음 넣을 값: 사과 4월 1일부터 20·70·90·30일(210일, 2026년은 10월 27일까지), 여름배추(고랭지) 7월 1일부터 25·30·25·10일(90일, 9월 28일까지). 봄·가을·월동배추는 줄만 만들고 값은 비웁니다.
- 생육단계 일수는 cropwater 작물 사전 값입니다. 배추는 태백 실측으로 보정할 예정입니다.

### `public.crop_kc_sets`

재배 방식별 작물계수(Kc)입니다(v1.1). 같은 작물이라도 재배 방식에 따라 물을 쓰는 양이 다릅니다. 사과는 FAO-56 Table 12에 과원 바닥 관리(청경·초생 재배)와 서리 유무에 따라 네 가지가 있습니다. cropwater에서는 "시나리오 1~4"라고 불렀는데, `scenarios`(계산 조건)와 헷갈려서 여기서는 **재배 방식**이라고 부릅니다.

| 열                           | 형식            | 뜻                                                         |
| ---------------------------- | --------------- | ---------------------------------------------------------- |
| `kc_set_id`                  | 문자, 키        | "apple-k3" (작물-k번호)                                    |
| `crop_id`                    | 문자            | `crops`를 가리킴                                           |
| `set_no`                     | 정수            | FAO-56 Table 12 순서 번호 (cropwater 시나리오 번호와 같음) |
| `name_ko`                    | 문자            | 화면 이름 (예: 초생 재배, 서리 지역)                       |

### `public.scenarios`

| `etc_sum_mm`           | 수, 비어도 됨   | 주 지표 날들의 예보 ETc 합                                                                                                                                           |
| `etc_sum_err_mm`       | 수, 비어도 됨   | 그 합의 오차 (±)                                                                                                                                                     |
| `rain_sum_mm`          | 수, 비어도 됨   | 주 지표 날들의 예보 강수 합                                                                                                                                          |
| `rain_expected_sum_mm` | 수, 비어도 됨   | 주 지표 날들의 기대 강수 합 (강수량 × 강수확률)                                                                                                                      |
| `calc_version`         | 문자            | 계산 버전                                                                                                                                                            |

- 날짜로 바꾸는 법: 예상일 k번째 날 = 그 회차의 주 지표 첫날 + (k − 1)일. 아침 회차의 첫날은 그날(D+0), 저녁 회차는 다음 날(D+1)입니다.
- 나중에 7일·14일로 늘리면 `horizon_days`만 바뀌고 표 구조는 그대로입니다.

### `public.heat_daily`

적산온도입니다(v1.4). 온도 화면과 종합 화면이 읽습니다. 키는 지점 × 작물 × 날짜(`stn_id`, `crop_id`, `date`)입니다. 그해 1월 1일부터 12월 31일까지 줄이 있고, 아직 오지 않은 날은 올해 값이 비어 있고 평년 값만 있습니다(그래프의 평년 선).

| 열                                 | 형식            | 뜻                                                                                      |
| ---------------------------------- | --------------- | --------------------------------------------------------------------------------------- |
| `t_base_c`                         | 수              | 계산에 쓴 기준온도 (℃)                                                                  |
| `gdd_day`, `gdd_cum`               | 수, 비어도 됨   | 올해 그날 적산온도 = max((최고+최저)/2 − 기준온도, 0), 1월 1일부터의 합 (℃·일)          |
| `gdd_normal_day`, `gdd_normal_cum` | 수, 비어도 됨   | 평년 그날 값(같은 날의 10년 평균)과 1월 1일부터의 합                                    |
| `lead_days`                        | 정수, 비어도 됨 | 평년보다 며칠 빠른가 (+ 빠름, − 늦음): 평년 누적이 올해 그날 누적에 닿는 날과 그날의 차 |
| `normal_from`, `normal_to`         | 정수            | 평년 기간 (2016, 2025)                                                                  |
| `filled`                           | 참/거짓         | 기온 결측을 채운 날                                                                     |
| `calc_version`                     | 문자            | 계산 버전                                                                               |

### `public.sun_daily`

적산일사입니다(v1.4). 햇빛 화면과 종합 화면이 읽습니다. 키는 지점 × 날짜입니다. 일사를 재지 않는 지점(태백)은 줄이 없고, 화면은 "자료 없음"을 보여 줍니다.

| 열                                     | 형식          | 뜻                                                   |
| -------------------------------------- | ------------- | ---------------------------------------------------- |
| `rs_day_mj`, `rs_cum_mj`               | 수, 비어도 됨 | 올해 그날 일사량과 1월 1일부터의 합 (MJ/m²)          |
| `rs_normal_day_mj`, `rs_normal_cum_mj` | 수, 비어도 됨 | 평년 그날 값(같은 날의 10년 평균)과 1월 1일부터의 합 |
| `normal_from`, `normal_to`             | 정수          | 평년 기간 (2016, 2025)                               |
| `filled`                               | 참/거짓       | 일사 결측을 채운 날                                  |
| `calc_version`                         | 문자          | 계산 버전                                            |

### `public.soil_water_daily`

작물을 고르지 않고 흙(토성)만 반영한 물 상태입니다(v1.5). 종합 화면의 작물 공통 카드와 토양 화면이 읽습니다. 키는 지점 × 토성 × 날짜(`stn_id`, `soil_code`, `date`)입니다. 한 해 10지점 × 12토성 × 365일 ≈ 4.4만 줄입니다. 겨울(12~2월) 줄도 두되 `status = 'winter'`, `dr_mm`·`aw_pct`는 비어 있습니다.

| 열                        | 형식            | 뜻                                                               |
| ------------------------- | --------------- | ---------------------------------------------------------------- |
| `stn_id`                  | 문자, 키        | `stations` 가리킴                                                |
| `soil_code`               | 문자, 키        | `soil_types` 가리킴                                              |
| `date`                    | 날짜, 키        | 한국 날짜                                                        |
| `eto_mm`, `rain_mm`       | 수, 비어도 됨   | 그날 ETo·강수 (mm)                                               |
| `eto_7d_mm`, `rain_7d_mm` | 수, 비어도 됨   | 그날까지 7일 합 (화면 "최근 7일" 문구용, mm)                     |
| `dp_mm`                   | 수, 비어도 됨   | 그날 심층침투 (저장 한도를 넘어 빠진 물, mm)                     |
| `dr_mm`                   | 수, 비어도 됨   | 그날 끝 부족한 물 (0~TAW, mm)                                    |
| `taw_mm`, `raw_mm`        | 수              | 담을 수 있는 물(TAW), 건조 시작점(RAW) (mm)                      |
| `aw_pct`                  | 수, 비어도 됨   | 흙 속 남은 물 % = (TAW − Dr) ÷ TAW × 100 (0~100)                 |
| `status`                  | 문자, 비어도 됨 | 작물 공통 상태 코드 여섯 가지 (위 "흙 물 상태 판정 (작물 공통)") |
| `days_to_dry`             | 정수, 비어도 됨 | 비가 없으면 건조까지 남은 날 (`fair`일 때만)                     |
| `filled`                  | 참/거짓         | 채운 값에 기대는 날                                              |
| `calc_version`            | 문자            | croplib-dp 계산 버전                                             |
| `updated_at`              | 시각            | 올린 시각                                                        |

## 바꿀 때의 순서

열을 더하거나 바꾸려면 이 저장소에서 마이그레이션과 이 계약서를 같은 PR로 고치고 버전을 올립니다(v1 → v1.1). 그다음 croplib-dp의 업로드 코드와 계약 검사를 새 버전에 맞추고, 두 PR에 서로의 링크를 답니다. 화면이 아직 쓰는 열은 지우지 않고, 새 열을 더하는 방식으로 바꿉니다.
