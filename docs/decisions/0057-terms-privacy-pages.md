## 결정

### 1. 주소 두 개 — `/terms` · `/privacy`

- **로그인 없이 누구나**(비회원 · 검색 로봇 포함) 열린다. `src/middleware.ts`는 `st` 파라미터만 보고 이 주소에는 아무것도 하지 않는다(확인함).
- 쪽 제목 "이용약관" · "개인정보처리방침"(`CropMon · …`), DB를 읽지 않는 화면이다. 휴대폰은 2단계 화면(`EXTRA_SCREENS`에 두 주소 모두 `{ kind: "title", title: "약관", back: true }` — 맥락 바 제목 "약관" + 뒤로 화살표). 데스크톱은 같은 내용을 셸 안에서, 본문 폭을 720px(`max-w-180`)로 제한한다.
- **정적 화면인지 확인한 결과**: 빌드 출력에서 `/terms` · `/privacy`는 다른 모든 쪽처럼 `◐`(부분 정적 — 루트 레이아웃의 머리 줄이 동적이라 `○`가 될 수 없음)이고, 본문은 빌드 때 만든 정적 부분에 들어 있다. 빌드 뒤 글 폴더를 치우고 서버를 띄워도 두 주소는 200으로 본문을 그대로 보낸다. 다만 실행 때 부품이 다시 실행되며 글 파일을 다시 읽으려 하므로(요청마다 `ENOENT`가 로그에 남음) **실행 환경에 글 파일이 있어야 한다** — 빌드의 파일 추적 목록(`.next/server/app/{terms,privacy}/page.js.nft.json`)에 두 글 파일이 들어 있음을 확인했다(Vercel 실행 묶음에 같이 들어간다).

### 2. 본문은 저장소 안의 글 파일 — 판(버전)

- `content/legal/terms-2027-01-01.md`, `content/legal/privacy-2027-01-01.md`. **이슈 댓글에서 `<!-- 본문 시작 -->` ~ `<!-- 본문 끝 -->` 사이를 프로그램이 그대로 잘라 쓴 것**이고(손으로 옮기지 않음, 앞뒤 빈 줄만 정리 — 본문 안의 빈 줄 · 공백은 그대로), 글자 하나도 고치지 않았다. **Prettier가 글자를 바꾸지 않게 `.prettierignore`에 `content/legal/`을 더했다**(표 정렬 · 목록 기호를 건드리므로). 줄 끝 LF는 `.gitattributes`의 `* text=auto eol=lf`가 이미 보장한다.
- `src/domain/legal.ts`에 문서 정보 `{ id, title, version, effectiveDate, edition, draft, previous }`. **`version` 문자열(`terms-2027-01-01`, `privacy-2027-01-01`)은 L4 동의 기록(`members.terms_version` · `privacy_version`)에 그대로 저장할 값**이다. 판이 바뀌면 새 글 파일을 더하고 `version` · `effectiveDate` · `edition`을 바꾸고 이전 판을 `previous`로 옮긴다.
- **"이전 판 보기"**: 지금은 제1판이라 이전 판이 없다. `previous: []` 자리만 두고 **화면에는 그리지 않는다**(이전 판이 있을 때 그리는 일은 그때).
- 시험이 글 파일을 검사한다: 약관에 "제1조"~"제11조"와 "부칙", 방침에 "### 1." ~ "### 15."가 모두 있고, 두 파일 모두 "초안 안내" · "공개 전" · 표시 줄(`<!--`) · HTML 태그 · CRLF · 보이지 않는 글자가 없음.

### 3. 마크다운 그리기 — 작은 변환기를 직접 (의존성 추가 없음)

- `src/domain/legal-markdown.ts`(순수 함수 `parseLegalMarkdown`)가 글을 값(제목 · 문단 · 번호 목록(안에 점 목록) · 점 목록 · 표 · 굵은 글씨)으로 바꾸고, 화면(`legal/LegalBody.tsx`)은 그 값을 React 글자 노드로만 그린다.
- **고른 이유**: ① 글이 두 개뿐이고 문법이 정해져 있다. `react-markdown` + `remark-gfm`은 unified 계열 의존성 수십 개를 끌어오는데, 법적 문서를 공개하는 화면의 공급망 표면을 넓히기 싫다. ② **글 안의 HTML은 그리지 않는다**를 구조로 보장한다 — `dangerouslySetInnerHTML`이 없고, HTML 태그가 보이면 변환 단계에서 오류가 난다. ③ 순수 함수라 단위 시험이 쉽다. 새 문법(링크 · 기울임 등)이 필요해지면 그때 라이브러리 도입을 다시 판단한다.
- **엄격하다**: 아는 모양이 아닌 줄(닫히지 않은 `**`, 코드 표시, HTML, 이상한 들여쓰기, 칸 수가 안 맞는 표 …)은 조용히 버리지 않고 줄 번호가 든 `LegalMarkdownError`를 낸다 — 빌드가 실패하므로 글 일부가 사라진 채 공개되지 않는다. 시험이 두 글을 끝까지 변환해 **글이 하나도 안 사라졌는지**(표시를 걷은 글자 전체가 같은지) 확인한다.
- **번호는 원문 숫자 그대로**: 변환기가 번호 목록의 원문 번호를 값으로 갖고 화면이 `<li value>`로 그린다(1부터 다시 세지 않음). **표 머리 칸은 `<th scope="col">`**, 칸 안의 굵은 글씨도 같은 변환을 거친다.

### 4. 화면 모양 (위에서 아래로)

1. **두 문서 바꾸기**: "이용약관 | 개인정보처리방침" 링크 두 칸(높이 44, `aria-current="page"`).
2. **"예시 글" 배지 + 안내 한 줄**: "전문가 확인을 거친 초안이에요. 2027년 1월 1일 시행 전에 바뀔 수 있어요." — `legal.ts`의 `draft: true` 하나로 켜고 끈다(`draftNotice()`가 `draft`가 거짓이면 아무것도 안 돌려줌, 단위 시험).
3. **시행일 줄**: "시행일 2027년 1월 1일 · 제1판".
4. **본문**: 제목 세 단계(문서 제목 24 · 조/번호 제목 18 · 작은 제목 16), 본문 16(글씨 크기를 따름, 줄 간격 넉넉). **표는 상자로 감싸 표만 가로로 스크롤**한다(문서 전체는 안 넘침). 표 최소 폭은 칸 수 × 8em(글자 크기를 따름)이라 칸이 많은 표(방침 7번 6칸)만 좁은 화면에서 스크롤되고 2칸 표는 그대로 들어간다(처음에 고정 폭으로 두었다가 6칸 표의 칸이 한 줄에 몇 자씩 접히는 것을 캡처에서 보고 바꿨다).
5. **운영자 표기**: `operatorSegments()`로(`shell/OperatorLine.tsx` — 바닥글과 같은 부품으로 합침). 마디마다 줄바꿈 금지 + 점(·)은 앞 마디 끝. **예외: 약관 화면에서는 주소 마디만 줄바꿈을 허용한다**(`wrapAddress`). 주소는 한 덩어리로 놓으면 휴대폰 본문 폭(390 화면에서 358px)보다 길어(100%에서 약 398px, 150%에서 458px) 오른쪽이 화면 밖으로 잘렸다 — 이슈의 "마디마다 줄바꿈 금지(바닥글과 같은 방식)"는 폭이 넉넉한 데스크톱 바닥글 기준이라, 번호가 든 마디(회사 · 대표 · 사업자등록번호 · 전화)는 그대로 쪼개지지 않게 두고 주소만 풀었다. 바닥글(데스크톱 1024 이상)은 그대로 모든 마디 줄바꿈 금지.
6. 쪽 큰 제목 `h1`은 화면 읽기용으로만 두고(`sr-only`) 본문 첫 제목(`##`, "CropMon 이용약관")을 문서 제목으로 보인다.
