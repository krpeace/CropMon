# 결정 0050: 아래에서 올라오는 시트 — 휴대폰 작물·지역 고르기 (이슈 #157)

- 날짜: 2026-11-19
- 상태: 확정
- 관련 이슈: #157 (순서표 #144의 S2-2, #155를 둘로 나눈 뒤쪽). 결정 0049(맥락 바)와 결정 0030(예전의 선택 줄 아래 펼침 판)을 이어받는다.
- 기준: 디자인 규칙 v0.4.6 12절, 시안 v0.4.1 작물 고르기 · 지역 시트

## 배경

#155로 휴대폰 위쪽이 맥락 바 한 줄이 됐지만, 작물·지역 판은 아직 **바 바로 아래로 펼쳐지는 판**(`SelectionPanel`)이었다. 디자인 규칙은 **화면 아래에서 올라오는 시트**다. 한 손으로 엄지가 닿는 자리이고, 앞으로 올 로그인 시트 · 관수 기록 시트 · 내 계정 시트와 같은 모양이 된다. 데스크톱(1024 이상)의 팝오버는 그대로다.

## 결정

1. **`SelectionPanel`을 `BottomSheet`(`shell/BottomSheet.tsx`)로 바꾸고, 다른 시트도 이 부품을 쓴다.** 선택 줄에 붙는 판(`anchorRef`)이 아니라 일반 아래 시트이므로 이름을 바꾸고 `anchorRef`를 없앴다. 로그인 시트 · 관수 기록 시트 · 내 계정 시트가 만들어질 때 같은 부품(덮개, 손잡이, 끌어서 닫기, 키보드 · 안전 영역 처리)을 쓴다 — 시트마다 따로 만들지 않는다.
2. **모양**: 화면 아래에 붙는 시트(`fixed bottom`, 위 모서리만 둥글게 `rounded-t-sheet`, 맨 위 끌기 손잡이). 시트 안은 머리(제목 + "닫기") → 내용이고, 내용은 지금 판 그대로다(작물: 작물 공통 / 사과 / 배추 + "한 번 고르면 모든 메뉴에 적용돼요", 지역: 검색 + 대표 10곳 + 전체, `shell/pickers.tsx`). 재배 방식 · 흙 고르기는 물 화면 안에 그대로 있다. 작물 시트의 ✓는 고른 줄 하나에만.
3. **덮개**: 화면 전체(`inset-0`, z-40)로 뒤 화면을 덮는다 — 탭바(z-30) · 맥락 바(z-20)까지. 덮개를 누르면 닫힌다. **예전 판은 머리말을 덮지 않았지만(누른 버튼과 판이 이어져 보이게) 이제는 규칙대로 덮는다.** 그래서 시트가 열려 있는 동안 맥락 바의 칸이나 "로그인"을 직접 누를 수 없고, 누르면 시트만 닫힌다.
4. **보이는 화면 기준 위치와 크기.** 아이폰 사파리 · 안드로이드 크롬은 키보드가 올라와도 `fixed bottom: 0`(레이아웃 뷰포트 기준)이 키보드 밑에 가려진다. 그래서 시트를 **보이는 화면(`visualViewport`) 기준**으로 놓는다.
   - 키보드 높이 = `window.innerHeight − visualViewport.height − visualViewport.offsetTop` → 시트 `bottom`으로 써서 시트가 키보드 바로 위에 온다. 1px 안팎의 오차는 키보드로 보지 않는다.
   - 최대 높이 = `visualViewport.height − 48px`. 위 48px은 덮개가 남아 "누르면 닫힘"이 보인다. 넘치면 시트 안(목록)에서 스크롤하고, 검색칸과 목록 위쪽은 시트 맨 위에 있어 늘 보인다.
   - 계산은 순수 함수 `sheetLayout`(`src/domain/sheet.ts`)로 빼 단위 시험으로 고정했다(브라우저마다 달라서 화면 부품 안에 두지 않음).
5. **아래 안전 영역**(아이폰 홈 막대): 시트 아래 여백을 `--sheet-safe-bottom`(`tokens.css`, 기본 `env(safe-area-inset-bottom, 0px)`)으로 둔다. 키보드가 올라와 있을 때는 0. 변수로 둔 까닭: 안전 영역이 0인 PC에서도 시험이 값을 34px로 바꿔 내용이 그만큼 위에 있는지 확인할 수 있다.
6. **끌어서 닫기**: **손잡이와 시트 머리(제목 줄)를 아래로 80px을 넘게 끌고 놓으면 닫힌다**(`dragOutcome`; 80px 딱은 "넘지" 않아 닫히지 않음). 80px 이하면 제자리로 돌아온다. 끄는 동안 시트가 손가락을 따라 내려가고 위로는 올라가지 않는다(`dragOffset`).
   - 끌기는 **이 영역에서만 시작**한다(`touch-action: none`도 이 영역에만). 목록 안에서 위아래로 스크롤하는 손가락을 닫기로 오해하지 않게 하기 위해서다. 머리 안의 "닫기" 버튼 위에서는 시작하지 않아 누르기와 겹치지 않는다.
7. **움직임**: 올라오는 움직임(0.24초, `--animate-sheet-up`)과 덮개 나타남(`--animate-sheet-fade`)은 `motion-safe`에서만 — **움직임 줄이기를 켠 기기는 바로 나타난다.** **닫을 때는 애니메이션 없이 바로 사라진다**(끌어서 닫을 때도 손가락 위치에서 바로 사라짐). 놓았는데 닫히지 않을 때만 0.18초 동안 제자리로 돌아간다.
8. **그대로 둔 것**: `role="dialog"` · `aria-modal` · 이름("작물 고르기" · "지역 고르기"), "닫기" 버튼, Esc, 닫은 뒤 누른 칸으로 포커스 되돌림, 뒤 화면 스크롤 잠금(`html` · `body`), 폭 1024 이상이 되면 닫힘, 경로 · 선택이 바뀌면 닫힘.

## 이 PC에서 확인하지 못한 것 (실제 휴대폰 확인 필요)

시험은 Chromium 에뮬레이션(마우스 포인터, 높이 줄이기)으로만 돌렸다. 아래는 **실제 기기에서 사용자가 확인**해야 한다(PR 본문에 같은 목록을 기기별로 적었다).

- **키보드가 올라올 때의 지역 시트**: 검색칸을 눌러 키보드가 올라와도 시트가 키보드 바로 위에 붙고, 검색칸과 목록 위쪽이 보이는가 (`visualViewport` 동작은 아이폰 사파리 · 안드로이드 크롬 · 카카오톡 인앱 브라우저가 서로 다를 수 있다).
- **아래 안전 영역**: 아이폰 홈 막대에 시트 아래 내용(지역 시트 맨 아래의 "기상청 ASOS 지점 …" 줄, 작물 시트의 안내 문장)이 가려지지 않는가.
- **손잡이 끌기와 목록 스크롤의 충돌**: 손잡이 · 머리에서 아래로 끌면 닫히고(80px 넘게), 목록 안에서 위아래로 스크롤하는 손가락은 시트를 닫지 않는가. 실제 손가락(터치)에서 끌기가 부드럽게 따라오는가.

## 알려진 한계

- 끌기는 포인터 이벤트(마우스 · 터치 · 펜 공통)로 만들었고 이 PC에서는 마우스로만 시험했다. 터치의 관성 · 빠른 쓸어내림(flick)은 따로 다루지 않아 **80px 넘게 끌어야** 닫힌다(짧게 빠르게 쓸어도 닫히지는 않음). 필요하면 속도 기준을 나중에 더한다.
- 시트가 열려 있는 동안 키보드로 시트 밖 요소에 포커스가 가는 것을 가두지는 않는다(`aria-modal`만 둠, 이전 판과 같다). 포커스 가두기는 로그인 시트 등 다른 시트와 함께 이 부품에서 한꺼번에 다룬다.
- 닫는 애니메이션이 없다(요청 · 승인된 결정).
