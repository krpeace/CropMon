# 0040. 상세 화면 함수 단위 캐시(use cache) 및 SWR·실패 미캐시 원칙

- **날짜:** 2026-11-09
- **상태:** 채택
- **연관:** 이슈 #81, 결정 0010, 결정 0011, 결정 0017, 결정 0038

## 맥락

CropMon은 노지 작물 물수지 및 기상 데이터를 제공하는 공개 웹 서비스입니다.
첫 화면 판정 표는 결정 0038(#106)을 통해 `use cache`(30분)로 캐시되어 하루 DB 조회가 인스턴스당 최대 48회로 제한되었습니다.
그러나 상세 화면(`/water`, `/temperature`, `/sunlight`)은 여전히 매 요청마다 DB를 직접 읽고 있었습니다:

1. **상세 화면별 1회 방문 시 DB 조회량 실측:**
   - **물 화면 (`/water`):** 시나리오, 최근 회차, 관측 물수지, 단기예보 요약 등 약 0.05~0.10MB
   - **온도 화면 (`/temperature`):** 연간 누적 적산온도(heat_daily), 생육 단계, 97개 지점 비교(readHeatLatest) 등 약 0.05MB
   - **햇빛 화면 (`/sunlight`):** 연간 누적 적산일사(sun_daily), 97개 지점 비교(readSunLatest) 등 약 0.04MB
   - **토양 화면 (`/soil`):** 정적 안내(ComingSoon) 페이지로 DB 조회 없음 (0MB)

동일한 지점·작물을 여러 사용자가 조회할 때 중복 DB 조회를 줄이고, Vercel/Supabase Egress 및 연결 부하를 절감하기 위해 상세 화면에도 캐시를 적용하기로 결정했습니다.

## 결정

1. **쪽 전체 ISR 대신 읽기 함수 단위 `use cache` 적용:**
   - 주소창의 다양한 쿼리 파라미터(`st`, `crop`, `kc`, `soil`, `d`, `run`) 및 Next.js 16 App Router의 Partial Prerendering(PPR) `<Suspense>` 스트리밍과 완벽히 호환되도록, 페이지 전체가 아닌 데이터 로더 함수 단위(`src/app/_components/shell/detail-cache.ts`)로 캐시합니다.
   - Next.js 전용 기능(`next/cache`, `use cache`)은 아키텍처 원칙에 따라 `src/app` 계층에 위치시킵니다.

2. **캐시 수명 30분 (`stale: 1800, revalidate: 1800, expire: 86400`):**
   - 인스턴스별(in-memory) 캐시로 동작합니다.
   - `croplib-dp`의 자료 갱신 주기(02시·17시 단기예보 회차, 09:20 관측 일자료)를 충분히 반영하며, 같은 지점·작물 조건의 DB 읽기를 하루 최대 48회로 상한을 둡니다.

3. **캐시 열쇠에 한국 기준 "오늘 날짜(`today`)" 명시적 포함:**
   - 캐시 함수 내부에서 날짜를 임의 계산하지 않고, 호출부에서 KST 기준 날짜 문자열(`YYYY-MM-DD`)을 인자로 넘겨 캐시 열쇠에 포함시킵니다.
   - 이를 통해 자정(00시) 전후로 캐시된 데이터가 잘못 서빙되는 문제를 방지합니다.

4. **실패 미캐시 원칙 (Fail-safe Bypass):**
   - DB 연결 실패나 일시 장애 발생 시 `throw new Error(...)`를 발생시켜 Next.js 캐시 저장을 즉시 취소(bypass)합니다.
   - 호출부(`loadWater`, `loadTemperature`, `loadSunlight`)에서 `try ... catch`로 안전한 폴백(fallback) 객체를 반환하여 클라이언트 화면이 크래시되지 않도록 보호합니다.
   - 에러가 캐시되지 않으므로 일시 장애가 복구된 다음 요청에서는 즉시 DB 재조회를 시도하여 정상 데이터를 보여줍니다.

5. **센서 미설치 지점의 정상 "자료 없음" 캐시:**
   - 태백(216) 등 일사 센서가 없는 지점의 `kind: "notMeasured"` 상태는 장애가 아니라 정상적인 관측 실태 판정이므로, 에러를 던지지 않고 30분 동안 정상 캐시합니다.

6. **SWR (Stale-While-Revalidate) 가용성 보장:**
   - 정상 값이 캐시된 후 30분이 지나 stale 상태가 되었을 때 백그라운드 재검증이 일시 실패하더라도, 직전의 정상 데이터를 `expire`(24시간)까지 유지 서빙하여 서비스 가동성을 보장합니다.

## 예상 효과

- 여러 사용자가 같은 지점의 상세 화면을 볼 때 DB 조회가 인스턴스 캐시 범위 내에서 대폭 감소합니다.
- 데이터베이스 네트워크 단절 등 일시적인 장애가 30분 동안 캐시되어 서비스가 마비되는 운영 리스크를 원천 차단합니다.
