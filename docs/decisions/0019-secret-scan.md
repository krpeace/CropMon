# 0019. 자동 검사에 비밀키 검사(gitleaks) 추가

- 날짜: 2026-10-26
- 상태: 확정 (이슈 #33)

## 배경

- 소스 코드 및 Git 커밋 이력에 API 토큰, 데이터베이스 접속 비밀번호, 서비스 키 등의 비밀키가 실수로 포함되는 사고를 방지하기 위해 CI에 비밀키 검사를 도입한다.
- GitHub 액션 마켓플레이스의 `gitleaks/gitleaks-action`은 조직(Organization) 저장소 등에서 상용 라이선스 등록을 요구하므로, 비용 및 운영 제약 없이 안정적으로 구동할 수 있는 방식이 필요하다.

## 결정

- **독립 실행 바이너리 직접 설치 및 체크섬 검증:**
  - 공식 릴리스의 MIT 라이선스 gitleaks 독립 실행 파일(`v8.30.1`, `linux_x64.tar.gz`)을 직접 받아 사용한다.
  - 릴리스에 제공되는 SHA256 체크섬 파일(`gitleaks_8.30.1_checksums.txt`)과 비교 검증(`sha256sum --check`)한 뒤 실행하여 바이너리 무결성을 확보한다.
- **별도 CI 작업(`secrets`)으로 병렬 실행:**
  - 기존 빌드·린트·테스트를 수행하는 `quality` 작업과 분리하여 `secrets` 작업을 병렬로 실행한다.
  - 전체 커밋 이력을 누락 없이 검사하기 위해 `actions/checkout@v5`의 `fetch-depth: 0`을 지정하고, `gitleaks git --redact --verbose .`를 실행한다.
- **자체 시험(Self-test) 단계 포함:**
  - CI 내에서 검사 도구가 실제 탐지 동작을 하는지 보증하기 위해, 저장소 검사 직전에 임시 가짜 키를 만들어 탐지 여부를 확인한다.
  - AWS Key 형식(`AKIA` + `[A-Z2-7]` 16자, 엔트로피 조건 충족, 기본 allowlist의 `.+EXAMPLE$` 회피)을 만족하는 값을 런타임에 여러 변수로 분할 결합하여 임시 디렉터리에 생성한다.
  - `gitleaks dir --redact`로 검사하여 정상 탐지(종료 코드 1 이상)되지 않으면 CI를 실패시킨다. 가짜 키는 저장소 파일에 온전한 문자열로 절대 남기지 않는다.
- **설정 파일(`.gitleaks.toml`)과 엄격한 예외 정책:**
  - `[extend] useDefault = true`로 공식 기본 규칙을 전체 상속한다.
  - 예외(`allowlist`)는 광범위한 정규식이나 특정 폴더 전체 제외를 금지하며, 정말 가짜인 값 하나하나에 이유 주석을 달아 최소화한다.
- **로그 마스킹:**
  - 모든 gitleaks 실행에 `--redact` 플래그를 붙여 탐지된 비밀키 원문이 CI 로그에 노출되지 않도록 한다.
