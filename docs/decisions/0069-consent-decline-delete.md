# 결정 0069: "동의하지 않고 나가기" = 첫 동의 전이면 그 자리에서 계정 지우기 (이슈 #199, L4 후속)

- 날짜: 2026-11-21
- 상태: 확정 (DB 변경 없음 — 병합은 CI 통과 뒤 검토 채팅이 바로 한다. SQL 실행 없음)
- 관련 이슈: #199. 앞: 동의 화면(결정 0065, L4) · 탈퇴 · 카카오 끊기(0067) · 구글 · 네이버 끊기(0068). 뒤: O2(동의 없이 24시간 지난 계정 정기 정리, 별도 이슈).
- **DB · 데이터 계약 변경 없음**(v2.3 그대로). `delete_my_account()`는 그대로 쓴다.

## 배경

SNS 로그인은 공급자에서 돌아오는 순간 Supabase가 `auth.users`와 `members` 줄을 먼저 만든다. 그래서 동의 화면보다 계정이 먼저 생긴다. 0065의 "동의하지 않고 나가기"(`POST /auth/signout`)는 **로그아웃만** 해서 계정이 남았고, 동의 화면의 "동의하지 않고 나가면 로그인 정보는 24시간 안에 자동으로 지워져요."는 정리 작업(O2)이 생기기 전까지 지켜지지 않았다.

**사용자 결정(2026-11-21)**: 동의한 사람만 회원으로 남게 한다. 순서는 사실상 "로그인 → 동의 → 가입".

## 결정

1. **나가기 전용 길** `POST /auth/consent/decline?next=…`(`src/app/auth/consent/decline/route.ts`). 동의 화면의 나가기 폼이 여기로 보낸다. **로그아웃 길(`/auth/signout`)은 바꾸지 않는다** — 내 계정 시트의 로그아웃이 같은 길을 쓴다.
   - 규칙은 동의 · 탈퇴 길과 같다: 스위치 끔 404 · 켬이면 `GET` 405 · `Origin`이 있고 이 사이트가 아니면 403 · `next`는 `readConsentNext`로 검사 · 결과는 `next`로 303, **알림 없음**.
2. **지우는 조건 = 첫 동의 전인 사람만.** 자기 `members` 줄의 동의 판 두 열이 **모두 비어 있을 때만** 지운다(`declineAction`, 순수 함수).
   - **예전 판에 동의했던 회원은 지우지 않고 로그아웃만 한다.** 약관 판이 바뀌어 다시 동의를 기다리는 회원에게는 농장 · 관수 기록이 있을 수 있어, 나가기 한 번에 그 자료가 사라지면 안 된다.
   - 한 열만 값이 있는 줄 · 동의 기록을 읽지 못함 · 로그인 정보를 읽지 못함 → **지우지 않고** 로그아웃만. 남은 계정은 O2가 정리한다.
3. **순서**(탈퇴 길을 따름): ① 로그인 정보(공급자 · 카카오 회원번호) 읽기 ② 동의 판 읽기 ③ `delete_my_account()` ④ 공급자 연결 끊기 ⑤ 이 기기 로그인 쿠키 지움(`signOut({ scope: "local" })`). **삭제가 실패해도 로그아웃은 하고** 보던 화면으로 보낸다(남은 계정은 O2).
4. **공급자 연결 끊기 — 재인증은 하지 않는다.** 동의도 안 한 사람에게 로그인을 한 번 더 시키지 않는다.
   - 카카오: 탈퇴와 같이 `unlinkKakao`(어드민 키 · 지우기 전에 읽어 둔 회원번호).
   - 구글 · 네이버: `getUser()`로 회원을 확인한 **뒤에** `getSession().provider_token`만 꺼내 `revokeGoogle` / `revokeNaver`로 끊는다. 토큰이 없으면 건너뛴다. `getSession()`의 `user`는 판단에 쓰지 않는다. 토큰은 그 요청 안에서만 쓴다(0068과 같음).
   - 끊기가 실패하거나 건너뛰어도 알림 문구는 늘리지 않는다.
   - ⚠ 로그인 뒤 세션이 갱신되면(한 시간쯤 뒤) 공급자 토큰이 사라진다고 알려져 있다. 그러면 건너뛴다. 가짜 서버로는 "있음/없음"만 확인되므로 실제 구글 · 네이버 쿠키 세션에 토큰이 남는지는 미리보기 실제 로그인으로 확인한다(PR "사용자가 확인할 것").
5. **`ops.withdrawn_accounts`**: 동의 전 나가기도 탈퇴자 해시 한 줄을 남긴다(개인 값 없음 — 회원 번호의 해시와 시각뿐, 7일 뒤 O2가 지움). 같은 사람이 다시 로그인해도 회원 번호가 새로 생겨 걸리지 않는다.
6. **문구는 한 글자도 바꾸지 않는다.** "동의하지 않고 나가면 로그인 정보는 24시간 안에 자동으로 지워져요."는 바로 지워도 맞는 말이다.

## 범위 밖

O2 정기 정리(탭을 그냥 닫고 떠난 사람) · 동의 화면 문구 · 약관 · 방침 본문 · 탈퇴 화면 문구 · 로그아웃 길.

## 시험

- 단위: `declineAction`(첫 동의 전 → 지움 / 예전 판 · 한 열만 · 지금 판 · 읽기 실패 → 로그아웃만) · `consentDeclineAction` · 새 길(404 · 405 · 403 · 순서 · 예전 판 · 읽기 실패 · 삭제 실패 · 카카오 · 구글 토큰 있음/없음 · 위험한 `next` · 기록에 비밀 없음).
- e2e(`consent-decline.spec.ts`, 가짜 Supabase `consentMode: "needed"` · `"legacy"`(예전 판 동의 — 이번에 추가)): 삭제 1회 · 카카오 끊기 1회 · 쿠키 없음 · 알림 없음 / 다시 로그인하면 새 회원 / 예전 판 → 삭제 0회 / 삭제 실패 → 로그아웃은 됨 / 구글 토큰 있음 · 없음 / 내 계정 시트 로그아웃은 지우지 않음 / 휴대폰 폭 캡처. 스위치 끔 e2e에 새 길 404 항목을 더했다.
- 바뀐 시험 한 줄: `consent.spec.ts`의 나가기 폼 `action`을 `/auth/signout?next=…`에서 `/auth/consent/decline?next=…`로(나머지 검사는 그대로).
