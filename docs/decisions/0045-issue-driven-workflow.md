# 결정 0045: 이슈 기반 작업 흐름 — 계획 승인·검토·병합을 검토 채팅이 맡음

- 날짜: 2026-11-18
- 상태: 채택
- 관련 이슈: (이 PR)

## 배경

지금까지는 Claude 채팅이 쓴 지시문을 사용자가 작업창(Antigravity)에 붙여 넣고, 계획 승인·PR 확인·병합도 사용자가 했다. 사용자는 개발자가 아니어서 복사·붙여 넣기와 승인 대기가 일의 병목이 됐다. 회원제(2027-01-01)까지 셸 개편·로그인·내 농장 화면을 차례로 만들어야 하므로 이 흐름을 줄인다.

## 결정

1. 작업 지시는 GitHub 이슈(라벨 `작업지시`)로 낸다. 검토 채팅(Claude)이 이슈를 쓴다.
2. 작업창은 이슈를 직접 읽고, 계획을 이슈 댓글로 올리고, 승인 댓글을 확인한 뒤 진행한다. PR을 열고 완료 보고를 이슈 댓글로 남긴다. 절차는 `CLAUDE.md` "이슈 작업 흐름".
3. 계획 승인·PR 검토·병합은 검토 채팅이 한다. 병합 조건은 자동 검사 통과 + 검토. DB를 바꾸는 SQL이 있는 PR은 사용자가 SQL을 실행한 뒤 병합한다.
4. 같은 GitHub 계정을 쓰므로 댓글 첫머리 `[작업창]`·`[검토 채팅]`으로 쓴 쪽을 가른다.
5. 한 저장소의 지시는 한 채팅에서만 한다는 원칙은 그대로다. 지금은 이 검토 채팅이 CropMon 지시를 맡는다. 채팅을 바꿀 때는 새 채팅이 이어받았다고 이슈 댓글로 남긴다.

## 결과

- 사용자가 하는 일: 작업창에 "이슈 #번호 진행" 한 줄, 검토 채팅에 진행 확인, DB SQL 실행.
- 작업창이 댓글을 기다리는 동안 멈춰 있을 수 있다(최대 60분 확인 뒤 사용자에게 알림).
