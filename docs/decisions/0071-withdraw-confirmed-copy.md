# 결정 0071: 탈퇴 화면 연결 줄 · 끊기 실패 알림을 확정 문구로 — 네이버가 열리지 않았으면 "네이버"를 뺀다 (이슈 #205, L6 후속)

- 날짜: 2026-11-21
- 상태: 확정 (DB 변경 없음 · 데이터 계약 v2.4 그대로 · 병합은 CI 통과 뒤 검토 채팅이 바로 한다. SQL 실행 없음)
- 관련 이슈: #205. 앞: 탈퇴 · 카카오 끊기(결정 0067, L6-1) · 구글 · 네이버 끊기(0068, L6-2). 이 결정이 두 결정의 **화면 · 알림 글자**를 확정 문구에 맞춘다.
- 회원제 스위치가 꺼져 있어 운영 영향은 없다.

## 배경

L6-1 · L6-2는 **바뀌기 전 문구**로 구현됐다. 확정 문구는 2026-11-20에 바뀌었다 — 탈퇴할 때 SNS 연결 끊기를 1/1에 구현하기로 정한 사용자 결정(회원제 설계)을 반영해, "각 계정 설정에서 해제" 안내를 **끊기 실패 알림으로 옮기고** 탈퇴 화면에는 "함께 끊어요" 한 줄을 둔다.

## 결정 (글자는 한 글자도 바꾸지 않는다)

**탈퇴 확인 화면(`/account/withdraw`)의 연결 줄** — 옛 줄("… 각 계정 설정에서 해제할 수 있어요.", 늘 보였음)이 있던 같은 자리 · 같은 작은 글씨:

> 탈퇴하면 카카오·네이버·구글 연결도 함께 끊어요.

**탈퇴 뒤 알림**

| 경우            | 문구                                                                                                      |
| --------------- | --------------------------------------------------------------------------------------------------------- |
| 끊기 성공(보통) | 탈퇴했어요 _(지금 그대로)_                                                                                |
| 끊기 실패       | 탈퇴했어요. 카카오·네이버·구글 계정의 '연결된 서비스'에 남은 CropMon은 각 계정 설정에서 해제할 수 있어요. |

- 실패 알림은 두 줄(`\n`)로 보인다. 첫 줄은 마침표까지 "탈퇴했어요.", 둘째 줄은 뒷문장 그대로. 줄을 나누는 것은 표시 방식이고 글자는 바뀌지 않는다. 시간(7초) · `whitespace-pre-line` · `role="status"`는 그대로.
- **네이버 로그인이 열리지 않았으면(`NAVER_LOGIN_ENABLED`가 켜져 있지 않으면) 두 곳 모두 "네이버"를 뺀다.** 남는 글자는 "카카오·구글":
  - 연결 줄: "탈퇴하면 카카오·구글 연결도 함께 끊어요."
  - 실패 알림: "… 카카오·구글 계정의 '연결된 서비스'에 …"

## 판단 위치 — 하나의 함수

- 켬 · 끔 판단은 `naverLoginEnabled(process.env)`(`src/domain/members-switch.ts`) **하나**다.
- **문구를 만드는 곳도 한 곳**: `src/domain/withdraw-copy.ts`(`unlinkProviderNames` · `withdrawLinkLine` · `withdrawUnlinkedText`). 시험이 전체 글자로 켬 · 끔 둘 다 견준다.
- **화면**(서버 컴포넌트 `account/withdraw/page.tsx`)은 `naverLoginEnabled(process.env)`를 한 번 읽어 재인증 대상 판단(`reauthTarget`)과 연결 줄 문구에 **같이** 쓴다(`WithdrawScreen`의 `naverOn`).
- **알림**은 브라우저의 `LoginNotice`가 그린다. 루트 layout이 서버 환경변수를 읽으면 정적 껍데기가 동적이 되므로, 이미 있는 **표시 쿠키 `cm_m`의 `n`**(결정 0064)에서 읽는다. 프록시가 같은 `naverLoginEnabled`로 만드는 값이고 `a`/`i` + `n`뿐이라 **개인 값이 없다**. 탈퇴로 로그아웃돼 `i`가 `a`로 바뀌어도 `n`은 그대로다.
- **`LoginNotice`가 `useMembersState()` 훅 대신 효과(effect) 안에서 `document.cookie`를 바로 읽는 이유**: 훅은 서버 HTML과 맞추려고 하이드레이션 중 서버 값("끔")을 먼저 주기 때문에, 알림을 띄우는 첫 효과에서 네이버가 켜져 있어도 "끔"으로 읽을 수 있다. 쿠키를 바로 읽으면 그 순간의 실제 값이다(`parseMembersFromCookieHeader`, 시험이 이미 있음).
- `ACCOUNT_TOAST["withdrawn-unlinked"]`는 **네이버 켬 기준 값**으로 남기고(기존 사용처 · 시험 호환), **화면 코드는 `accountToast(notice, naverOn)`만 부른다.** `ACCOUNT_TOAST`를 직접 읽는 화면 코드는 없다.
