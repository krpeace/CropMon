# 0017. 종합 화면 온도·햇빛은 DB 값 (온1 마무리)

- 날짜: 2026-10-25
- 상태: 확정 (이슈 #22, 0011 의 "예시" 부분을 대체, 0003 을 전부 대체)

## 결정

- **온도 카드:** 온도 화면과 같은 문구 함수(`leadVerdict`, `gddNumbers`). "평년보다 생육 N일 빠름" + "적산온도 ○ / 평년 ○ ℃·일", 태백형은 "평년 한 해 치를 넘었어요". 그래서 평년 한 해 합(12/31 `gdd_normal_cum`)을 한 번 더 읽는다.
- **햇빛 카드:** "올해 햇빛은 평년의 N%" + "적산일사 ○ / 평년 ○ MJ/m²". 일사 자료가 없으면 회색 "자료 없음"과 "○○ 관측소의 햇빛 자료가 없어요". 판단은 DB 기준 (결정 0016).
- **전국 표:** "3일 빠름"(태백형은 "한 해 치 넘음")과 "96%"를 DB 값으로, 칸 이름의 "예시"를 뗀다. 자료가 없으면 회색 "자료 없음".
- **읽기:** 온도·햇빛 화면의 지역 비교와 같은 함수(`src/services/growth-latest.ts`) — 10곳을 한 번에 어제 날짜로, 없는 지점만 최근 14일 보충.
- **캐시 (지시서가 고르라고 한 것):** 판정 표(`getStationBoard`)에 넣지 않고 **따로 5분 캐시**(`loadGrowth`, 작물마다 한 벌)를 둔다. 판정 표는 헤더 때문에 모든 쪽이 읽으므로, 거기 넣으면 온도·햇빛이 필요 없는 쪽까지 읽기가 늘어난다. 따로 두면 종합 화면을 열 때만, 그것도 5분에 한 번 읽는다 (적산온도 2~3번 + 적산일사 1~2번). 한 요청당 읽기 수는 늘지 않는다.
- **실패:** 적산온도와 적산일사를 따로 읽어 한쪽이 실패해도 다른 쪽은 보인다. 실패한 쪽은 회색 "자료 없음"과 "DB에서 자료를 읽지 못했어요".
- `src/mocks/home.ts` 를 지운다.
