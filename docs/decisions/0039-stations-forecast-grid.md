# 0039. 운영 97곳 지점 단기예보 격자(grid_nx, grid_ny) 시드

- 날짜: 2026-11-08
- 상태: 확정 (`croplib-dp` 결정 0025, PR #75, #28 C3 요청)

## 배경

- `croplib-dp`의 전 지점 수집 확대 작업(#28) 중 단기예보 격자가 비어 있는 지점은 수집기가 생성되지 않고 `slot_done` 완료 조건을 충족하지 못해 같은 회차가 세 번 반복 실행되는 문제가 있었습니다(`croplib-dp` 결정 0025).
- 이를 해결하기 위해 `croplib-dp`가 기상청 단기예보 격자 변환식(Lambert 정각원추 `kma_lcc_5km_v1`)으로 운영 97곳 지점의 격자를 계산하여 `docs/data/stations_grid_20261108.csv`로 확정했습니다.
- `CropMon`은 이 계산 결과 CSV를 원본 그대로 보존하고, DB 지점 사전(`stations`)에 97곳 격자를 시드합니다.

## 결정

1. **외부 계산 CSV 복사 및 보존 (`docs/data/stations_grid_20261108.csv`)**:
   - `croplib-dp` main 커밋 `2038b4b8606c9617852e7b4e7184248387de9159`의 CSV를 `docs/data/`에 복사하고 SHA-256 체크섬(`32A58E3772F25A9514DD2EB7FC44CC333F488A9ACE710CE4A8C0F908F451C366`)을 기록했습니다.
   - 값을 손으로 옮겨 적지 않고, 마이그레이션 SQL 생성(`scripts/generate_migration.py`)과 테스트 검증의 단일 기준(Single Source of Truth)으로 삼습니다.

2. **사전 검증 확인**:
   - **대표 10곳**: 기존 DB 값과 계산 CSV 값이 **10/10 일치**함을 확인했습니다.
   - **경계 근접 12곳 (`near_boundary = true`)**: 반올림 경계 0.02칸 이내 지점 모두 계산값과 **12/12 일치**함을 확인했습니다.
     - `105` 강릉: (93, 132)
     - `121` 영월: (85, 119)
     - `129` 서산: (52, 109)
     - `138` 포항: (102, 95)
     - `174` 순천: (67, 71)
     - `226` 보은: (73, 104)
     - `232` 천안: (66, 109)
     - `252` 영광군: (52, 77)
     - `253` 김해시: (95, 77)
     - `255` 북창원: (91, 77)
     - `257` 양산시: (97, 78)
     - `296` 북부산: (96, 77)
     - 특히 `296` 북부산은 raw 좌표가 `x=96.254, y=77.000350`으로 y가 정수 경계선(77.000)에 거의 걸쳐 있어(경계 마진 약 0.000칸) 위경도가 조금만 달라도 한 칸(5km) 옆으로 갈 수 있으나, 공식 변환식에 따른 계산값 `(96, 77)`과 정확히 일치함을 확인했습니다.
   - **격자 고유성**: 운영 97곳 모두 서로 다른 97개의 격자를 가지며, 겹침(중복)이 0개입니다.

3. **마이그레이션 안전 규칙 및 이전 시드 파일 재실행 주의사항 (`20261108020000_seed_stations_forecast_grid.sql`)**:
   - `where s.stn_id = v.stn_id and s.grid_nx is null` 조건을 두어, 이미 값이 채워져 있는 **대표 10곳 값은 절대 덮어쓰지 않고 빈 칸(87곳)만 채웁니다**.
   - 마이그레이션을 여러 번 실행해도 오류가 나지 않고 멱등성이 보장됩니다.
   - `has_forecast` 열은 수정하지 않습니다 (예보 수집 활성화는 `croplib-dp` S4에서 20곳씩 순차 진행).
   - 폐지·휴지 지점 8곳은 격자 `null`을 유지합니다.
   - **재실행 시 주의사항**: 과거 마이그레이션인 `20261028030000_seed_stations_asos.sql`을 다시 실행하면 87곳 격자가 `null`로 돌아갑니다 (`on conflict do update set grid_nx = null`). 따라서 만약 해당 파일을 다시 실행했다면 반드시 이 파일(`20261108020000_seed_stations_forecast_grid.sql`)을 이어서 다시 실행해야 합니다 (해당 파일 머리말 주석에도 경고 추가).

4. **자동 검증 (`src/infra/supabase/seed.test.ts`)**:
   - `docs/data/stations_grid_20261108.csv`를 직접 읽어 마이그레이션 SQL의 97곳 `(grid_nx, grid_ny)` 값과 **97/97 완전 일치**를 자동 검사합니다.
   - 대표 10곳 덮어쓰기 방지 조건(`where ... and s.grid_nx is null`) 및 `has_forecast` 미변경을 테스트로 고정합니다.
