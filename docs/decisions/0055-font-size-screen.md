# 결정 0055: 글씨 크기 화면 · 저장 · 처음 한 번 알리기 카드 (이슈 #168)

- 날짜: 2026-11-19
- 상태: 확정 (**"휴대폰 설정 따르기"는 시험 과제** — 아래 3번)
- 관련 이슈: #168 (순서표 #144의 S7-1). 결정 0047(글씨 크기 변수 뼈대)을 이어받는다. 130% 이상 화면 배치 · 150% 넘침 고치기는 S7-2.
- 기준: 모바일 셸 설계 v1.2, 시안 v0.4.3 "글씨 크기" · 시안 v0.4.6 종합의 알리기 카드, 디자인 규칙 v0.4.6 02절 · 12절, 11/17 사용자 결정(설정을 못 찾는 사람을 위한 한 번만 알리기)

## 배경

결정 0047에서 모든 글자가 `--fz` 하나를 따르게 뼈대를 만들었지만 고르는 화면이 없어 `--fz`는 늘 1이었다. 고령 사용자가 글씨를 키울 수 있게 화면을 열고, 설정을 못 찾는 사람을 위해 종합 맨 위에 한 번만 알린다. **`tokens.css`의 `--fz` 계산식 · 구역 규칙은 바꾸지 않는다** — `<html>`의 `--fz` 값만 바꾼다.

## 결정

### 1. 저장 — 비회원은 기기, 저장 함수는 한곳

- 단계 다섯: 작게 0.9 · 보통 1 · 크게 1.15 · 더 크게 1.3 · 아주 크게 1.5. 기본 "보통". 이 밖의 값은 `--fz`에 들어가지 않는다.
- 저장 이름 `cropmon-font-scale`(기존 `cropmon-theme` · `cropmon-menus` · `cropmon-national-tab`과 같은 대시 모양), 값 `{"v":1,"step":"normal","follow":false}`. 비었거나 망가졌거나 모르는 판 · 단계는 기본값(보통 · 따르기 꺼짐)으로 읽는다. "휴대폰 설정 따르기" 켜짐도 같은 값의 `follow` 한 칸이다.
- **저장 · 읽기는 `shell/font-scale-store.ts` 한곳**이다. 회원 계정 저장은 L5(화면 설정 계정 저장)에서 이 파일의 읽기 · 저장만 바꿔 끼운다. 저장소가 막힌 브라우저(사생활 보호 모드)는 이번 화면 동안만 메모리에 둔다(`NationalList.tsx`와 같은 방식). 순수 규칙(단계 · 읽기 · 환산)은 `src/domain/font-scale.ts`.

### 2. 첫 그리기 전에 적용 (깜박임 없음)

- `layout.tsx`의 `<head>` 작은 스크립트(`buildFontScaleScript()`)가 `THEME_SCRIPT`와 같은 방식으로 저장 값을 읽어 `document.documentElement.style.setProperty("--fz", 값)`을 한다. 새로고침 때 100% → 150%로 튀는 장면이 없다(시험이 화면 내용이 처음 생기는 순간의 `--fz`를 읽어 확인).
- 값은 **다섯 단계 가운데 하나만**: 스크립트가 단계 목록에서 값을 고르므로 허용 목록 밖(`"step":"huge"` 등)은 보통이 된다. 저장소 · 측정 오류는 `try`로 삼켜 화면을 막지 않는다(저장된 단계, 없으면 보통).
- 머리 안에서는 `document.body`가 아직 없어서 측정용 요소는 `document.documentElement`에 달았다가 바로 뗀다.
- 스크립트 글자는 단계 값 · 키를 상수에서 끼워 만들고, **단위 시험이 스크립트와 순수 함수가 같은 결과를 내는지 같은 표로 확인**한다(허용 목록 밖의 값, `--fz` 2 같은 값은 둘 다 기본값으로).
- 화면이 뜬 뒤에는 보이지 않는 부품 `FontScaleSync`가 한 번 다시 맞추고, "휴대폰 설정 따르기"가 켜져 있으면 화면으로 돌아올 때(`focus` · `visibilitychange`)마다 다시 재며 다른 탭에서 바꾼 값(`storage`)을 따라간다.

### 3. "휴대폰 설정 따르기" — 측정 방법과 시험 과제 상태

- **측정**: 보이지 않는 시험 요소를 달아 글자 크기를 잰다. 아이폰 사파리처럼 `-apple-system-body`를 지원하면(`CSS.supports("font", "-apple-system-body")`) `font: -apple-system-body`의 px ÷ **17**(보통 설정의 기본), 그렇지 않으면(안드로이드 크롬 · 카카오톡 인앱 등) `font-size: medium`의 px ÷ **16**(브라우저 기본). 이 배율을 가장 가까운 단계로 맞춰 쓴다(0.9~1.5 밖이면 끝 단계, 같은 거리면 작은 쪽). 못 재면(예외 · 0px) 저장된 단계 값을 쓴다.
- **데스크톱 크롬에서 확인한 것**: 순수 함수 시험(1.07 → 보통, 1.2 → 크게, 0.5 → 작게, 2 → 아주 크게), 스크립트 ↔ 순수 함수 일치 시험(안드로이드 기준 16 · 아이폰 기준 17, 측정 실패 포함), 그리고 크롬 DevTools 프로토콜(`Page.setFontSizes`)로 브라우저 기본 글자 크기를 24px로 바꾼 e2e — 스위치를 켜면 `--fz` 1.5(아주 크게), 새로고침해도 첫 그리기부터 1.5.
- **확인하지 못한 것(시험 과제)**: 실제 휴대폰의 글자 크기 설정(갤럭시 크롬 · 아이폰 사파리 · 카카오톡 인앱)이 위 측정에 실제로 반영되는지. PR의 "사용자가 휴대폰에서 확인할 목록"에 있다. **안 되면 사용자 확인 뒤 스위치를 빼고 단계만 남긴다** — 그래서 스위치는 부품 하나(`FollowSwitch`)와 저장 값의 `follow` 한 칸이라 떼기 쉽다.
- 켠 동안 슬라이더 · 단계 칸은 불투명도 0.4로 흐려지고 누를 수 없다.

### 4. 글씨 크기 화면 `/font-size` (2단계 화면)

- `EXTRA_SCREENS`에 `"/font-size": { kind: "title", title: "글씨 크기", back: true }` — 휴대폰 맥락 바에 뒤로 화살표 + 제목. 데스크톱에서도 주소로 열리면 같은 내용(데스크톱 들어가는 길은 로그인 이슈의 "내 계정"에서 붙인다).
- 위에서 아래로: 미리보기 카드(물 카드 모양 · 고정 예시 값, 위에 "미리보기 · 예시 값" 표시, 글씨 크기를 바꾸면 바로 바뀜) → "지금 글씨 크기 보통 100%" → 슬라이더(5칸, 왼쪽 작은 "가" 15 · 오른쪽 큰 "가" 28은 글씨 크기를 따라 커지지 않음, 키보드 ←/→, `aria-valuetext` "글씨 크기, 보통 100%") → 단계 이름 다섯 칸(누르는 곳 44 이상, 고른 칸 `aria-pressed`) → "휴대폰 설정 따르기" 스위치.
- **저장 버튼 없음** — 고르는 즉시 화면 전체에 적용 · 저장. 미리보기 카드는 `SummaryCard`의 `href`를 선택으로 바꿔(없으면 링크 대신 `div`, 화살표 없음) 같은 부품을 썼다.
- 더보기 "글씨 크기" 줄은 준비 중 버튼에서 `/font-size` 링크 줄로 바뀌었다(꼬리표 없음, 오른쪽에 지금 단계 이름 · 고른 지역 · 작물을 이어서 이동). "화면 구성"은 S5까지 준비 중 그대로.

### 5. 처음 한 번 알리기 카드 (종합 맨 위)

- 문구 "글씨가 작으면 크게 볼 수 있어요" + 버튼 "글씨 크기"(→ `/font-size`) + 닫기 ×(`aria-label="닫기"`). 모양은 시안 v0.4.6 알리기 카드(연한 초록 바탕 · 초록 테두리 · 진한 초록 알약 버튼 · 오른쪽 ×), 위치는 종합 첫 줄(제목) 위. 첫 방문부터, 비회원 포함. **×를 누르거나 `/font-size`에 한 번 들어가면 다시 안 나온다**(기기에 기억).
- **130% 이상에서는 버튼이 글자 아래 줄로 내려간다.** 폭이 아니라 지금 적용된 `--fz`(`<html>` 인라인 값)로 정하므로 "휴대폰 설정 따르기"로 1.3 이상이 된 경우도 같다.
- **카드는 한 번에 하나**: ① 농장 등록 권하기 → ② 가온 시작일 → ③ 글씨 크기. 고르는 규칙은 순수 함수 `pickNotice`(`src/domain/notice.ts`, 값은 "이 카드를 보여도 되는 상태")이고 단위 시험한다. ①②는 아직 없어(F1 · W4) 지금은 ③만 실제로 나온다. 카드 모양은 공용 부품 `home/NoticeCard.tsx`(문구 · 버튼 · 닫기) — F1 · W4가 그대로 쓴다.
- **닫음 기억**: 기기 `cropmon-notice-closed`, 값 `{"v":1,"closed":["fontSize"]}`(F1 · W4 카드도 같은 자리).
- **첫 그리기 깜박임 · 밀림 없음**: `layout.tsx`의 머리 스크립트(`buildNoticeScript()`)가 처음 그리기 전에 닫은 카드 이름을 `<html data-notice-closed="fontSize">`로 달고, 카드는 서버에서 그려 두되 CSS(`globals.css`)가 그 표시가 있으면 `display:none`으로 숨긴다. 그래서 이미 닫은 사람에게 "보였다 사라짐"도, 처음 보는 사람에게 카드가 뒤늦게 떠서 내용이 밀리는 일도 없다. 브라우저에서 닫은 기록을 읽은 뒤에는 `HomeNotice`가 카드를 거둔다(F1 · W4 카드가 있으면 다음 카드로 바뀜). 이 방식이 `pickNotice`를 지저분하게 만들지 않는 것은, 서버가 "닫음"을 모르는 대신 CSS가 닫음을 맡기 때문이다.
- 시험 기본 상태(`e2e/fixtures.ts`)는 "카드 닫음"을 미리 넣어 기존 시험의 종합 맨 위가 흔들리지 않게 하고, 카드 자체 시험만 `test.use({ showNotice: true })`로 켠다. 글씨 크기 저장 값은 기본으로 넣지 않는다(기존 시험은 `--fz` 1).

## 버린 안

- **서버에서 카드를 안 그리고 브라우저에서 확인한 뒤 보이게 하기**(처음 계획): 처음 방문하는 사람은 카드가 뜨며 아래 내용이 한 번 밀린다. 위 머리 스크립트 + CSS 방식으로 바꿨다.
- **슬라이더 칸 눈금(점)을 그려 단계에 맞추기**: 기본 `range` 입력의 손잡이 이동 범위가 양 끝에서 안쪽이라 눈금이 어긋난다. 단계는 아래 "단계 이름 다섯 칸"이 맡는다.

## 알려진 한계

- 130% 이상 화면 배치 바꿈과 150%에서 답답한 곳 고치기는 S7-2다. 이번 PR에서 150%로 둘러본 결과는 PR 본문 목록에 있다(가로 넘침 · 글자 잘림은 둘러본 화면에서 없었음).
- 처음 방문 뒤 닫은 기록을 못 읽는 브라우저(저장소 막힘)에서는 이번 화면 동안만 닫힘이 유지되고 새로고침하면 카드가 다시 나온다.

> **[결정 0066 갱신]** 로그인한 회원은 글씨 크기를 바꾸면 기기에 쓰고 계정에도 쓴다(400ms 모아 마지막 값만). 로그인 직후 · 다른 기기 값 따라오기 규칙은 0066.
