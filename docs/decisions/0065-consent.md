- 관련 이슈: #191 (순서표 #144 M2의 L4). 앞: 회원 DB(결정 0059), 로그인 배관(0061), 로그인 시트(0064). 뒤: L5(화면 설정 계정 저장), L6(회원 정보에 "동의한 약관", 탈퇴), O2(동의 없이 24시간 지난 계정 정리).

## 배경

로그인 = 가입이고 약관 동의는 B안이다: **첫 로그인 뒤 동의 화면 한 장, 동의 전에는 회원 기능(내 농장 · 관수 기록)을 막는다.** 개인정보 칸은 "동의"가 아니라 **"안내 확인"** 이다(서비스에 꼭 필요한 정보는 법상 동의 없이 처리 — 전문가 1차 회신). **스위치(`MEMBERS_ENABLED`)를 끄면 지금 알파와 똑같다**(새 주소는 404, 기존 e2e 그대로).

## 결정

### 1. "동의가 필요" 판단 — 두 판 가운데 하나라도 못 받으면 다시 묻는다

`src/domain/legal.ts`의 순수 함수 `needsConsent({ termsVersion, privacyVersion })`. **이용약관 판과 개인정보 안내 판 두 값을 모두 본다 — 하나라도 "받아 주지 않는 판"이면 필요**(방침이 크게 바뀔 때도 다시 묻는다. 검토 채팅 승인 11/20). 받아 주는 판 = **지금 판 + `acceptedBefore`**. 비었거나(null · 빈 글자 · 공백) 모르는 값(대소문자 · 공백이 다른 글자 포함)이면 필요하다.

`LegalDoc`에 새 칸 **`acceptedBefore`**("이전 판 중 다시 묻지 않아도 되는 판 번호", 지금 `[]`)를 두었다. 기존 `previous`("이전 판 보기" 목록)와 **따로** 둔다 — 이전 판을 *보여 주는 것*과 *다시 묻지 않는 것*은 다른 결정이기 때문이다(사소한 변경은 공지만 하고 `acceptedBefore`에 넣어 이전 동의를 그대로 받아 주고, 크게 바뀌면 넣지 않아 다시 동의받는다).

### 2. 흐름

- **콜백**(`/auth/callback`): `ensure_my_member()` 뒤 **자기 `members` 줄의 `terms_version` · `privacy_version` 두 열만** 읽는다(`readMyConsent`, RLS로 자기 줄만). 동의가 필요하면 `next` 대신 **`/consent?next=<원래 next>`**, 아니면 지금처럼 `next?login=ok`(`postLoginDestination`). **읽기에 실패해도 로그인은 막지 않고 동의 화면으로 보낸다**(동의 화면이 다시 확인). 서버 기록에는 단계와 오류 코드만(`consent/read`), 원문 · 개인 값은 안 남긴다(0061 `logAuthError`).
- **`/consent`**: 로그인 필요 주소(`LOGIN_REQUIRED_PATHS`에 추가). 들어올 때 서버에서 다시 확인한다 — 스위치 끔 404 · 로그인 안 함 → 로그인 시트 · **이미 동의함 → `next`로 이동**(스트리밍 중 `redirect()`: HTML 200 + 이동 표시. 콜백이 이미 동의한 사람을 `/consent`로 보내지 않으므로 드문 갈래) · 동의 전(읽기 실패 포함) → 그린다.
- **동의하고 시작하기**: `POST /auth/consent?next=…`가 `record_my_consent`를 부르고 303으로 `next?login=ok`(첫 로그인의 "로그인했어요"는 동의 뒤 한 번). **판 값은 서버가 `legal.ts`에서 넣고 폼 · 주소로 온 값은 읽지도 않는다**(위조해도 무시). 체크 칸 상태와 상관없이 셋 모두로 기록하며 체크 칸은 큰 버튼 **글자만** 바꾼다. 실패하면 `/consent?next=…&consent=failed`로 돌아와 한 줄을 띄운다.
- **동의하지 않고 나가기**: `POST /auth/signout?next=…`(있는 경로) → 보던 화면, 알림 없음.
- **다른 사이트 막기**: `POST /auth/consent`는 로그아웃과 같게 `Origin`이 있고 이 사이트가 아니면 403, 없으면 통과한다. 근거: **로그인 쿠키가 `SameSite=Lax`라서 다른 사이트에서 보낸 `POST`에는 세션이 실리지 않는다** — e2e가 로그인 뒤 세션 쿠키의 `sameSite`가 `Lax`임을 확인한다(`@supabase/ssr` 기본값). `GET`은 405(링크 미리 불러오기가 기록하지 않게).
- **`/consent`는 공통 관문을 지나지 않는다**(자기 자신으로 돌고 도는 일 없음). `consentGate`의 `onConsentPage`가 이 갈래를 한 함수에 못 박고(`consent`는 어떤 입력으로도 안 나옴), e2e가 "동의 전 회원이 `/consent`를 여러 번 열어도 그대로"를 시험한다.

### 3. 화면 (확정 문구 그대로 · 글자 하나도 바꾸지 않음)

- 문구는 `src/domain/consent.ts`의 `CONSENT_COPY` 한 곳(시험이 글자 그대로 견줌). 순서는 시안 v0.4.6: 도깨비 → 제목 → **큰 버튼** → 체크 셋(+ 요약 셋) → 안내 → 안내(24시간) → 나가기 버튼. "수집·이용" 같은 가운뎃점 낱말은 줄바꿈 금지(`tieMiddleDot`, 결정 0048)로 한 덩어리 — 글자는 그대로이고 U+2060만 둔다(접근성 이름에서는 빠질 수 있어 시험은 `\W*`로 받음).
- **확정 문구 밖 한 문장**: 저장 실패 안내 **"동의를 저장하지 못했어요. 잠시 뒤 다시 해 주세요"** — **확정 문구 밖 — 검토 채팅 승인(11/20)**. 그래서 `CONSENT_COPY`에 넣지 않고 `CONSENT_SAVE_FAILED_TEXT`로 따로 두었다.
- **전체를 덮는 겹침**(`fixed inset-0`, z-50): 머리글 · 탭바 · 바닥글은 루트 `layout`에 있어 그대로 두고(정적 화면을 동적으로 바꾸지 않으려), 동의 화면이 그 위를 덮는다. 열려 있는 동안 `body`의 다른 자식(머리글 · 탭바 · 바닥글)에 `inert`를 걸어 Tab · 화면 읽기가 새지 않는다(알림 자리 `role="status"`는 제외). 휴대폰은 꽉 찬 화면(뒤로 화살표 · 탭바 · 도깨비 없음 = 덮여서 안 보임), 데스크톱은 뒤판 위 가운데 창(폭 520). **× · 뒤판 누르기 · Esc로 닫히지 않는다**(전문가 2차 확인) — 출구는 "동의하지 않고 나가기" 하나.
- **[보기]**: 화면을 떠나지 않고 같은 겹침 안에 본문 패널이 올라온다("동의 화면으로 돌아가기"로 닫음, 체크 상태 유지). 본문은 서버가 L1의 `LegalBody`로 미리 그려(`LegalView` — `LegalScreen`에서 문서 바꾸기 링크 · 운영자 표기를 뺀 본문) 클라이언트에 넘긴다. "예시 글" 배지 · 시행일 줄 포함, 본문 글자는 안 고침.
- 큰 버튼 글자: 셋이 모두 켜져 있을 때만 "동의하고 시작하기"(`consentButtonLabel`), 아니면 "모두 동의하고 시작하기". 낮은 화면(390×667)과 글씨 150%에서도 큰 버튼은 제목 바로 아래라 스크롤 없이 보이고 잘리지 않는다(시험).
- **한계(알려 둠)**: 동적 부분이 `<Suspense>` 안에서 스트리밍되므로 **자바스크립트가 꺼진 브라우저에서는 화면이 안 보인다**(앱 전체가 같다). 동의 폼 자체는 진짜 `<form method="post">`라서 보내는 길(`POST /auth/consent`)은 자바스크립트 없이 동작한다(e2e가 폼 모양을 확인).

### 4. 동의 전 회원 기능 막기

- **공통 관문 `requireMemberConsent()`**(`src/app/_lib/consent-gate.ts`, 서버 전용 · 요청 때): 스위치 끔 404 · 비로그인 → 로그인 시트 · **동의 전 · 읽기 실패 → `/consent?next=<지금 주소>`**. `farm/layout.tsx` · `account/layout.tsx`가 `MemberGate`(`<Suspense>`로 감싼 서버 부품)로 부르므로 F1 · F2 · L6 화면이 들어오면 **자동으로 막힌다**(지금 `/farm/*`는 화면이 없어 404). 이것은 "동의 화면으로 보내 주는 편의"이고 진짜 막이는 DB의 RLS다(0061).
- **지금 주소를 아는 법**: 레이아웃은 자기 주소를 모르므로 프록시가 **로그인한 사람의 로그인 필요 주소 요청**에 `x-cm-next`(경로 + 검색어) 머리를 실어 준다. **밖에서 온 같은 이름의 머리는 믿지 않고 덮어쓰며**(로그인 필요 주소가 아니면 지움) 관문이 읽을 때도 `next` 검사를 한 번 더 한다. 프록시는 DB를 읽지 않는다.
- **`/account` 임시 쪽**(검토 채팅 승인): "준비 중"만 보인다. 막기를 화면 시험으로 못 박으려고 둔다. **L6가 이 쪽을 이어받아** 회원 정보 · 로그아웃 · 회원탈퇴 · SNS 연결 끊기 화면으로 바꾼다(쪽 주석에도 적음). → **L6-1(이슈 #195, 결정 0067)에서 실제 회원 정보 화면으로 바뀌었다.**
- **스위치 끔 = 알파**: 새 쪽(`/consent` · `/account`)이 생겨도 끄면 404여야 한다. 쪽 안의 `notFound()`는 스트리밍에서 상태가 200이 되므로, **프록시가 스위치 끔일 때 로그인 필요 목록의 주소를 없는 주소로 다시 쓴다**(`rewrite`: 주소창 그대로, 로그인으로도 안 보냄 → Next.js가 404 쪽을 그림). 기존 "로그인 필요 목록도 안 막는다" e2e가 그대로 통과한다.
- **헤더 · 내 계정 시트의 "동의 전" 표시는 두지 않는다**(검토 채팅 기본안): 동의 전 회원은 첫 로그인 직후 동의 화면에 있고, 탭을 닫았다 돌아와도 내 계정의 막힌 항목이 전부 "준비 중"이라 보여 줄 갈림이 없다. 24시간 뒤 정리 작업(O2)이 지운다.

### 5. DB (v2.3, `20261120200000_data_contract_v2_3_consent.sql`)

1. **`public.record_my_consent(p_terms_version, p_privacy_version)`**: 보안 정의 · `search_path` 비움 · `authenticated`만 실행. 로그인 안 했으면 28000, 판 값이 앞뒤 공백을 뗀 뒤 비었거나 100자를 넘으면 22023. 줄이 없으면 `member_seed`로 만든 뒤 쓴다(오류로 막는 것보다 로그인 흐름에 안전, `ensure_my_member`와 같은 식). 다섯 열을 **`now()` 한 값**으로 한 번에 쓴다.
2. **동의 다섯 열의 직접 고치기 권한 회수**(`revoke update (…) on public.members from authenticated`). 직접 고치는 열은 9개 → 4개(`display_name` · `layout` · `font_scale` · `theme`). 동의 시각을 아무 값으로나 쓸 수 없어 기록으로서 강해진다.
3. **`public.member_has_consented()`**: `stable` · **`security definer`**(`farms` · `irrigation_logs` 정책 안에서 `members`를 다시 읽을 때 `members`의 정책이 겹쳐 평가되지 않게 — 정책 안의 정책 방지. 인자가 없고 `auth.uid()`의 줄만 보므로 남의 줄을 알아낼 길이 없음).
4. **농장 쓰기는 동의한 회원만**: `farms` · `irrigation_logs`의 **넣기 · 고치기** 정책 `with check`에 `member_has_consented()`를 더했다. **읽기 · 지우기는 막지 않는다**(판이 바뀌어 다시 동의를 기다리는 회원도 자기 자료는 보고 지울 수 있다). RLS의 `with check`는 다른 제약보다 먼저 평가되므로 동의 전 회원의 농장 넣기는 값이 틀려도 항상 42501이다.
5. 확인 SQL `l4_consent_check.sql`(되돌림 방식, 31항목, 맨 끝 `all_ok`), 되돌리기 `l4_consent_rollback.sql`(정책을 v2.1 상태로 먼저 되돌린 뒤 함수를 지움 · 동의 값은 건드리지 않음). **기존 확인 SQL 두 개를 v2.3에 맞게 고쳤다(기준은 안 낮춤)**: `d1_1_members_check.sql` 3a(동의 열을 직접 고치는 항목 → 네 열만, 직접 고치기는 새 확인 SQL이 "막힘"으로 봄), `d1_2_farms_check.sql`의 `new_user()`(가짜 회원을 동의한 회원으로 만듦, 항목 수 118 그대로).

### 6. e2e 서버 · 프로젝트

가짜 Supabase에 `GET /rest/v1/members`(두 열) · `rpc/record_my_consent` · 사용자별 동의 상태 · "같은 사용자로 로그인" · 읽기 · 저장 실패 시나리오를 더했다. 기본값은 "새 회원도 지금 판으로 동의함"이라 기존 시험이 그대로 통과한다(가짜의 판 값이 `legal.ts`와 같은지 단위 시험이 지킨다). 가짜의 상태가 전역이라 **"켬" 서버 시험은 파일마다 프로젝트 하나로 만들어 차례로** 돈다(같은 프로젝트의 파일은 일꾼이 나뉘어 동시에 돌 수 있어 상태가 섞였다).

## 하지 않은 것
