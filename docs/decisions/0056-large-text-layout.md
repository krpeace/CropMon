# 결정 0056: 큰 글씨(130% 이상) 화면 배치 바꿈 · 150%에서 겹치던 곳 고침 (이슈 #172)

- 날짜: 2026-11-19
- 상태: 확정
- 관련 이슈: #172 (순서표 #144의 S7-2). 결정 0047(글씨 크기 변수 뼈대) · 0055(글씨 크기 화면 · 저장)를 이어받는다.
- 기준: 시안 v0.4.3 · v0.4.5, 디자인 규칙 v0.4.6 12절 "큰 글씨에서 첫 화면". 시안 코드(`fzBig = 단계 ≥ 3`)에서 130% 이상 판정과 배치 값(`g3` 한 열, `mCols: minmax(0,1fr) auto` · `mSpan: 1 / -1`)을 확인했다.

## 배경

#168(S7-1)로 글씨 크기를 고를 수 있게 되었다. 규칙은 **"130% 이상은 가장 중요한 것 하나가 스크롤 없이 보이게"**이고, 방식은 화면 확대가 아니라 **배치 바꿈**(세로로 쌓기 · 아래 줄로 내리기)이다. `--fz` 계산식 · 구역(0047)과 글씨 크기 화면 · 저장(0055)은 바꾸지 않았고, 그래프 높이 · 막대 폭 자체도 키우지 않았다.

## 결정

### 1. "큰 글씨" 변형 하나 — `big:`

- 머리 스크립트(`buildFontScaleScript()`)가 `--fz`를 줄 때 **`<html data-fz-big>`을 함께 달고**(더 크게 · 아주 크게일 때만, 아니면 뗌) 첫 그리기부터 붙는다. 글씨 크기 화면에서 바꿀 때와 "휴대폰 설정 따르기"로 1.3 이상이 된 경우는 `font-scale-store.ts`의 `applyFontScale`이 **같은 규칙**으로 달고 뗀다.
- **판정은 부동소수 값이 아니라 단계 순서**(`더 크게` 이상, `isBigStep`)다. 그래서 1.3이 정확히 걸리고 스크립트와 순수 함수가 같은 방식이다. 시험이 같은 표로 확인한다(다섯 단계, 허용 목록 밖 값, 따르기로 1.3이 된 경우 · 측정 실패 포함).
- `tokens.css`에 `@custom-variant big (&:where([data-fz-big], [data-fz-big] *))`(다크 변형과 같은 모양). **화면은 JS로 `--fz`를 읽지 않고 `big:` 클래스만 쓴다.** `NoticeCard`의 130% 판정도 이 변형으로 옮겼다(동작 그대로). `useAppliedFz`는 글씨 크기 화면(`FontSizeScreen`)이 "지금 적용된 단계"를 보여 주려고 계속 쓴다.

### 2. 130% 이상 배치 바꿈

| 화면                               | 130% 미만                              | 130% 이상                                                                              |
| ---------------------------------- | -------------------------------------- | -------------------------------------------------------------------------------------- |
| 물 판정 카드 숫자 셋(`NowCard`)    | 3칸 가로                               | 한 열 세로(이름 위 · 값 아래, 시안 `g3`)                                               |
| 종합 휴대폰 목록(`NationalList`)   | 지점 · 배지 · 막대 한 줄(머리 줄 포함) | 막대(셋째 칸)를 지점 · 배지 아래 줄 전체 폭으로, 배지는 오른쪽(시안 `mCols` · `mSpan`) |
| 온도 단계 카드 두 장(`StageCards`) | 반폭 두 장                             | 한 장씩 쌓기(`Grid`의 `stackOnBig`), 날짜는 줄바꿈 금지("9월 10일"이 안 쪼개짐)        |
| 알리기 카드(`NoticeCard`, #168)    | 한 줄                                  | 버튼이 글자 아래 줄                                                                    |
| 내 농장 토성 목록                  | 3칸                                    | 2칸                                                                                    |

데스크톱 표(`NationalTable`)는 바꾸지 않는다(데스크톱 1440에서 150%로 종합 · 물 · 온도가 가로로 안 넘치는지만 시험).

### 3. 물 기준 날짜 줄

150% · 390에서 "11월 19일 (목) 오늘"이 두 줄로 접히고 위 안내와 붙던 것을: **날짜는 한 줄(줄바꿈 금지), 자리가 모자라면 "오늘" 꼬리표만 다음 줄로.** 서비스의 `label`은 그대로 두고 화면에서 작은 순수 함수 `splitDayLabel(label, isToday)`(`domain/water-outlook.ts`)로 날짜와 꼬리표를 나눈다(글자 형식이 바뀌면 이 한 곳에서 잡힘). 지난 날짜에서 "오늘로" 버튼이 생기면 큰 글씨에서는 그 버튼이 아래 줄 가운데로 간다. ‹ › 크기와 누르는 곳 44는 그대로이고, 위 안내 글자 "기준 날짜 · 눌러서 고르기"를 숨기는 처방은 필요하지 않아 쓰지 않았다.

### 4. 높이 고정 글자 상자 확인 (PR #152 메모)

150% · 390에서 하나씩 눈으로 확인했다. 겹침 · 잘림이 있던 곳만 고쳤다.

| 곳                                                         | 결과                                                           | 처방                                                                                                                           |
| ---------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 물(작물 공통) 계절 그래프 월 눈금 줄 (`h-37.5` / `h-32.5`) | **겹침** — "10월"·"11월", "1월"·"2월"이 맞닿음                 | 130% 이상에서 첫 달만 "월"을 남기고 숫자만(`ui/MonthLabel`, 온도 · 햇빛 누적 그래프와 같은 방식). 칸 폭 · 그래프 높이는 그대로 |
| 햇빛 휴대폰 월별 막대 라벨                                 | **겹침** — 막대 위 "100%95%83%…"가 서로 붙음, 월 글자도 맞닿음 | 130% 이상에서 퍼센트의 "%"만 숨기고(아래 줄 "막대 위 숫자는 평년 대비 %"가 설명), 월 글자는 `MonthLabel`                       |
| 내 농장 휴대폰 토성 목록 칸                                | **글자가 칸 테두리에 닿음**("미사질식양토" 넘침 +7)            | 130% 이상에서 2칸                                                                                                              |
| 온도 · 햇빛 누적 그래프 눈금 상자 (`h-50`)                 | 확인 — 겹침 없음(월 눈금은 "1월 2 3 … 12"로 이미 숫자만)       | 없음                                                                                                                           |
| 온도 "준비 중" 배지                                        | 확인 — 겹침 없음                                               | 없음                                                                                                                           |
| 재배 방식 칩 (`h-9.5`)                                     | 확인 — 겹침 없음                                               | 없음                                                                                                                           |

- 약속한 대로 고친 곳은 4곳을 넘지 않았다(3곳). 고정 `h-*`를 `fh-*`로 바꾸거나 `--fz2` 구역으로 옮기는 방법은 쓰지 않아도 됐다.
- **종합 물 카드**의 판정 글 · 숫자 줄이 각각 두 줄로 접히는 것은 의도된 줄바꿈이라 그대로 두었다(겹침 없음 확인만).
- 알려진 것(고치지 않음): 물(작물 공통) 계절 그래프에서 "오늘" 세로선이 오른쪽 축 글자("60+", "80%", "60%", "100%")의 앞 글자를 가로지른다 — 글씨 크기와 상관없는 기존 모양이다.
- 115%에서 같은 월 눈금 · 막대 위 글자 간격은 이번에 보지 않았다(이슈 범위가 130% 이상).

### 5. 이 이슈 밖

- 로그인 시트 "설명을 버튼 아래로", 동의 화면 첫 화면 규칙은 그 화면을 만드는 L3 · L4에서 한다(이슈가 규칙을 옮겨 적음).
- 데스크톱 1024 이상 배치(이번엔 휴대폰 390 기준).
- 150%에서 단어가 의도대로 두 줄로 접히는 것(겹침 · 잘림 아님)은 고치지 않는다.

## 시험

- e2e 휴대폰 390(`large-text-mobile.spec.ts`, 글씨 크기는 저장 값으로 연다): 첫 그리기부터 `data-fz-big`(130% 이상만), 글씨 크기 화면에서 바꾸면 따라 붙고 떨어짐, 위 표의 배치(115%에서는 한 줄 · 130% 이상 세로/아래 줄), 물 기준 날짜 줄(오늘 · 지난 날짜), 계절 그래프 월 눈금 · 햇빛 월별 라벨 · 토성 칸이 겹치지 않음. 데스크톱 1440(`large-text.spec.ts`): 150%에서 종합 · 물 · 온도가 가로로 안 넘침.
