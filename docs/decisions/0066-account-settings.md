# 결정 0066: 화면 설정 계정 저장 — 화면 구성 · 글씨 크기 · 다크 모드 (이슈 #193, M2 · L5)

- 날짜: 2026-11-20
- 상태: 확정 (DB 변경 없음 — 병합은 CI 통과 뒤 검토 채팅이 바로 한다)
- 관련 이슈: #193 (순서표 #144 M2의 L5). 앞: 화면 구성(결정 0058 · 0060) · 글씨 크기(0055) · 로그인 시트(0064) · 동의(0065). 뒤: L6(회원 정보 · 탈퇴 — 탈퇴 때 계정 값은 `delete_my_account()`가 함께 지운다), F3(작물 · 지역 "내 농장 맥락").
- **DB · 데이터 계약 변경 없음.** `members`의 `layout` · `font_scale` · `theme` 열과 회원 본인 고치기 권한은 v2.0부터 있고 v2.3 뒤에도 그대로다(운영 DB 읽기 전용 확인: `authenticated`가 이 세 열을 고칠 수 있음).

## 배경

설정 셋은 지금까지 **기기(로컬 저장소)** 에만 저장됐다(`cropmon-menus` · `cropmon-font-scale` · `cropmon-theme`). 셸 설계: **비회원은 기기, 회원은 계정**에 저장하고, 로그인하면 기기 설정을 계정으로 옮길지 묻는다. 휴대폰과 컴퓨터를 같이 쓰는 회원이 한쪽에서 바꾼 설정이 다른 쪽에도 따라오게 하는 것이 목적이다. **스위치(`MEMBERS_ENABLED`)를 끄면 지금 알파와 똑같다** — 비회원 · 끔에서는 계정 요청 0, 새 주소는 404.

## 결정

### 1. 말뜻 — 계정의 `null`은 "한 번도 저장 안 함"

기본값으로 되돌릴 때도 `null`이 아니라 **"기본값 값"**(`{v:1, order:기본 순서, off:[]}` · `{v:1, step:"normal", follow:false}`)을 쓴다. 그래야 다른 기기가 "초기화됨"을 따라온다. 테마는 기본값을 고르는 길이 없어 늘 `light|dark`다. **기기의 기본값**은 화면 구성 = 기본 순서 · 모두 켬(저장값 없음과 같음), 글씨 = 보통 · 따르기 꺼짐, 테마 = **저장한 선택이 없음**(휴대폰 설정 따름)이다. 값은 `parse…`를 거친 **정규 모양**으로 견준다(메뉴는 `order` 전체 + 끈 메뉴 집합 — 일부 ID만 적힌 값 · 사라진 ID · 종합을 끈 값도 `resolveMenus`와 같은 규칙으로 풀어서 같은 상태 = 같은 글자).

### 2. 읽고 쓰는 길 — `GET` · `POST /auth/settings`

공개 화면은 정적인 채(결정 0038 · 0064), **로그인한 사람의 브라우저가 화면이 뜬 뒤** 부른다. 브라우저용 Supabase 클라이언트는 두지 않는다(0061).

- `GET` → `{ who, layout, fontScale, theme }`(서버가 이미 거른 값, **비었거나 틀린 칸은 `null`**), `Cache-Control: no-store`. `who`는 회원 번호의 SHA-256 앞 16자(기기의 "기준"이 회원을 가를 때 쓰는 해시 — **회원 번호 자체는 내보내지 않는다**).
- `POST` → `{ layout?, fontScale?, theme? }` 중 **바뀐 칸만**(JSON). **전부 먼저 검사한 뒤** 쓴다 — 하나라도 틀리면 400이고 아무것도 안 쓴다(부분 저장 없음). 모르는 칸 · `null`로 지우기 · 8KB 초과(413) · JSON이 아님(400)은 거절. 메뉴 ID는 40개 · 40자 한도. **쓰는 열은 `layout` · `font_scale` · `theme` 셋뿐**이고 값은 서버가 만든 정규 글자로 쓴다.
- 순서(둘 다): 스위치 끔 **404**(쿠키도 안 건드림) · (POST) `Origin`이 다른 사이트 **403**(로그아웃 · 동의와 같게, 없으면 통과 — 근거: 로그인 쿠키가 `SameSite=Lax`라 다른 사이트의 `POST`에는 세션이 안 실리고, JSON 본문은 사전 확인 없이 다른 사이트에서 보낼 수 없다) · 비로그인 **401** · **동의 전(읽기 실패 포함) 403**(`needsConsent`, 결정 0065 — 동의 전에는 아무것도 읽거나 쓰지 않음) · 줄이 없으면 409 · DB 오류 502. 서버 기록에는 단계와 오류 코드만.
- 클라이언트는 **`cm_m`이 `i`(로그인함, `<html data-members="in">`)일 때만** 부른다. 비회원 · 끔은 요청 0. 동의 화면(`/consent`)에서는 부르지 않고, **403을 받으면 그 탭에서는 다시 부르지 않는다**(`sessionStorage`). 새 로그인(`login=ok`)은 막힘을 다시 확인한다. 응답 본문은 안 읽어도 끝까지 받는다(안 읽으면 브라우저가 요청을 끝난 것으로 안 세는 일이 있어 화면 시험이 알려 줬다).

### 3. 로그인 직후 (한 번) — 순수 함수 `decide…OnLogin`

`LoginNotice`가 `login=ok`를 읽을 때 "방금 로그인함" 신호를 한 번 켜고(`markLoginJustNow`, 주소에서 지우기 전), `AccountSync`가 **읽기 하나(`GET`)** 로 이 판단과 아래 4절 따라오기를 함께 한다(로그인 직후 탭에서 두 번 부르지 않음).

| 기기          | 계정      | 화면 구성에서 하는 일                                                                               |
| ------------- | --------- | --------------------------------------------------------------------------------------------------- |
| 기본값        | 비어 있음 | 아무것도 안 함                                                                                      |
| 기본값        | 값 있음   | **묻지 않고** 계정 값을 기기에 씀(같으면 안 함)                                                     |
| 기본값과 다름 | 비어 있음 | **시트(저장형)** [저장하기] 기기→계정 / [기본 구성 쓰기] 기기를 기본값으로(계정은 그대로 비어 있음) |
| 기본값과 다름 | 같음      | 아무것도 안 함                                                                                      |
| 기본값과 다름 | 다름      | **시트(충돌형)** [저장하기] 기기→계정 / **[계정 구성 쓰기]** 계정→기기                              |

- **글씨 크기 · 다크 모드는 시트 없이 조용히**: 계정이 비어 있으면 기기가 기본값일 때 안 하고, 아니면 기기 값을 계정에 저장. 계정 값이 있으면 같을 때 안 하고, 기기가 기본값이면 계정 값을 쓰고, **기기가 기본값과 다르면 계정에 다른 값이 있어도 기기 값을 계정에 저장**.
- 시트는 시안대로 **탭 미리보기**(기기 설정으로 만들어질 탭 넷 + 더보기) + 두 단추. 휴대폰은 아래 시트(`BottomSheet`), 데스크톱은 가운데 창. **× · 닫기 · 바깥 · Esc는 아무것도 안 바꾸고**(기기 그대로, 계정 저장 안 함) 다음 로그인 때 다시 묻는다. 신호가 `login=ok` 한 번이라 **새로고침해도 다시 안 묻는다**.
- **시트 글자**: 저장형은 **시안 v0.4.6 그대로**(제목 "화면 구성을 계정에 저장할까요?" · 설명 "이 기기에서 바꿔 둔 하단 탭이에요. 저장하면 다른 기기에서도 같은 구성으로 보여요." · 단추 "저장하기" / "기본 구성 쓰기" — 이슈 문장 "이 기기의 화면 구성을…"보다 시안이 우선, 검토 채팅 답). **충돌형은 시안 밖 — 검토 채팅 승인(11/20)**: 설명 "이 기기의 하단 탭이 계정에 저장된 구성과 달라요. 저장하면 다른 기기에서도 이 구성으로 보여요." · 단추 "저장하기" / "계정 구성 쓰기". (**다음 디자인 의뢰 때 넘길 목록**에 "충돌형 저장 시트"를 한 줄 더한다.)

### 4. 로그인한 뒤 바꿀 때 · 다른 기기 값 따라오기

- **바꾸면 기기에 쓰고 계정에도 쓴다**(저장 단추 없음). 저장소(`menu-store` · `font-scale-store` · `ThemeToggle`)가 기기에 쓴 직후 `pushAccount`를 부르고, **400ms 모아 마지막 값만** 한 번에 `POST`(`createAccountPusher`, 칸은 합침). `pagehide` · 탭이 숨겨질 때는 기다리지 않고 바로 보낸다(`keepalive`). 실패는 조용히(기기 값으로 계속). 계정 값을 기기에 쓰는 갈래(채택 · 따라오기)는 `{ sync: false }`로 되보내지 않는다.
- **탭당 한 번 따라오기**: 로그인한 채 탭/창을 **처음 열 때 한 번**(`sessionStorage`) 같은 `GET`으로 계정 값을 읽어 기기에 쓴다. 첫 그리기는 기기 값이고 **다를 때만(드묾) 한 번 다시 그려진다**(탭바 · 글씨 · 테마가 새로고침 없이 바로 바뀜 — e2e가 확인). 깜박임을 더 줄이려면 값을 쿠키에 실어야 하는데 값이 커서 권하지 않는다.
- **기준(base) — 따로 바꾼 기기 값을 지키는 장치**: 기기에 **마지막으로 맞춘 값**(칸별 정규 글자)을 적어 두고, 따라오기는 아래 표대로만 한다. 시트를 ×로 닫은 기기 값을 탭 따라오기가 덮어쓰지 않게 하려는 것이다.

| 계정                          | 기기                                                      | 따라오기가 하는 일                                   |
| ----------------------------- | --------------------------------------------------------- | ---------------------------------------------------- |
| 비어 있음(한 번도 저장 안 함) | 무엇이든                                                  | 아무것도 안 함                                       |
| 값 있음 · 기기와 같음         | —                                                         | 기준만 맞춤(`mark`)                                  |
| 값 있음 · 기기와 다름         | **기준과 같음**(이 기기에서 따로 안 바꿈) 또는 **기본값** | **계정 값을 기기에 씀**                              |
| 값 있음 · 기기와 다름         | 기준과 다르고 기본값도 아님(따로 바꿈 · 예: 시트 ×)       | **아무것도 안 함** — 다음 로그인 때 시트로 다시 물음 |

- **기준의 수명**: 저장 · 채택 · 따라오기가 끝날 때마다 갱신한다. **로그아웃해도 기준은 그대로 둔다**(기기 값도 그대로 두므로). 기준에는 **회원 번호의 해시(`who`)를 함께 적고**, **다른 회원이 같은 기기로 로그인하면 해시가 달라 "기준 없음"으로 본다**(그러면 그 회원의 따라오기는 "기기가 기본값일 때만"). 회원 번호 자체는 기기에 남기지 않는다.

### 5. 안내 줄

`/layout`의 저장 위치 안내 줄: 회원(`cm_m`이 `i`)이면 시안 글자 **"내 계정에 저장돼요. 다른 기기에서도 같은 구성으로 보여요."**, 비회원 · 끔은 지금 글자("이 기기에 저장돼요. 로그인하면 계정에 저장돼요.") 그대로. 글씨 크기 화면에는 저장 위치 안내 줄이 없어(코드 주석뿐) 바꿀 것이 없다. **로그아웃**하면 기기 값은 그대로 둔다(지우지 않음).

### 6. 알려 둘 것

- 동의 전 회원이 `/consent`를 나가지 않고 탭을 두면 요청이 되풀이되지 않는다(403 뒤 그 탭은 안 부름). 동의를 마치고 돌아오는 `login=ok`가 막힘을 풀고 판단을 한다.
- 가짜 로그인 서버는 실제 서명 방식(ES256)을 증명하지 못한다(결정 0061 6절) — 실제 로그인으로 해 보는 확인은 미리보기에서. 스위치가 꺼져 있어 운영에서는 볼 것이 없다.
- e2e: 가짜 Supabase에 `members`의 세 열 읽기 · `PATCH` 쓰기와 회원 번호별 저장을 더했고, "켬" 서버 시험은 파일마다 프로젝트 하나로 차례로 돈다(결정 0065의 구성에 `members-on-account` · `members-on-account-mobile`을 더함).

## 하지 않은 것

DB 변경, 계정에 다른 설정 더하기, 기기별 설정 따로 두기, 회원 정보 · 탈퇴(L6), 작물 · 지역 선택 저장(F3), 알림 설정.
