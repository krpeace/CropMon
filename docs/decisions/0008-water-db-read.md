# 0008. 물 화면은 DB를 읽는다 (물5 첫 단계)

- 날짜: 2026-10-25
- 상태: 확정

## 결정

- **물 화면부터 예시 값을 DB 값으로 바꾼다.** 종합 화면과 지역 칩의 점 색은 첫1·기5에서 바꾼다.
- **읽는 순서:** 재배 방식 목록·계산 조건(지점 × 작물 × 그해)·마지막 회차를 함께 읽고, 고른 재배 방식의 조건으로 관측 물수지(작기 시작~오늘)·3일 전망·요약을 읽는다.
- **마지막 회차 =** 서버 수집(`collector = actions`) 중 실패가 아닌 가장 최근 회차. 실패 알림은 수집 감시(croplib-dp)가 맡고, 화면은 마지막으로 받은 전망을 보여 준다. 백업 회차는 자료 상자 "발표" 줄에 적는다.
- **지금 상태 =** 그 회차 요약의 출발 날짜 상태(아침: 어제 끝, 저녁: 오늘 끝). 회차가 없으면 마지막 관측 물수지 날. 배지는 기존 규칙(`todayBadge`)대로 오늘 다음 날이 관수 필요면 미리 알린다.
- **관수 필요 예상일 문구:** 0 = "지금 관수 필요", k번째 날 = 주 지표 첫날 + (k − 1)일을 오늘·내일·모레 또는 날짜로, 비어 있으면 "3일 안에는 없음". 빠르면·늦으면이 다르면 범위를 붙인다. 날 수는 `horizon_days`를 그대로 쓴다(7·14일로 늘려도 화면 규칙은 그대로).
- **재배 방식:** 주소창 `&kc=<set_no>`. 없거나 모르는 번호면 DB의 기본 재배 방식(`is_default`). 기본값일 때는 주소창에 붙이지 않아 지금의 링크가 그대로 유효하다.
- **작물 이름:** 주소창 `cabbage`는 DB `kimchi_cabbage`로 바꿔 묻는다(`CROP_DB_ID`). 주소창 값은 바꾸지 않는다.
- **실패해도 멈추지 않는다:** 연결 정보가 없거나 DB가 오류를 주면 서버 기록에 남기고, 화면에는 "자료 없음"과 쉬운 이유를 보여 준다. 읽기 하나에 8초 제한을 두고 자동 재시도는 끈다(켜면 DB가 없을 때 쪽마다 7초 걸림).
- **열은 적어서 읽는다:** `forecast_runs`의 `raw_path`·`error`는 공개하지 않는 열이라 읽지 않는다. 읽는 열이 마이그레이션에 있는지 테스트가 검사한다.
- 화면은 계산하지 않는다. 숫자는 반올림해 문구로만 바꾼다.
