# 0006. 데이터 계약 v1.2: 전망 선행일 0~4, 원자료 버킷

- 날짜: 2026-10-24
- 상태: 확정

## 배경

croplib-dp 수집기(물1-3)를 실제 API로 시험 실행하면서, 저녁(17시) 회차의 3일 전망이 D+1~D+4(선행일 1~4)인데 v1의 `water_outlook.lead_day`는 0~3만 받는다는 것을 찾았다. 그대로 두면 저녁 회차를 올릴 때 DB가 거부한다. cropwater 서비스도 아침은 D+0~D+3, 저녁은 D+1~D+4이고, 처음 3개 대상일이 주 지표·마지막 날이 참고다.

## 결정

- **`lead_day`는 0~4.** 줄 수와 열은 그대로다. 화면은 회차가 아침이면 D+3, 저녁이면 D+4를 "참고"로 보여 준다(주 지표는 처음 3일).
- **원자료 버킷 `raw`를 비공개로 만든다.** 시각별 예보와 API 응답 원문은 DB 용량(500 MB)을 아끼려고 Storage에 압축해 둔다. 공개 정책을 만들지 않으므로 비회원·회원은 읽을 수 없고, 서버 키(service role)만 쓴다. 버킷 만들기도 DB 구조와 같은 곳(이 저장소의 마이그레이션)에 둔다.
- 버킷 SQL은 `storage.buckets`가 있을 때만 돈다. Supabase가 아닌 PostgreSQL(테스트용)에서도 마이그레이션 전체를 오류 없이 두 번 실행할 수 있게 하려는 것이다.
- 적산온도·적산일사 표는 v1.3으로 미룬다.

## 확인한 것

임시 PostgreSQL에서 모든 마이그레이션을 이름 순서대로 두 번 실행해 오류가 없고, 선행일 4는 들어가고 5는 막히는 것을 확인했다.
