# 결정 0067: 회원 정보 · 로그아웃 · 회원탈퇴 · 카카오 연결 끊기 (이슈 #195, M2 · L6-1)

- 날짜: 2026-11-20
- 상태: 확정 (DB 변경 없음 — 병합은 CI 통과 뒤 검토 채팅이 바로 한다. 사용자 할 일: 병합 뒤 Vercel에 `KAKAO_ADMIN_KEY` 넣기, 아래 5절)
- 관련 이슈: #195 (순서표 #144 M2의 L6-1). 앞: 회원 DB · 탈퇴 함수(결정 0059, D1-1) · 로그인 배관(0061) · 로그인 시트(0064) · 동의(0065) · 화면 설정 계정 저장(0066). 뒤: **L6-2(구글 · 네이버 연결 끊기 — 재인증 흐름)**.
- **DB · 데이터 계약 변경 없음.** `public.delete_my_account()`(해시 한 줄을 `ops.withdrawn_accounts`에 남기고 `auth.users`를 지워 `members`가 연쇄로 지워짐)는 D1-1부터 있고, 이 PR이 처음 부른다.

## 배경

L6은 회원 정보 · 로그아웃 · 회원탈퇴 · SNS 연결 끊기다. 연결 끊기는 공급자마다 방법이 달라 나눈다.

- **카카오**: 앱 어드민 키 + 카카오 회원번호로 서버에서 바로 끊는다(그 회원의 토큰이 필요 없음). → **이번(L6-1)**.
- **구글 · 네이버**: 그 회원의 공급자 토큰이 있어야 하고 Supabase는 로그인 직후 한 번만 준다 → 탈퇴 때 한 번 더 로그인(재인증)해야 한다. 위험과 시험이 커서 **L6-2**로 넘긴다. 이번에는 자료 삭제만 되고 연결은 **안내 줄**로 갈음한다(전문가 2차 확인 Q9: 끊기를 안 하면 안내 줄이 필수).

**스위치(`MEMBERS_ENABLED`)를 끄면 지금 알파와 똑같다** — `/account` · `/account/withdraw`는 프록시가 없는 주소로 다시 써서 404, `/auth/withdraw`는 POST · GET 모두 404(쿠키도 안 건드림).

## 결정

### 1. 탈퇴 처리 `POST /auth/withdraw` — 순서가 전부다

1. 스위치 끔 **404** · `Origin`이 있고 이 사이트가 아니면 **403**(로그아웃 · 동의와 같은 규칙, 없으면 통과) · 폼 값 `confirm=on`이 없으면 **아무것도 안 하고** `/account/withdraw?withdraw=confirm`으로 303(화면의 막기와 별개로 서버도 본다). `GET`은 405.
2. **지우기 전에** `auth.getUser()`(Auth 서버에 묻는다 — 쿠키 값만 믿지 않음)에서 **로그인한 공급자 목록(`identities`)과 카카오 회원번호**를 읽는다(지운 뒤에는 못 읽음). **못 읽으면 아무것도 안 하고** `?withdraw=failed` — 카카오 회원번호를 모른 채 지우면 끊을 수 없기 때문이다.
3. **`delete_my_account()`** — 회원 세션으로 `rpc`(서버 키를 쓰지 않음). **실패하면 아무것도 끊지 않고** `/account/withdraw?withdraw=failed`로 303(로그아웃도 안 한다 — 다시 시도할 수 있게).
4. **카카오 identity가 있으면 카카오 연결 끊기.** 끊기가 실패해도 **탈퇴는 이미 끝난 것**이다.
5. 로그인 쿠키 지우기(`signOut({ scope: "local" })` — 계정이 이미 없어 서버에 묻지 않아도 이 기기 세션은 지운다) → `/?account=withdrawn` 또는 `/?account=withdrawn-unlinked`로 303. 탈퇴 뒤 헤더는 "로그인"이 된다(프록시가 쿠키 없음으로 `cm_m=a`로 고침). `/account`를 다시 열면 로그인 시트가 뜬다.

탈퇴는 **동의 전에도 할 수 있다**(회원의 권리) — 처리 경로(`POST /auth/withdraw`)는 동의 관문 밖이다. 화면(`/account/withdraw`)은 다른 회원 화면처럼 `account/layout`의 관문 안이라 동의 전 회원은 동의 화면이 먼저 뜬다(동의 화면의 "동의하지 않고 나가기"가 로그인 정보를 24시간 안에 지우는 길이다, 결정 0065).

**기기에 남는 것**: 이 기기의 화면 설정(`cropmon-*`)은 지우지 않는다(비회원 기기 설정으로 남음). 확정 문구의 "화면 설정"은 **계정에 저장된 화면 설정**을 뜻한다(`members` 줄과 함께 지워짐, 검토 채팅 승인 11/20). 기준(`cropmon-acct-base`)은 회원 번호 해시가 달라 다음 회원에게 쓰이지 않는다(결정 0066).

### 2. 알림 — `account=` 표시

`LoginNotice`가 `login=`처럼 `account=withdrawn | withdrawn-unlinked`를 읽어 한 번 띄우고 주소에서 `account`만 지운다(순수 함수 `readAccountNotice`).

- 카카오 하나만 연결했고 끊기가 성공했을 때만 **"탈퇴했어요"**(4초).
- 그 밖(끊기 실패 · 키 없음 · 구글 · 네이버 · 둘 이상 연결 · 공급자를 못 읽음)은 **한 알림의 두 줄** "탈퇴했어요 / 연결된 서비스는 각 계정 설정에서 해제할 수 있어요"(긴 글이라 **7초**, `whitespace-pre-line`, `role="status"` 안의 한 덩어리 — 검토 채팅 승인 11/20). 판단은 순수 함수 `withdrawOutcome`.

### 3. 화면

- **`/account` 회원 정보**(L4 임시 쪽을 이어받음): 2단계 화면(맥락 바 제목 "회원 정보" · 뒤로 화살표). 서버가 요청 때 `members`의 일곱 열(이름 · 공급자 · 가입일 · 동의 다섯 열 중 판 · 시각 넷 — 역할 · 화면 설정 열은 읽지 않음)과 로그인 정보(메일)를 읽는다. 위에서 아래로: 로그인 방법 · 이름 · 메일(**없으면 줄째로 뺌**) · 가입한 날 · 동의한 약관 두 줄([보기 ›] → `/terms` · `/privacy`) · 로그아웃(`POST /auth/signout?next=/`, 알림 없음) · 맨 아래 빨강 회원탈퇴. 읽기에 실패하면 안내 한 줄과 함께 로그아웃 · 회원탈퇴 길은 그대로 연다. 값 만들기는 순수 함수(`src/domain/account-info.ts`).
- **동의한 약관 글자**(시안 밖 — 검토 채팅 승인 11/20): 이용약관 **"2026년 8월 12일 동의 · 제1판"**, 개인정보처리방침 **"2026년 8월 12일 안내 확인 · 제1판"**. 시안은 둘 다 "동의"라고 적었으나 개인정보 칸은 동의가 아니라 **안내 확인**이라는 결정(0065)에 맞췄다. "제N판"은 지금 판이면 `LegalDoc.edition`, 모르는 이전 판이면 판 번호 글자 그대로.
- **내 계정 시트**의 "회원 정보" 줄을 켰다(화면 있는 줄 → 시트를 닫고 이동). 회원탈퇴는 시트가 아니라 회원 정보 화면 맨 아래에만 둔다.
- **`/account/withdraw` 탈퇴 확인**: 확정 문구 그대로(지워지는 것 6줄 · 굵은 줄 · 남는 것 작게 · 연결 해제 안내 · 다시 로그인 안내 · "위 내용을 확인했어요" · [탈퇴하기]). **연결 해제 안내 줄은 이번에는 늘 보인다**(구글 · 네이버 끊기가 L6-2이므로 · 카카오 회원도 끊기가 실패할 수 있어 같게). 확인 칸을 켜야 [탈퇴하기]가 눌린다(`aria-disabled`, 누르려 하면 안내 줄 "위 내용을 확인했다고 체크하면 탈퇴할 수 있어요"), 바탕 `--color-danger`, **두 번 누름 막기**(누르면 "탈퇴하는 중이에요"). 폼 `POST`라 자바스크립트가 없어도 되고 서버도 확인 칸을 본다. "남는 것"은 이슈의 확정 글자(시안보다 길어짐 — 이슈 표 우선), "다시 로그인 안내"는 시안 v0.4.2 글자 그대로.
- **탈퇴 실패 한 줄**(확정 문구 밖 — 검토 채팅 승인 11/20): "탈퇴를 마치지 못했어요. 잠시 뒤 다시 해 주세요". 회원 정보를 못 읽었을 때의 "회원 정보를 불러오지 못했어요. 잠시 뒤 다시 열어 주세요"도 같은 쉬운 말 규칙으로 더했다(동의 저장 실패 줄과 같은 모양).

### 4. 카카오 연결 끊기 — 공식 문서로 확인 (2026-11-20)

`POST https://kapi.kakao.com/v1/user/unlink`, 머리 `Authorization: KakaoAK ${서비스 앱 어드민 키}` · `Content-Type: application/x-www-form-urlencoded;charset=utf-8`, 본문 `target_id_type=user_id` · `target_id=<카카오 회원번호>`, 응답 `{ "id": <회원번호> }`. 근거 주소와 받은 날짜는 `docs/SOCIAL_LOGIN.md` 10장.

- **어드민 키는 서버 환경변수 `KAKAO_ADMIN_KEY`**다. 화면 코드 · 기록 · 댓글에 값을 쓰지 않는다. **없으면 끊기를 건너뛰고 "실패"로 다룬다**(탈퇴는 진행, 알림에 한 줄 더). 그래서 사용자가 키를 넣기 전에도 병합할 수 있다.
- **카카오 회원번호**는 지우기 **전에** `identities`의 카카오 줄에서 `identity_data.provider_id` → `sub` → `id` 순서로 **숫자 1~20자리**인 첫 값만 쓴다(요청 본문에 다른 값이 끼어들 길을 막음). ⚠ 이 필드 이름은 Supabase 문서와 가짜 서버로만 확인했고 **실제 카카오 로그인으로는 못 본다** → 미리보기에서 실제 탈퇴로 확인하는 항목(PR "확인할 것"). 값이 달라 끊기가 안 되면 탈퇴는 그대로 되고 안내 줄이 뜬다.
- **5초 시간 제한**, 서버 기록에는 단계와 상태 코드만(`withdraw/kakao-unlink` + `timeout` · `network` · `401` …). 키 · 회원번호 · 응답 원문 · 메일은 남기지 않는다. 응답 본문은 읽지 않는다.
- **`KAKAO_API_BASE`(시험 전용)는 이 컴퓨터(고리) 주소일 때만 받는다** — `http://127.0.0.1:<포트>` · `http://localhost:<포트>`만, 그 밖의 값(비어 있음 · 다른 주소 · https · 경로 · 계정 정보)은 **무시하고 `https://kapi.kakao.com`을 쓴다**. 이 변수는 **어드민 키를 실어 보낼 곳**을 바꾸므로 운영에 잘못 들어가도 키가 다른 곳으로 가지 않게 하려는 것이다(검토 채팅 11/20). e2e는 운영 빌드로 돌기 때문에 `NODE_ENV`로 가르지 않고 주소 모양으로 가른다. e2e 서버(3101)만 가짜 서버(54321)를 가리킨다.

### 5. 사용자가 할 일 (병합 뒤)

1. 카카오 개발자 콘솔 → 내 애플리케이션 → 앱 키에서 **어드민 키**를 확인한다(값을 대화창 · 파일 · 이슈에 적지 않는다).
2. Vercel → Settings → Environment Variables에 **`KAKAO_ADMIN_KEY`**를 **Production · Preview** 둘 다 넣는다(`KAKAO_API_BASE`는 **넣지 않는다**).
3. 다시 배포한다. 키가 없어도 탈퇴는 되고(안내 줄만 더 뜸) 끊기만 건너뛴다.
4. 미리보기에서 카카오 시험 계정으로 로그인 → 회원 정보 → 회원탈퇴를 해 보고, **카카오 계정의 "연결된 서비스"에서 CropMon이 사라졌는지**와 알림이 "탈퇴했어요"(한 줄)인지 본다. 안내 줄이 같이 뜨면 회원번호 필드 이름이 다른 것이므로 이슈에 알린다.

### 6. 알려 둘 것 · 다음 디자인 의뢰 때 넘길 목록

- 시안과 다른 글자 한 줄(설계 채팅에 알림): 개인정보처리방침 줄 **"안내 확인 · 제1판"**(시안은 "동의"), "남는 것" 문장이 이슈 확정 글자로 길어짐, 탈퇴 실패 한 줄 · 회원 정보 읽기 실패 한 줄(시안에 없음), 알림 두 줄(시안에 없음).
- 구글 · 네이버 회원은 자료 삭제만 되고 연결은 안내 줄이다(L6-2에서 재인증으로 끊고, 그때 탈퇴 화면의 연결 해제 안내 줄 · 개인정보처리방침 4번 3항 · 이용약관 9조 3항 문구를 정한다 — 약관 쪽 채팅 확인 뒤).
- 가짜 Supabase는 로그인한 사용자에 `email` · `identities`(카카오 회원번호)를 싣고, `delete_my_account`(성공하면 그 회원의 세션 · 설정 · 동의를 지움 · 실패 흉내) · 카카오 연결 끊기(요청 머리 · 본문을 적어 둠 · 실패 흉내) · `members`의 회원 정보 열 읽기를 흉내 낸다. "켬" 서버 시험은 파일마다 프로젝트 하나로 차례로 돈다(`members-on-withdraw` · `members-on-withdraw-mobile`을 더함).
- 실제 카카오로 하는 확인(회원번호 필드 · 실제 연결 끊김)은 미리보기에서만 가능하고, 스위치가 꺼져 있어 운영에서는 볼 것이 없다.

## 하지 않은 것

DB 변경, 구글 · 네이버 연결 끊기(L6-2), 계정 합치기, 탈퇴 사유 묻기, 탈퇴 뒤 되돌리기, 정기 정리 작업(O2), 알림 설정 화면, 농장 설정 · 작물 설정 화면(F1 · F2).

## 갱신 (2026-11-20, 이슈 #197 · 결정 0068)

구글 · 네이버 회원은 이제 [탈퇴하기]에서 **그 공급자로 한 번 더 로그인**한 뒤 탈퇴 + 끊기를 한다(결정 0068). 카카오만 있는 회원은 이 문서 그대로다. 1절의 "구글 · 네이버는 자료 삭제만 되고 안내 줄로 갈음"은 **네이버 스위치가 꺼져 있을 때의 네이버 회원**과 재인증하지 않은 나머지 공급자에게만 남는다. `withdrawOutcome`은 공급자별 결과 표를 받는 `withdrawOutcomeFor`의 특수한 경우가 되었다(L6-1 시험은 그대로).
