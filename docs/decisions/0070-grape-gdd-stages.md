- 관련 이슈: #201. 앞: 농장 DB와 포도 사전(결정 0062 — 포도 `gdd_stages` · 라벨은 일부러 비워 둠) · 적산 계열(0063). 뒤: 포도 온도 화면 G1(지역 보기) · G2(회원 포도, 1/1 뒤), 도달 카드 단계 이름 표시.

## 배경

D1-2(결정 0062) 때 포도 작목 `crops.grape`의 `gdd_stages` · `gdd_stage_labels`는 croplib-dp가 세 숫자를 계산하는 중이라 비워 두었다(시드 파일 `20261120010000_seed_grape_dictionary.sql` 4번 주석). 그 계산이 끝났다.

## 결정

1. **값**(croplib-dp #126 확정, 2026-11-21): `gdd_stages` = `{370,1040,2050}`, `gdd_stage_labels` = `{"만개","변색기","수확기"}`.
2. **근거**: 기준온도 10℃, 04-20부터 누적, 평년 2016–2025, 다섯 지점(구미 · 영천 · 상주 · 추풍령 · 거창) 평균을 10 단위로 반올림. 대표 품종은 샤인머스캣(포도 기준값 결정표).
3. **비가림만 해당.** `gdd_stages`는 작목(`crops`) 한 줄에 붙지만 적산을 내는 작형은 비가림(`cum_start_mmdd = '04-20'`)뿐이다. 시설가온은 `cum_start_mmdd`가 비어 적산온도를 내지 않는다. 그래서 이 값은 사실상 비가림의 값이다. 출처(`source`) 글에 "비가림 04-20 기준"이 드러나게 덧붙였다.
4. **새 시드 파일 하나**(`20261121000000_seed_grape_gdd_stages.sql`): `update public.crops … where crop_id = 'grape'`. 옛 시드 파일은 고치지 않는다(머리말 규칙: "값을 고칠 때는 새 파일을 더한다"). `source`는 **글을 통째로 지정**해 여러 번 실행해도 근거가 두 번 붙지 않는다. 다른 열(Kc · Zr · p · 높이 · 기준온도 · 이름)은 건드리지 않는다.
5. **옛 시드와의 관계**: 옛 포도 시드의 `on conflict … do update`는 `source`를 옛 글로 덮어쓰지만 `gdd_stages` · 라벨은 건드리지 않는다. 옛 시드만 다시 돌리면 "단계 값은 있는데 출처 글은 옛 글"이 된다. 마이그레이션을 이름 순서대로 다시 돌리면 새 파일이 뒤에서 바로잡는다. **새 파일 머리말에 "옛 포도 시드를 다시 돌렸다면 이 파일도 이어서 돌린다"를 적었다.**
6. **지금 화면은 바뀌지 않는다. 이 값은 G1 · G2에서 처음 쓰인다.** 근거: `crops.gdd_stages`를 읽는 곳은 `src/infra/supabase/heat-source.ts`의 `stages(cropId)` 하나이고, 부르는 곳은 `src/services/temperature.ts`뿐이며, 넘기는 값은 `CROP_DB_ID`(작물 공통 · 사과 · 배추)다. 포도는 선택할 수 있는 작물이 아니라 어떤 화면 경로도 `stages("grape")`를 부르지 않는다.
7. **단계 이름(라벨)을 화면에 보여 주는 일은 범위 밖**(도달 카드 단계 이름은 G1 · G2 때).
8. 가짜 Supabase(`e2e/fake-supabase.mjs`)의 `crops`에는 포도 줄이 없어 맞출 것이 없다.

## 확인 · 되돌리기

- `supabase/checks/grape_gdd_check.sql`: 시드와 같은 update를 안에서 실행하고 일부러 오류로 되돌리는 방식(아무것도 남기지 않음). "한 일 → 변수 → 상태 확인"(결정 0065 확인 SQL 규칙) — 실행 전 스냅샷과 영향받은 줄 수를 먼저 변수에 담은 뒤 상태를 읽는다. 항목 15개, 맨 끝 `all_ok`. 한 번 더 실행해도 같은 결과(근거가 두 번 안 붙음)도 본다.
- `supabase/checks/grape_gdd_rollback.sql`: 두 열을 다시 비우고 `source`를 원래 글로 돌린다. 문제가 있을 때만.
- 기존 `d1_2_farms_check.sql` **11a**는 "적산 단계와 라벨은 비어 있다"를 보았다. 시드 뒤에는 거짓이 되므로 기대값을 **새 값과 같다**로 바꿨다(항목 수 118 그대로, 다른 항목 그대로 — `d1_1` 3a를 L4 때 고친 방식과 같다). 이 항목은 시드를 실행하기 전에는 false다.
