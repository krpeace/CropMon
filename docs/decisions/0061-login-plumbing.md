# 결정 0061: 로그인 배관 · 회원제 기능 스위치 (이슈 #182, M2 · L2)

- 날짜: 2026-11-19
- 상태: 확정 (실제 공급자로 해 보는 확인은 L3)
- 관련 이슈: #182 (순서표 #144 M2의 L2). 앞: 회원 DB(결정 0059, `members` · `ensure_my_member()`). 뒤: L3(로그인 시트 · 공급자 버튼 · 알림), L4(동의 화면), L5(계정 저장), L6(회원 정보 · 탈퇴).
- 설정 순서와 함정: `docs/SOCIAL_LOGIN.md`.

## 배경

2027-01-01 회원제는 **SNS 로그인만**(카카오 · 네이버 · 구글, 아이디 · 비밀번호 가입 없음)이고 **로그인 = 가입**이다. 로그인 직후 사용자는 **누르기 전에 보던 화면**(주소의 `?st=&crop=` 포함)으로 돌아간다. 이 결정은 그 **배관만** 깐다: 콜백 · 세션 · 로그아웃 · 돌아갈 주소 검사 · 로그인이 필요한 주소 목록 · **기능 스위치**. 화면(로그인 시트 · 버튼 · 알림)은 L3이다.

CropMon은 **공개가 기본**이다. 로그인이 필요한 곳만 목록으로 막는다(대부분의 틀은 반대로 "로그인이 기본").

## 결정

### 1. 기능 스위치 `MEMBERS_ENABLED`

- **서버 환경변수**(`NEXT_PUBLIC_` 아님). 정확히 `"true"`일 때만 켠다. 없거나 비었거나 다른 값(`True` · `1` · 공백 포함)이면 끈다. 판단은 순수 함수 `membersEnabled(env)`(`src/domain/members-switch.ts`).
- **요청 때 읽는다.** 빌드는 한 번이고 서버만 환경변수를 달리해 켬 · 끔을 돌린다(e2e도 이렇게 한다). 빌드 때 굳으면 값을 바꿔도 안 바뀐다.
  - 주의: `cacheComponents`에서는 요청 정보를 안 쓰는 `GET` 경로 처리기가 **빌드 때 미리 만들어진다(정적)**. 처음 만들었을 때 `/auth/callback` · `/auth/login`이 그렇게 잡혀 스위치가 굳을 뻔했다(빌드 결과 `○`). 그래서 `/auth/*` 경로 처리기는 맨 앞에서 `membersEnabledNow()`(`src/app/_lib/members.ts` — `await connection()` 뒤에 읽음)를 부른다. 빌드 결과가 `ƒ`(요청 때)인지 확인한다. 프록시는 매 요청 도는 곳이라 `membersEnabled(process.env)`를 바로 쓴다.
- **끄면 지금 알파와 똑같다**: `/auth/login` · `/auth/callback` · `/auth/signout`은 **404**(쿠키를 심지 않음, e2e가 확인), 프록시는 폐지 지점 돌려보내기만 하고 세션도 쿠키도 로그인 필요 목록도 안 본다. 기존 e2e는 끔 서버(3100)에서 **하나도 안 바꾸고** 통과한다.
- 설정은 사용자 몫: `.env.example`에 설명과 빈 값, Vercel에는 사용자가 넣는다(L3 · O3에서 운영에 켠다). 화면(헤더)이 스위치를 알아야 할 때 어떻게 넘길지(정적 쪽을 동적으로 만들지 않는 방법)는 L3에서 정한다.

### 2. `middleware.ts` → `proxy.ts` 하나로

- Next.js 16 이름대로 `src/proxy.ts`(`export async function proxy`). **폐지 지점 돌려보내기(결정 0037)와 matcher는 그대로**다. `middleware.test.ts`의 다섯 시험은 `proxy.test.ts`로 옮기고 **기대값은 바꾸지 않았다** — `proxy`가 `async`라서 `await`만 붙었다.
- 순서: ① 폐지 지점이면 돌려보냄(스위치와 상관없음) → ② 스위치 끔이면 끝 → ③ 켬: **로그인 쿠키(`sb-<프로젝트>-auth-token`, 쪼개지면 `.0 .1`)가 없으면 Supabase를 부르지 않는다**(방문자 대부분 — 템플릿처럼 요청마다 `getClaims()`를 부르면 쪽마다 바깥 요청이 하나씩 는다). 쿠키 이름은 주소마다 달라 **이름 모양**(`hasAuthCookie`)으로 가른다. 로그인 도중에만 있는 `…-code-verifier` 쿠키는 세지 않으므로 **`/auth/callback`도 교환 전에 Supabase를 부르지 않는다**(단위 시험이 못 박음). ④ 쿠키가 있으면 `getClaims()`로 로그인 여부를 확인하고 세션을 갱신한다.
- **로그인 필요 목록** `LOGIN_REQUIRED_PATHS`(`src/domain/auth.ts`): `/farm/settings` · `/farm/crop` · `/account`와 그 아래 주소(F1 · F2 · L6이 이 이름으로 화면을 만든다). `/my-farm`(비회원 정적 미리보기, 결정 0018) · `/auth/*` · `/api/*`는 절대 넣지 않는다(시험이 못 박음). 스위치가 켜져 있고 로그인 안 한 사람이 열면 **`/?login=1&next=<그 주소>`**로 보낸다(L3의 로그인 시트가 `login=1`을 읽어 연다). 주소는 인코딩 · 점(`..`) · 겹친 슬래시로 가려도 비켜 가지 못한다(`requiresLogin`이 다듬은 뒤 견줌, 풀 수 없는 인코딩은 "필요"로 봄).
- **프록시의 막기는 편의이고 진짜 막이는 DB의 RLS다.** 로그인 확인은 토큰에서 읽으므로 다른 기기에서 로그아웃한 것은 토큰 만료까지(기본 1시간) 늦게 반영된다. 화면(F1 · F2 · L6)도 자기 쪽에서 한 번 더 확인한다.

### 3. `/auth/*` 경로 (스위치를 끄면 모두 404)

- **로그인 시작 `GET /auth/login?provider=kakao|google|custom:naver&next=<돌아갈 주소>`** — **서버에서 PKCE를 시작한다**(코드 검증값 쿠키를 심고 공급자 화면으로 `302`). 이유: ① L3의 버튼이 **그냥 링크**가 되어 자바스크립트 없이도 동작하고, 브라우저용 Supabase 클라이언트를 화면에 싣지 않는다(그래서 `browser-client.ts`는 만들지 않았다 — 필요해지면 L3에서) ② 모르는 공급자 · 나쁜 `next` 거절이 서버 한 곳에서 시험된다.
  - **⚠ L3 버튼은 `<a>`로 걸고 `<Link>`는 쓰지 않는다.** 로그인 시작은 쿠키를 심는 요청이라 `<Link>`의 미리 불러오기가 그 요청을 먼저 보내면 안 된다.
  - 공급자는 허용 목록(`isAllowedProvider`)만. 모르면 400. 네이버는 Supabase 기본 공급자가 아니라 사용자 지정(`custom:naver`)이고, 설정은 L3 시험 과제다(목록에는 넣어 둠).
- **콜백 `GET /auth/callback`** — 코드를 세션으로 바꾸고(PKCE, 사람의 User-Agent를 넘김) **성공하면 `public.ensure_my_member()`를 한 번 부른다**(가입 트리거가 오류를 삼켜 `members` 줄이 빠진 경우를 메움, 결정 0059). **이 호출이 실패해도 로그인은 계속**하고 서버 기록에는 오류 **코드만** 남긴다. 그다음 검사한 `next`로 `302`(없거나 위험하면 `/`).
  - 실패 · 취소는 돌아갈 화면 주소(`next`, 없으면 `/`)에 **표시 하나**만 붙인다: **`login=cancelled`**(공급자 화면에서 취소 — `access_denied`) · **`login=failed`**(그 밖의 모든 실패, 코드도 오류도 없이 돌아온 경우 포함 — 오류가 주소의 `#` 뒤로 오면 서버는 못 보므로 "실패"로 본다). L3가 이것을 읽어 취소는 말없이, 실패는 "로그인을 마치지 못했어요. 잠시 뒤 다시 해 주세요"를 띄운다. 주소에 있던 `login` · `next` 검색어는 지우고 나머지 검색어와 `#`는 그대로 살린다(`withLoginNotice`).
  - **원문 오류 · 이메일 · 이름 · 사용자 ID · `code` · 토큰은 화면 · 주소 · 응답 · 서버 기록 어디에도 넣지 않는다.** 서버 기록은 한 함수(`logAuthError(단계, 코드)`)로만 남기며, 코드는 글자 · 숫자 · `_` 40자 이내 모양일 때만 기록하고 아니면 `unknown`이다(점 · 하이픈이 든 토큰 · UUID 모양은 못 지나감).
- **로그아웃 `POST /auth/signout?next=<돌아갈 주소>`** — 세션 쿠키를 지우고 검사한 `next`(없으면 `/`)로 `303`. **`POST`만**(링크 미리 불러오기로 로그아웃되지 않게 `GET`은 405). **`Origin` 헤더가 있고 이 사이트가 아니면 403**(다른 사이트가 몰래 로그아웃시키는 것을 막음; `null` 문자열도 다른 사이트로 봄). **`Origin`이 없는 요청은 막지 않는다**(오래된 브라우저 · 일부 앱 안 브라우저) — 시험으로 못 박았다.
- 콜백 주소의 바탕(origin)은 요청 주소에서 얻는다. Vercel 미리보기 · 휴대폰 미리보기에서 `localhost`로 떨어지는 함정과 Redirect URLs 허락 목록은 `SOCIAL_LOGIN.md`.

### 4. 돌아갈 주소 검사 `validateRedirectPath`

템플릿의 검사(`/` 시작 · `//` · `\` · `://`)에 이슈가 요구한 것(**인코딩으로 숨긴 것 · 제어 문자 · 로그인 길 자신**)을 더해 새로 썼다. 안전하면 **받은 값 그대로**(검색어 · `#` 살림), 아니면 `/`.

- **경로 부분**(`?` · `#` 앞)만 앞머리를 본다: `/`로 시작, `//`로 시작하지 않음, `\` 없음, `/auth` 아래가 아님(돌고 도는 것 방지). **인코딩을 풀어(최대 세 겹) 같은 검사**를 한다(`%2f%2f` · `%5c` · `%252f` 등).
- **제어 문자**(줄바꿈 · 널 · DEL)는 **전체**에서, 풀어 본 값까지 거절한다.
- **검색어 · `#`의 값은 경로가 아니므로** 그 안의 `%2F` · `://` · `%5C`는 거절하지 않는다(나중에 정상 주소가 막히지 않게).

| 받은 값                                                                                                                                    | 결과                    |
| ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------- |
| `/water?st=101&crop=apple&soil=loam&kc=1.05&d=2026-11-19&run=3` (지금 쓰는 검색어 `st` · `crop` · `soil` · `kc` · `d` · `run`)             | 그대로 통과             |
| `/water?back=%2F%2Fx` · `/water?u=https%3A%2F%2Fx.example` · `/water?u=https://x.example/a` · `/water?p=a%5Cb` (검색어 **값** 안의 인코딩) | 그대로 통과 (의도)      |
| `//evil.example` · `https://evil.example` · `javascript:…` · `/\evil` · `\\evil` · `/a\b`                                                  | `/`                     |
| `/%2f%2fevil.example` · `/%5cevil` · `/%252f%252fevil` (경로 앞머리의 인코딩)                                                              | `/`                     |
| `/water\n` · `/water%0d%0aSet-Cookie:x` · `/water?x=%0a` · `/water#a%0d` (제어 문자, 어디든)                                               | `/`                     |
| `/auth/login` · `/auth%2flogin` · `/%61uth/login`                                                                                          | `/` (`/authors`는 통과) |
| 비어 있음 · 문자열 아님 · 앞 공백 · 2048자 초과                                                                                            | `/`                     |

### 5. 클라이언트 · 의존성 · 구조 규칙(결정 0033)

- **`@supabase/ssr` `0.12.7`을 정확한 판으로 고정**한다. 사내 틀이 `@supabase/supabase-js 2.118.0`(CropMon과 같은 판)과 함께 쓰는 조합이고 `supabase-js`가 `^2.114.0` 이상이면 된다. `npm ls @supabase/supabase-js`는 `2.118.0` 하나뿐(중복 없음)이고, 새로 딸려 온 것은 `cookie@1.1.1`뿐이다.
- **공개 자료 읽기는 지금의 `getSupabaseClient()`(세션 없음)를 그대로 쓴다.** 물 · 온도 · 햇빛 · 헤더 · 판정 표를 쿠키 클라이언트로 바꾸면 `use cache`가 사람마다 달라지거나 화면이 동적이 된다(결정 0038). 이번에 화면 쪽 읽기는 바꾸지 않았다.
- **`src/infra`는 Next.js를 모른다(결정 0033, ESLint가 막음)** — 사내 틀은 쿠키 어댑터를 infra에 두었으나 여기서는 나눴다: Next.js를 모르는 `createCookieSupabaseClient`(쿠키 읽고 쓰는 방법을 받음) · `current-user.ts` · `auth-log.ts`는 `src/infra/supabase/`, `cookies()` · `connection()` · `NextRequest`를 쓰는 어댑터(`server-client.ts` · `proxy-client.ts`)와 `membersEnabledNow()`는 `src/app/_lib/`.
- `current-user.ts`는 `getClaims()`로 읽되 **id만** 돌려준다(이메일 · 전화 · 메타는 안 옮김 — 개인 값이 필요한 이슈에서 더한다).

### 6. 가짜 서버는 HS256 흉내다 — 실제 서명 방식 확인은 L3 실제 로그인 때

`getClaims()`는 Supabase가 **비대칭 열쇠(ES256)**로 서명한 토큰이면 Auth 서버에 가지 않고 **공개 열쇠(JWKS)로 그 자리에서** 서명 · 만료를 확인하고, 예전 **대칭 열쇠(HS256)** 토큰이면 `getUser()`로 돌아가 Auth 서버에 확인한다. e2e의 가짜 Supabase(`e2e/fake-supabase.mjs`)는 **HS256 모양 토큰**을 만들어 `/auth/v1/user`로 확인하게 하므로 **실제 프로젝트의 서명 방식(비대칭이면 공개 열쇠 확인)과 길이 다르다.** 시험이 증명하는 것은 "쿠키가 있으면 확인하고, 없으면 부르지 않고, 확인 결과에 따라 보냄"까지이고, **실제 서명 방식 · 공개 열쇠 받기는 L3에서 실제 공급자로 로그인할 때 확인한다.** (토큰은 가짜 서버가 실행할 때 만들어 소스에 JWT 모양 글자를 적지 않는다 — 비밀 검사 오탐 방지.)
