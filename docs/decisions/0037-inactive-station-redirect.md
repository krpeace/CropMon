# 0037. 폐지·휴지 지점 주소는 기본 지점으로 이동하고 안내를 표시한다

- 날짜: 2026-11-08
- 상태: 확정 (2026-11-08 사용자 결정)

## 왜

지점 사전(`stations`, 계약 v1.6)에는 관측이 중단된 폐지·휴지 지점 8곳(`isActive = false`, 예: 116 관악산, 175 진도(첨찰산))이 과거 기록 보존을 위해 등록되어 있다.

이전에는 사용자가 `st=116` 같은 폐지 지점 주소로 직접 들어오면 `parseSelection`이 조용히 기본 지점(춘천 101) 자료를 보여 주었으나, 주소창은 `st=116` 그대로 남아 있어 사용자는 왜 춘천 자료가 나오는지 알 수 없었다.

## 결정

- **한 곳(middleware)에서 이동:** 화면별로 리다이렉트 코드를 넣지 않고, Next.js 미들웨어(`src/middleware.ts`)에서 폐지·휴지 지점(`st`가 `stations` 사전에서 `isActive === false`인 8곳)으로 요청이 들어오면 `st=101&from=<폐지번호>`로 307 이동시킨다. 다른 쿼리(작물 `crop`, 토성 `soil` 등)는 그대로 유지한다.
- **사전에 없는 번호는 기존 처리 유지:** 사전에 없는 지점 번호(`st=999`)나 잘못된 값(`st=abc`)은 미들웨어가 개입하지 않고 그대로 통과시키며, `parseSelection`이 조용히 기본값으로 대체하고 별도 안내 배너를 띄우지 않는다.
- **공용 셸(SiteHeader)에서 안내 표시:** 상단 헤더(`SiteHeader`)가 `from` 쿼리를 읽어 지점 사전에 등록되어 있고 `isActive === false`인 8곳일 때만 사전에서 지점 이름을 가져와 상단에 한 줄 안내를 표시한다 (사전에 없거나 운영 지점(108 등)인 경우, 숫자가 아닌 값(abc 등)은 무시):
  `○○(번호)은 관측이 중단된 지점이라 기본 지점을 보여 드려요`
- **화면 전환 시 안내 자연 해제:** 다른 메뉴 탭이나 지역 칩을 클릭할 때는 `withSelection`을 통해 `st=101`로만 이동하므로 `from` 파라미터가 자동으로 사라져 안내가 깔끔하게 닫힌다.
