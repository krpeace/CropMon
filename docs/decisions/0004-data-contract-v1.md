# 0004. 데이터 계약 v1: 공개 테이블 9개

- 날짜: 2026-10-24
- 상태: 확정

## 결정

- **작형 사전을 따로 둔다 (`crop_seasons`).** 사과 같은 과수는 한 해에 생육기가 하나지만, 배추 같은 채소는 봄·여름·가을·월동 작형마다 시작일과 생육 기간이 다르다. 작물에 따라 정해지는 값(Kc, 뿌리깊이)은 `crops`에, 작형에 따라 달라지는 값(시작일, 생육단계 일수)은 `crop_seasons`에 둔다. 고추·무 같은 작형 작물을 더할 때도 줄만 늘리면 된다.
- **기본 작기 시작일:** 사과 4월 1일, 여름배추(고랭지) 7월 1일. 봄·가을·월동배추는 값을 정할 때까지 비워 두고, 비어 있는 작형은 화면 선택지에 나오지 않는다.
- **시작일 수정은 1/1 회원 버전부터.** 고친 값은 표준값을 덮어쓰지 않고 농장별 보정값 층(v2)에 저장하며, 서버(croplib-dp)가 다음 수집 회차에 다시 계산한다. 화면은 계산하지 않는다는 원칙(CLAUDE.md 규칙 1) 때문이다. 11/06 비회원 화면은 기본값으로 고정한다.
- **토성 값은 FAO-56 Table 19만 쓴다.** 12종 중 9종에만 값이 있고, 나머지 3종(사질식양토·식양토·사질식토)은 비워 둔다. 표가 범위로 나와 있어 범위 양 끝을 저장하고, 계산에는 가운데 값을 쓴다(양토 FC 0.25 / WP 0.12). cropwater가 써 온 값(0.22 / 0.10)과 달라서, 현장 PC와 숫자를 비교할 때만 cropwater 값을 넣는다.
- **상태 판정은 서비스 엑셀 기준 다섯 가지.** 휴면기, 과습 경고(Dr = 0), 토양 수분 충분(0 < Dr < RAW × 0.5), 주의(RAW × 0.5 ≤ Dr < RAW), 관수 필요(Dr ≥ RAW). 이론 근거가 약해서 운영하면서 다듬는다. 규칙은 croplib-dp 계산 코드에 두고, 바꾸면 `calc_version`을 올린다.
- **상태는 문구가 아니라 코드로 저장한다.** `need`, `ok`, `enough`, `wet`, `dormant`. 화면 문구는 `src/domain/water-status.ts`가 붙이므로 문구를 바꿔도 DB는 그대로다. `ok`의 문구는 지금 화면이 "아직 여유", 서비스 엑셀이 "주의"로 다르며, 화면 쪽에서 정한다.
- **DB는 구조만 막고, 값의 범위는 croplib-dp가 막는다.** DB에는 키, 연결, 이름이 정해진 칸(상태, 수집 방식 등), `lead_day` 0~3, `wp < fc`만 둔다. ETo 0~15 같은 범위는 croplib-dp가 올리기 전에 검사한다. 범위 규칙을 고칠 때 DB를 바꾸지 않게 하려는 것이다.
- **수집 기록의 실패 이유와 원자료 위치는 공개하지 않는다.** `forecast_runs`의 `error`, `raw_path`는 칸 단위 권한으로 비회원·회원이 읽지 못하게 했다. 나머지 칸은 누구나 읽는다. 화면은 `select *`가 아니라 필요한 열을 적어서 읽는다.
- **모든 테이블은 기본으로 붙는 권한을 먼저 거두고(`revoke all`), 읽기만 다시 준다.** 쓰기 정책은 만들지 않는다. 쓰기는 croplib-dp의 서버 키(service role)만 한다.

## 자동으로 지키는 것

`src/infra/supabase/contract.test.ts`가 계약서의 테이블 목록과 마이그레이션이 같은지, 모든 테이블에 RLS와 읽기 정책이 있고 쓰기 권한이 없는지, 상태 코드가 `src/domain/water-status.ts`와 같은지를 검사한다. 이 마이그레이션은 임시 PostgreSQL에서 두 번 실행해 오류가 없는 것과, 비회원이 읽기만 되고 쓰기는 막히는 것을 확인했다.

## 남은 것

- 화면 주소의 `?crop=cabbage`는 DB의 `kimchi_cabbage`와 이름이 다르다. 화면이 DB를 읽게 만들 때(물5) 맞춘다.
- 기존 화면 코드(`src/domain/water-status.ts`)에는 "아직 여유(ok)"와 "토양 수분 충분(enough)"이 있고 "주의"가 없다. `ok`를 "주의" 구간(RAW × 0.5 ≤ Dr < RAW)으로 쓰기로 했으니, 문구는 화면 쪽에서 정한다.
- croplib-dp의 업로드 코드와 계약 검사는 별도 PR로 이 계약에 맞춘다.
