# 결정 0068: 구글 · 네이버 연결 끊기 — 탈퇴 때 한 번 더 로그인, 다른 계정이면 지우지 않음 (이슈 #197, M2 · L6-2)

- 날짜: 2026-11-20
- 상태: 확정 (DB 변경 없음 — 병합은 CI 통과 뒤 검토 채팅이 바로 한다. 사용자 할 일: 네이버를 켤 때 Vercel에 `NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET` 넣기, 6절)
- 관련 이슈: #197 (순서표 #144 M2의 L6-2). 앞: 탈퇴 · 카카오 끊기(결정 0067) · 로그인 배관(0061) · 로그인 시트(0064). 뒤: 탈퇴 화면 안내 줄 새 글자 · 개인정보처리방침 4번 3항 · 이용약관 9조 3항 고침(약관 쪽 채팅 확인 뒤 작은 후속 이슈).
- **DB · 데이터 계약 변경 없음.**
- ⚠ **네이버 공식 문서 미확인** — 이 환경에서 `developers.naver.com`을 읽지 못했다(검토 채팅도 같음). 네이버 토큰 삭제의 요청 모양(`service_provider=NAVER` 포함)은 공식 문서를 옮긴 글들이 일치하는 것을 따랐고, 재인증 옵션 `auth_type=reauthenticate`는 기억에 의존한다. **사용자가 공식 문서를 확인하거나 미리보기 실제 탈퇴로 확인**해야 한다(PR "확인할 것"). 네이버 켜기는 어차피 12/15 이후(결정 0064)라 지금 막히지 않는다.

## 배경

L6-1(결정 0067)로 탈퇴와 카카오 끊기(어드민 키)는 끝났다. **구글 · 네이버는 그 회원의 공급자 토큰이 있어야 끊을 수 있고**, Supabase는 공급자 토큰을 DB에 저장하지 않고 **로그인 직후 한 번만** 준다. 그래서 탈퇴할 때 **그 공급자로 한 번 더 로그인(재인증)**해 새 토큰을 받고, 그 자리에서 탈퇴 + 끊기를 한다. 공급자 토큰을 DB · 쿠키에 쌓지 않는 방식이다(보관하면 암호화 · 방침 항목이 늘어남).

**이 흐름에서 가장 중요한 것은 엉뚱한 계정을 지우지 않는 것이다.** 재인증 화면에서 사람이 다른 구글 계정을 고를 수 있다.

## 결정

### 1. 누가 재인증을 하나 — `reauthTarget`

- 연결된 공급자(`identities`)에 **구글 · 네이버가 있으면** 재인증, **카카오만이면 L6-1 그대로**(바로 탈퇴 + 어드민 키 끊기).
- 둘 다 있으면(드묾) **처음 가입한 공급자(`user.app_metadata.provider`)가 구글/네이버면 그것, 아니면 구글 → 네이버**(검토 채팅 승인). 그 공급자가 연결 목록에 없으면 따르지 않는다. 재인증하지 않은 나머지 공급자는 끊지 못하므로 알림에 안내 줄이 붙는다.
- **네이버는 `NAVER_LOGIN_ENABLED`가 켜진 때만** 대상이다. 꺼져 있으면 L6-1처럼 자료 삭제 + 안내 줄(재로그인 없음).

### 2. 시작 — `POST /auth/withdraw`의 갈래

1단계 검사(끔 404 · `Origin` 403 · 확인 칸)와 로그인 정보 읽기는 L6-1과 같다. 대상이 있으면 **아직 아무것도 지우지 않고**:

1. **탈퇴 의도 쿠키 `cm_wd`**를 응답에 심는다 — `HttpOnly` · `SameSite=Lax` · `Secure`(https일 때) · **`Path=/auth/callback`**(콜백만 받음) · `Max-Age=300`. 내용은 **지금 회원 번호의 해시 16자(`who`, 화면 설정 기준과 같은 함수 `whoOf`) · 공급자 · 만료 시각** — 회원 번호 · 메일은 넣지 않는다. 값은 JSON을 base64url로 만든 글자뿐이다.
2. `signInWithOAuth`로 그 공급자를 다시 시작한다. `redirectTo` = **기존 콜백 `/auth/callback?flow=withdraw`**(Supabase 허용 주소를 새로 넣을 필요 없음 — 이미 `?next=` 검색어를 쓴다). 구글은 **`prompt=select_account`**(계정 고르기만 — 동의 화면을 다시 띄우는 `consent`는 쓰지 않음, 구글 공식 문서로 확인), 네이버는 **`auth_type=reauthenticate`**(⚠ 미확인).
3. 시작에 실패하면 쿠키를 심지 않고 탈퇴 화면의 실패 줄로.

**쿠키에 서명을 하지 않는 까닭**(검토 채팅 승인): 콜백이 **새로 인증된 세션의 회원 번호 해시와 견주는 것**이 핵심이다. 쿠키를 위조할 수 있는 사람은 자기 해시를 넣어 **자기 계정만** 지울 수 있을 뿐이고 다른 사람을 지울 수는 없다. 서명하려면 서버 비밀이 하나 더 필요하다. 쿠키 값이 5분보다 오래 살 수 있게 만든 것은 읽을 때 "깨짐"으로 본다.

### 3. 콜백 탈퇴 갈래 — `GET /auth/callback?flow=withdraw`

일반 로그인 일(`ensure_my_member` · 동의 판단 · `login=ok` · `next`)은 **하지 않는다.** 의도 쿠키는 **어느 갈래든 지운다**(`Max-Age=0`과 과거 `Expires`를 함께 — Max-Age만으로는 Next가 로그아웃의 세션 쿠키와 응답을 합치는 과정에서 만료가 빠져 빈 값의 쿠키로 남는 것을 e2e가 알려 줬다).

| 상황                                        | 하는 일                                                                                                                                                                                                                                             | 도착                                            |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 공급자 화면에서 취소(`access_denied`)       | 아무것도 안 함. **코드 교환 전이라 원래 세션 그대로**                                                                                                                                                                                               | `/account/withdraw`(말 없음)                    |
| 그 밖의 오류 · 코드 없음 · 교환 실패        | 원래 세션 그대로(로그아웃도 안 함)                                                                                                                                                                                                                  | `/account/withdraw?withdraw=failed`             |
| **의도 쿠키 없음 · 깨짐 · 만료**            | **코드 교환도 안 한다** — 누구로 로그인될지 모르므로 원래 세션을 지킨다                                                                                                                                                                             | `/account/withdraw?withdraw=expired`            |
| 새 세션의 로그인 정보를 못 읽음             | 이 기기 쿠키 지움(알 수 없는 세션)                                                                                                                                                                                                                  | `?withdraw=failed`                              |
| **회원 번호 해시가 의도와 다름(다른 계정)** | **아무것도 안 지운다.** 이 기기 쿠키만 지운다(지금 세션이 다른 계정이 되었으므로)                                                                                                                                                                   | `/?account=withdraw-other`                      |
| 해시 같음                                   | `delete_my_account()` → (실패면 아무것도 안 끊고 로그아웃도 안 함, `?withdraw=failed`) → **방금 받은 `provider_token`으로 끊기**(구글 취소 · 네이버 삭제, **토큰이 없으면 "실패"**) → 카카오 identity도 있으면 어드민 키로 끊기 → 이 기기 쿠키 지움 | `/?account=withdrawn` 또는 `withdrawn-unlinked` |

- **알림 규칙**: 연결된 공급자를 **모두** 끊었을 때만 한 줄("탈퇴했어요"), 하나라도 못 끊었으면(실패 · 토큰 없음 · 키 없음 · 재인증하지 않은 공급자) 두 줄(L6-1과 같음). 순수 함수 `withdrawOutcomeFor(공급자, 결과 표)`이고 `withdrawOutcome`(L6-1 꼴)은 그것의 특수한 경우로 두어 L6-1 시험은 손대지 않았다.
- **다른 계정이 이번 재인증으로 새로 만들어졌다면** 그 계정은 동의 전 계정이라 **O2(동의 없이 24시간 지난 계정 정리)가 지운다.** 이번에 직접 지우지 않는다(범위 밖).
- **공급자 토큰은 그 요청 안에서만** 쓴다. 쿠키 · DB · 기록 · 주소에 남기지 않는다(기록은 단계와 상태 코드만). 토큰이 응답에 없으면(예: 사용자 지정 공급자 네이버가 안 주는 경우) "끊기 실패"로 다루고 탈퇴는 진행한다.

### 4. 끊기 함수 — `src/infra/google/revoke.ts` · `src/infra/naver/revoke.ts`

카카오 끊기와 같은 꼴: 던지지 않고 `ok · failed · skipped`, 5초 제한, 기록은 단계와 상태 코드(`timeout` · `network` · `400` …), 응답 원문 · 토큰 · 비밀은 안 남김. form `POST`와 시간 제한은 공통 함수(`src/infra/post-form.ts`).

- **구글**: `POST https://oauth2.googleapis.com/revoke`, `Content-Type: application/x-www-form-urlencoded`, 본문 `token=<토큰>`(구글 공식 문서로 확인, 2026-11-20). 성공 200 · 실패 400. 토큰이 없으면 부르지 않고 `skipped`.
- **네이버**: `POST https://nid.naver.com/oauth2.0/token`, form 본문 `grant_type=delete` · `client_id` · `client_secret` · `access_token` · `service_provider=NAVER`. HTTP 200 안에 오류가 올 수 있어 **본문의 `result`가 `success`일 때만** 성공으로 본다. **비밀(`client_secret`)과 토큰은 본문으로만** 보내고 주소 · 기록에 남기지 않는다. 클라이언트 아이디 · 시크릿은 서버 변수 `NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET`이고 하나라도 없으면 `skipped`(= 실패 취급). ⚠ 미확인(위).
- **시험용 주소 `GOOGLE_API_BASE` · `NAVER_API_BASE`는 카카오와 같은 규칙** — 이 컴퓨터(고리) 주소일 때만 받고 그 밖의 값은 무시하고 공식 주소를 쓴다. 규칙을 `src/infra/loopback-base.ts` 한 곳으로 모으고 `kakaoBase`가 그것을 쓰게 했다(카카오 시험은 그대로 통과).

### 5. 화면

- **탈퇴 확인 화면**: 재인증 대상 회원에게는 [탈퇴하기] 위에 한 줄 **"탈퇴하기를 누르면 연결을 끊기 위해 구글 로그인을 한 번 더 해요."**(네이버는 "네이버 로그인을") — **시안 밖, 검토 채팅 승인(11/20)**. 확정 문구의 **연결 해제 안내 줄은 이번에도 그대로**(전문가가 확인한 글자 — 끊기가 실패할 수 있음). 새 글자("탈퇴하면 연결도 함께 끊어요")와 방침 · 약관 고침은 약관 쪽 확인 뒤 후속 이슈.
- **새 글자 둘**(시안 밖, 검토 채팅 승인 11/20): 다른 계정 알림 **"다른 계정으로 로그인해서 탈퇴하지 않았어요. 원래 계정으로 다시 로그인해 주세요"**(긴 글이라 7초), 만료 줄 **"시간이 지나 탈퇴하지 않았어요. 다시 해 주세요"**. 공급자 화면 **취소는 말 없이** 탈퇴 화면으로 돌아온다(원래 세션이 그대로라 다시 누르면 됨). (**다음 디자인 의뢰 때 넘길 목록**에 세 줄을 더한다.)

### 6. 사용자 할 일 (병합 뒤)

- **구글**: 새 변수 없음. 미리보기에서 구글 시험 계정으로 실제 탈퇴 → **구글 계정의 "타사 앱 및 서비스"에서 CropMon이 사라졌는지** 확인, 재로그인 화면에서 **다른 구글 계정을 골랐을 때 아무것도 안 지워지는지**(원래 계정으로 다시 로그인하면 그대로) 확인. 구글 공식 문서는 취소가 프로젝트에 준 범위를 거둔다고만 하고 그 목록에서 사라지는지는 적지 않았다.
- **네이버를 켤 때만**: Vercel(Production · Preview)에 **`NAVER_CLIENT_ID` · `NAVER_CLIENT_SECRET`**을 넣는다 — Supabase 대시보드의 네이버 공급자에 이미 넣은 값과 같은 값(서버 변수라 화면에 안 나가고, 요청 본문으로만 보냄). `GOOGLE_API_BASE` · `NAVER_API_BASE`는 **넣지 않는다.** 네이버 공식 문서(접근 토큰 삭제 · 재인증 옵션)를 확인하고, 미리보기에서 네이버 시험 계정으로 실제 탈퇴해 본다.

### 7. 알려 둘 것

- **세션 쿠키에 공급자 토큰이 실린다**(확인함): `@supabase/ssr`가 세션 전체를 쿠키에 쓰므로 **보통 로그인에서도** 공급자 토큰이 로그인 쿠키에 함께 실린다(e2e `account-reauth.spec.ts`가 현재 동작으로 기록). 바꾸는 일은 이번 범위 밖이고, 검토 채팅이 O3 점검 목록과 방침 확인 목록에 올린다. 탈퇴 갈래는 끝에서 이 쿠키를 지운다.
- Supabase가 `queryParams`(`prompt` · `auth_type`)를 공급자까지 넘기는지, 사용자 지정(OIDC) 공급자 네이버가 `provider_token`을 주는지는 **실제 구글 · 네이버로만** 확인된다 — 가짜 서버로는 우리가 보낸 모양만 확인한다(PR "확인할 것").
- 기존 시험 한 곳이 바뀌었다(검사 기준은 그대로): `account.spec.ts`의 "구글 회원은 카카오 끊기를 부르지 않고 안내 한 줄" — 구글 회원이 이제 재로그인으로 이어지므로 같은 회원으로 재로그인하는 모양(`sameUser`)으로 바꾸고, 자세한 시험은 새 `account-reauth.spec.ts`로 옮겼다. 단위의 "구글 · 네이버 회원은 카카오를 부르지 않고 안내"는 네이버(스위치 꺼짐) 시험으로 바꿨고 구글은 재인증 시작 시험이 맡는다.

## 하지 않은 것

탈퇴 화면 연결 해제 안내 줄의 새 글자 · 방침 / 약관 고침(약관 쪽 확인 뒤), 재인증으로 새로 생긴 계정 즉시 지우기(O2), 계정 합치기, 공급자 토큰 보관, 세션 쿠키에서 공급자 토큰 빼기(O3 점검).
