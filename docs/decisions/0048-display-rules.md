# 결정 0048: 공통 표시 규칙 — 줄바꿈 금지 · 날짜 한국어 · 톤 환산 (이슈 #153)

- 날짜: 2026-11-19
- 상태: 확정
- 관련 이슈: #153 (순서표 #144의 P2)
- 기준: 디자인 규칙 v0.4.6 12절 "줄바꿈 금지 공백"

## 배경

앞으로 물 · 관수 기록 · 작물 설정 · 쓰는 물 화면이 같은 표시 규칙(날짜, 숫자 + 단위, 톤 환산)을 여러 곳에서 쓴다. 화면마다 따로 만들면 서로 어긋난다. 실제로 시안에서 같은 "작물이 쓸 물 1.3 mm"가 칸마다 2.5 · 2.6 · 2.7톤으로 보였다. 그래서 `src/domain` 의 순수 함수 한 곳에 먼저 모았다. 이번에 화면에 적용한 곳은 하나(물 판정 카드의 "부족한 물 51 mm / 관수 시작점 65 mm" 줄)뿐이고, 나머지 화면은 각 화면 이슈(W1 · W2 · W3 · F2 등)가 이 함수를 쓴다.

## 결정

### 1. 줄바꿈 금지 (`src/domain/display.ts`)

- **숫자 + 단위 · 날짜 조각 · "약" + 숫자 · 끝의 "›" 는 U+00A0**(줄바꿈 금지 공백)으로 묶는다: "35 mm", "1,000 m²", "300 L", "약 3.2톤", "2026년 12월 1일", "바꿔요 ›". 한글 단위 "톤"은 숫자에 붙여 쓴다("0.3톤").
- **가운뎃점 낱말("수집·이용", "작목·작형", "℃·일")은 U+2060**(단어 결합자)을 점 앞뒤에 둔다. 숫자 · 단위 · 날짜에는 U+2060 을 쓰지 않고 U+00A0 만 쓴다.
  - 이유: 150%에서 "수집 / ·이용"으로 끊겼다. 이 PC의 Chromium에서 실험하면 일반 가운뎃점은 폭 10~160px 중 100개 폭에서 끊기고, U+2060 으로 묶으면 어떤 폭에서도 끊기지 않았다(`e2e/no-break.spec.ts`).
  - **단점**: 보이지 않는 문자라 복사해 붙여넣거나 찾기(Ctrl+F)에 걸릴 때 낱말 가운데에 섞여 들어간다(읽어 주는 소프트웨어는 무시한다). 그래서 가운뎃점 낱말에만 쓴다.
  - **확인 범위**: **Chromium에서만 시험했다.** Safari(WebKit) · Firefox는 이 PC에 없어 직접 시험하지 못했다. U+2060 은 줄바꿈 규칙(UAX #14)의 줄바꿈 금지 문자라 아이폰 Safari · 안드로이드 Chrome도 따른다고 알려져 있으나 확인하지 않았다. 안 먹는 기기가 보이면 이 결정을 새 결정으로 고친다.
- **두 가지로 쓴다.** ① 값을 만드는 함수가 처음부터 묶인 글을 돌려준다(`valueUnit`, `koreanDate`, `koreanPeriod`, `formatApproxTons`, `formatWaterAmount`) — 새 화면의 기본 방법. ② 이미 있는 고정 문구(약관 · 안내 글)는 `keepTogether(text)` 로 한 번에 묶는다. `keepTogether` 의 단위 허용 목록은 `mm`, `mm/일`, `m²`, `㎡`, `MJ/m²`, `℃·일`, `L`, `평`, `kg`이며, 목록에 없는 말("35 명", "3 Level")은 건드리지 않는다(오탐 방지). 두 번 적용해도 같다(멱등) — 특히 `℃·일`은 숫자 + 단위(U+00A0)와 가운뎃점(U+2060) 규칙이 겹치지만 한 번만 묶인다.
- **기존 함수의 출력은 바꾸지 않는다.** `monthDay` 는 지금처럼 일반 공백을 돌려주고, 묶인 글이 필요하면 `{ tied: true }` 를 준다. 기존 단위 시험이 일반 공백 문자열을 그대로 비교하고, 다른 화면 문구를 일괄로 바꾸지 않기 위해서다.

### 2. 날짜 한국어 표기 (`src/domain/datetime.ts`)

- 입력은 `YYYY-MM-DD` 문자열이다. 요일은 `Date.UTC` 로만 계산해 시간대 때문에 하루 밀리지 않는다. 형식이 틀리거나 없는 날짜(2월 30일 등)는 `weekdayKo` · `tenDayPeriod` 가 `null`, `koreanDate` · `koreanPeriod` 가 "자료 없음"(시각 표기 `formatKoreanDateTime` 과 같은 방식)이다.
- `koreanDate` "2026년 8월 12일 (수)" — `year: false` 면 연도를 빼고 `weekday: false` 면 요일을 뺀다. 상순(1~10일) · 중순(11~20일) · 하순(21일~말일) `tenDayPeriod`, `koreanPeriod` "2027년 6월 하순". 해를 넘는 작기 표기에서 연도를 붙일지는 호출하는 쪽이 `year` 옵션으로 고른다.
- `monthDay` 는 `heat.ts` 와 `water-verdict.ts` 에 따로 있던 것을 `datetime.ts` 한 곳으로 옮겼다(출력 동일, 기존 시험은 같은 단언으로 이동).
- 시각 표기(`formatKoreanDateTime`, `koreanClock`)는 바꾸지 않았다.

### 3. 톤 환산 (`src/domain/water-amount.ts`)

- **계산이 아니라 표시 변환이다.** DB 의 mm 를 단위만 바꿔 보여 줄 뿐이고 모델 계산은 하지 않는다(CLAUDE.md 프로젝트 규칙 1: 이 저장소는 계산하지 않고 DB 값을 보여 준다). croplib-dp 와도 "톤 환산은 화면 표시 변환"으로 합의했다.
- **톤은 화면에 보이는 mm 로 곱한다**: **보이는 mm(소수 한 자리로 반올림한 값) × 면적(m²) ÷ 1,000.** 반올림 전 값으로 곱하지 않는다.
  - 이유: 농가가 화면의 mm 로 직접 곱해 봐도 화면의 톤과 같아야 한다. 반올림 전 값으로 곱하면 화면 mm 와 톤이 어긋난다(예: 1.25 mm → 화면 1.3 mm, 3,305 m² 에서 반올림 전 곱은 4.13톤인데 화면 mm 로 곱하면 4.3톤).
  - 반올림은 부동소수 오차에 흔들리지 않게 `Math.round(mm * 10 + 1e-9)` 로 한다(절반은 올림: 1.25 → 1.3, 1.24 → 1.2).
- **표기**(`formatApproxTons`): 늘 "약". 10톤 미만은 소수 한 자리 고정("약 2.6톤", 0도 "약 2.0톤" — 폭이 흔들리지 않게), 10톤 이상은 정수 + 천 단위 쉼표("약 169톤", "약 1,653톤" — 보이는 mm 가 0.1 단위라 큰 면적에서 톤의 소수 자리는 근거 없는 정밀함이고 폭만 넓어진다). **자리수는 반올림한 뒤의 값으로 정한다**: 9.95톤은 소수 한 자리로 10.0 이므로 "약 10톤"("약 10.0톤" 아님). 보이는 mm 가 0 이면 정확히 0 이라 "약" 없이 "0톤", 0 보다 크지만 소수 한 자리로 0.0 이 되는 양은 "0.1톤 미만". 값이 없거나 이상하면(null · 음수 · 면적 0 이하) `null` 을 돌려주고 "자료 없음" 문구는 화면이 정한다.
- **관수량 L ↔ 톤**(`convertWater`, `formatWaterAmount`): 1톤 = 1,000 L, 부동소수 찌꺼기를 없앤다(1.1톤 = 1,100 L). 관수 기록은 사용자가 넣은 단위 그대로 보여 주므로 "약"을 붙이지 않는다("300 L", "0.3톤"). 단위 타입은 `"L" | "ton"` 이고, DB `input_unit` 값과의 연결은 회원 표를 만드는 이슈(D1)에서 맞춘다.

## 알려진 한계

- U+2060 은 Chromium 에서만 확인했다(위 1 참고).
- `keepTogether` 의 단위 허용 목록은 지금 쓰는 단위만 담았다. 새 단위(예: 평년 표기)가 생기면 목록과 시험에 같이 더한다.
- 화면 적용은 물 판정 카드 숫자 줄 한 곳이다. 나머지 화면의 끊김은 각 화면 이슈에서 이 함수로 고친다.
