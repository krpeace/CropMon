# 결정 0052: 더보기 아래쪽 · 데스크톱 바닥글(운영자 표기) · 위험 색 토큰 (이슈 #161)

- 날짜: 2026-11-19
- 상태: 확정
- 관련 이슈: #161 (순서표 #144의 S4). 결정 0049(맥락 바) · 0048(공통 표시 규칙)을 이어받는다.
- 기준: 디자인 규칙 v0.4.6 12절 "더보기", 이슈 #161 본문 · 승인 댓글

## 배경

휴대폰 더보기는 서비스 메뉴 목록과 다크 모드 한 줄뿐이었다. 시안은 그 아래에 공지 · 문의 · FAQ · 약관과 화면 구성 · 글씨 크기를 두고, 끈 메뉴 안내는 맨 아래에 둔다. 데스크톱 바닥글에는 안내 항목과 **운영자(사업자) 표기**가 없었고, 앞으로 회원탈퇴 · 지우기 글자에 쓸 **위험 색**도 토큰이 없었다. 이 이슈는 이 셋만 맡는다.

## 결정

### 1. 더보기 (`/more`) 순서

서비스 메뉴 → **구분선** → 공지 · 문의 · FAQ · 약관 → 화면 구성 · 글씨 크기 · 다크 모드 → (끈 메뉴가 있으면) **맨 아래** "숨긴 메뉴 n개 · 화면 구성에서 다시 켜기".

- 아직 화면이 없는 줄(공지 · 문의 · FAQ · 약관 · 화면 구성 · 글씨 크기)은 **버튼처럼 보이되 `aria-disabled="true"`**, 회색 "준비 중" 꼬리표, 눌러도 이동하지 않는다. 눌리는 높이는 `fh-54`(글씨 크기를 따라 커지고 44 이상), 아이콘 24. 약관은 L1에서 `/terms` 링크로 바꾼다.
- 다크 모드 줄은 스위치 모양이고 **동작 · 버튼 이름("다크 모드로 보기" / "라이트 모드로 보기")은 그대로**(`useThemeToggle`). 휴대폰 맥락 바에는 해/달 버튼이 없어서 비회원은 여기서 바꾼다.
- "숨긴 메뉴" 줄은 서비스 메뉴 바로 아래에서 **맨 아래로 옮겼다**(줄 자체는 그대로). 시안과 이슈 문장("끈 메뉴가 있으면 맨 아래") 대로다.
- 아이콘 경로(공지 · 문의 · FAQ · 약관 · 화면 구성 · 글씨 크기)는 시안 v0.4.6에서 가져와 `ICON_PATH`에 더했다.
- 쪽 안 큰 제목 "더보기"는 **휴대폰에서만 보이지 않게**(`max-desktop:sr-only`) 했다 — 위 맥락 바에 같은 제목이 이미 있다. `h1`은 화면 읽기용으로 남고 데스크톱은 그대로다.

### 2. 데스크톱 바닥글 (폭 1024 이상만)

- 안내 항목 한 줄: **공지 · 문의 · FAQ · 약관 · 개인정보처리방침**(`ul`), "개인정보처리방침"만 굵게(700). 화면이 없어 **글자만**(링크 아님, "준비 중" 표시 없이 회색). L1이 약관 · 개인정보처리방침을 링크로 바꾼다.
- **운영자 표기**(12px, 회색): 주식회사 파모스 · 대표 이세용 · 사업자등록번호 281-87-02364 · 주소 · 전화 031-360-4152. **글자는 `src/domain/operator.ts` 한 곳**에만 둔다 — L1의 약관 · 개인정보처리방침 끝 운영자 줄이 "초안과 같은 글자"여야 해서 같은 값을 읽게 하려는 것이다. 공개된 사업자 정보다. 단위 시험이 이슈의 인용과 **한 글자도 다르지 않은지**(보이지 않는 글자가 안 섞였는지 포함) 못박는다.
- **줄바꿈**: 하이픈 숫자("281-87-02364", "031-360-4152")는 하이픈 뒤에서 줄이 끊긴다. #153의 `keepTogether`/`valueUnit`은 숫자 + 단위 · 날짜를 다루고 하이픈 숫자는 다루지 않으며, 검토에서 U+2060 같은 보이지 않는 글자는 가운뎃점 낱말에만 쓰기로 했다. 그래서 **글자는 바꾸지 않고** 마디(회사 · 대표 · 사업자등록번호 + 번호 · 주소 · 전화)마다 `white-space: nowrap`으로 묶고, 점(`·`)은 앞 마디 끝에 붙인다(줄 끝에 점이 오고 줄 처음에는 안 옴).
- 지금 바닥글의 "자료 출처" · 판 번호 · "CropMon 소개"는 그대로, **휴대폰 바닥글은 바꾸지 않는다**(안내 항목 · 운영자 표기는 휴대폰에서 숨김).

### 3. 위험 색 토큰 (이번에는 토큰만, 쓰는 곳 없음)

| 토큰                | 라이트           | 다크              |
| ------------------- | ---------------- | ----------------- |
| `--color-danger`    | `rgb(196 43 28)` | `rgb(255 105 97)` |
| `--color-on-danger` | `#fff`           | `#000`            |

- **글자 대비(WCAG, 4.5:1 이상이 기준)**: 라이트 위험 색 글자 — 흰 카드 5.66:1 · 바탕(`rgb(242 242 247)`) 5.07:1. 다크 — 검정 바탕 7.45:1 · 다크 카드(`rgb(28 28 30)`) 6.03:1.
- **`--color-on-danger`를 따로 둔 이유**: 다크에서 **흰 글자를 위험 색 바탕에 올리면 2.82:1**로 4.5에 못 미친다(검정 글자는 7.45:1). 시안도 탈퇴하기 버튼을 라이트 "흰 글자 / 빨강", 다크 "어두운 글자 / 연빨강"으로 그렸다. L6에서 버튼을 만들 때 글자 색을 틀리지 않게 바탕과 짝으로 둔다. 라이트는 흰 글자 5.66:1.
- **시험이 실제 값을 읽는다**: `src/domain/contrast.ts`(순수 함수 — 색 읽기 · 상대 휘도 · 대비비)와, 실제 `tokens.css`를 읽어 위 값과 대비를 확인하는 `src/app/tokens.test.ts`. 토큰이 바뀌어 대비가 떨어지면 시험이 잡는다.
- 상태 색(`--color-need-*`) 다크 값은 이슈에서 "확인함"이라 건드리지 않았다.

## 영향

- DB · `DATA_CONTRACT` 변경 없음. 서비스 메뉴 목록 · 휴대폰 바닥글 · 회원 "내 계정" 시트는 그대로.
- 기존 시험 변경 1건: `e2e/more.spec.ts`의 "준비 중 꼬리표 6개" 검사가 `main` 전체의 "준비 중"을 세고 있어, 아래 줄(공지 등)이 생기며 12개가 됐다. **기준(서비스 메뉴 6개에 꼬리표)은 그대로 두고** 세는 범위를 서비스 메뉴 줄(링크) 안으로 좁혔다. 아래 줄의 꼬리표는 `more-bottom.spec.ts`가 따로 본다.
- 새 시험: `operator.test.ts` · `contrast.test.ts` · `tokens.test.ts`(단위), `more-bottom.spec.ts`(휴대폰 390) · `footer.spec.ts`(데스크톱 1440, 휴대폰에서는 안 보임). 준비 중 줄 누름 시험은 줄을 화면 가운데로 올린 뒤 "누르는 자리에 줄이 있는지" 확인하고 누른다(아래 탭바가 가리는 자리를 눌러 다른 화면으로 가 버리는 것을 시험이 잡도록).
- `docs/ARCHITECTURE.md`에 셸 · 토큰 항목을 더했다.
