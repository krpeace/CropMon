# 결정 0074: 옛 적산 표 heat_daily · sun_daily 를 지운다 (D1-3 3단계 ②, 이슈 #211)

- 날짜: 2026-11-26
- 상태: 확정 (데이터 계약 v2.5 · 사용자가 SQL 실행 · **되돌릴 수 없음**)
- 관련: 결정 0063(새 표 · 뷰, v2.2), 결정 0072(3-①, 화면이 새 표를 읽음). 이 결정으로 D1-3 적산 계열 옮기기가 끝난다.

## 왜

같은 값이 두 곳에 있었다. 화면도 croplib-dp 도 옛 표를 쓰지 않게 되었으므로, 남겨 두면 어느 쪽이 맞는 표인지 헷갈리고 DB 용량만 차지한다.

## 순서

1. 3-① (11/25, PR #208, 결정 0072): 화면이 새 표만 읽게 하고 배포했다.
2. croplib-dp 가 옛 표 쓰기를 멈췄다(croplib-dp #135 · PR #136). 11/26 09:20 회차부터이고 그 회차는 정상으로 끝났다. croplib-dp 는 옛 표를 읽는 곳도 없다(croplib-dp 검토 채팅 → 사용자 11/26).
3. 3-②(이 결정): 확인 뒤 옛 표를 지운다.

### 지우기 전 확인 (읽기 전용 조회, 2026-11-26)

| 표                  | 줄 수   | 마지막 고친 시각 (UTC) | 관측값이 있는 마지막 날 |
| ------------------- | ------- | ---------------------- | ----------------------- |
| `heat_daily` (옛)   | 141,620 | 11/25 00:27:32         | 11/24                   |
| `sun_daily` (옛)    | 26,280  | 11/25 00:27:48         | 11/24                   |
| `heat_series_daily` | 95,642  | 11/26 00:29:35         | 11/25                   |
| `sun_series_daily`  | 44,712  | 11/26 00:30:54         | 11/25                   |

- 새 표는 그해 줄을 12-31 까지 미리 두므로 수집 회차가 돌아도 줄 수는 늘지 않는다. 11/26 회차의 증거는 고친 시각(모든 줄)과 마지막 관측일이다.
- 옛 표에 기대는 다른 표의 외래키 · 뷰 · 함수 · 예약 작업 · publication 은 0건. 표 자신에 딸린 정책(`누구나 읽기` 2) · 트리거(`*_set_updated_at` 2) · 색인 · 제약만 함께 사라진다.

## 결정

- `drop table if exists` 두 문장만 쓰고 **`cascade` 를 쓰지 않는다**: 확인 뒤에 무언가 기대게 되었다면 같이 지우지 않고 실패하는 쪽이 안전하다.
- 함수 `set_updated_at()` 은 계열 표의 트리거가 쓰므로 남긴다.
- 지난 마이그레이션 · seed · checks 파일과 지난 결정 문서는 기록이라 고치지 않는다.

## 되돌릴 수 없음 · 사라진 것

- **지우기는 되돌릴 수 없다.** `supabase/checks/d1_3b_drop_old_rollback.sql` 은 **빈 옛 표의 구조만** 다시 만든다. 줄은 살리지 못한다.
- 옛 표에 지난 해 줄은 없었다(#207 비교). 같은 계열의 값은 새 표와 차이 0이었으므로 그 값은 사라지지 않는다.
- 사라진 것은 옛 `heat_daily` 의 **포도 줄**(작물 키 · 10℃ · 1월 1일 누적)뿐이다. 새 표에 같은 계열이 없고 화면이 쓰지 않는 줄이다.

## 시험

- 계약 시험: v2.5 마이그레이션은 두 문장뿐이고 `cascade` 가 없다 · "만든 표 − 지운 표 = 계약서 표" · 확인 SQL 은 읽기만 · 되돌리기 SQL 은 구조 · 권한까지 만들고 줄을 넣지 않는다.
- 옛 표 키 검사(v1.4)에 있던 값 열 · 평년 기간 확인은 계열 표 검사로 옮겼다.
- `old-tables-gone.test.ts`: `src` 에 옛 표 읽기 0곳(그대로).
- e2e 가짜 Supabase 는 옛 표가 없고, 없는 표는 실제 PostgREST 와 같은 404(`PGRST205`)로 답한다. 화면 기대값은 바뀌지 않았다.
