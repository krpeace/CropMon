# 결정 0043: 온도·햇빛 지역 비교에 지금 보는 지점 함께 표시

- 날짜: 2026-11-15
- 상태: 채택
- 관련 이슈: #79

## 배경

온도(`/temperature`)와 햇빛(`/sunlight`) 화면의 지역 비교 카드는 대표 10곳(`isRepresentative`)만 보여 주고 있었다. 사용자가 대표 10곳 밖의 지점(예: 서울 108, 강릉 105)을 보고 있을 때도 자기 지역과 대표 10곳을 바로 나란히 비교할 수 있어야 한다.

## 결정

1. **대표 밖 지점은 1곳만 추가로 읽어 맨 위에 고정**: `services/growth-latest.ts`의 `readHeatLatest`·`readSunLatest`에 선택 인자 `stationIds?: readonly number[]`를 둔다. 대표 밖 지점을 볼 때 `temperature.ts`·`sunlight.ts`의 `readCompare`가 대표 10곳 읽기와 선택 지점 1곳 읽기를 `Promise.all`로 함께 호출해 11줄 목록(맨 위 선택 지점 + 대표 10곳)을 만든다.
2. **종합 화면과 30분 캐시는 그대로**: 종합 화면(`shell/board.ts`의 `loadGrowth`, `home.ts`)은 `stationIds`를 넘기지 않으므로 10곳 기준 읽기와 30분 캐시, 전국 표 행 구성이 전혀 바뀌지 않는다.
3. **한 곳 읽기 실패·미관측 격리**: 선택 지점 1곳 읽기만 실패하거나 값이 없으면(`sun_daily` 미관측 지점 포함) 대표 10곳은 그대로 보이고 선택 지점 줄만 `"자료 없음"`(막대 없음)으로 표시한다. `detail-cache.ts` 폴백 경로의 `buildHeatCompare`·`buildSunCompare`도 같은 규칙을 쓴다.
4. **시각 구분과 기준일 안내**: 맨 위 선택 지점 줄 아래에 얇은 구분선을 둔다(`CompareCard.tsx`, `SunCards.tsx`). 상단 기준일 안내문(`compareNote`)은 대표 10곳 기준으로만 계산해 안내가 흔들리지 않게 하고, 맨 위 선택 지점 줄은 대표 기준일과 다를 때만 자기 줄에 `(M/D)`를 표시한다(`extraCompareDateTag`).

## 대안과 선택 이유

- **97곳 전체를 매번 읽는 방식**: 지역 비교는 최대 11곳만 필요하므로 매번 97곳을 읽으면 egress가 불필요하게 커진다. 선택 지점 1곳만 추가로 읽는 쪽이 요청 크기를 최소화한다.
- **`compareNote`에 선택 지점을 섞는 방식**: 대표 10곳 모두 어제 값인데 선택 지점 1곳만 이틀 전 값일 때 대표 10곳 전체 안내문이 바뀌어 혼동을 줄 수 있으므로, 대표 10곳 기준 안내문은 유지하고 선택 지점 줄에만 개별 날짜 표식을 둔다.
