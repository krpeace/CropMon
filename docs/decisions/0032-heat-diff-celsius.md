# 0032: 적산온도 "며칠 빠름"을 "평년 대비 ℃"로 바꿔 보여 주기

- 날짜: 2026-10-30
- 상태: 확정

## 배경

- `lead_days`(평년보다 며칠 빠른가)는 "올해 오늘 누적에 평년 누적이 처음 닿는 날 − 오늘", 곧 누적 곡선의 **수평 거리**다.
- 앞선 일수 ≈ 올해 초과분(℃) ÷ 그 시기 평년 하루 적산온도. 가을에는 분모가 3~8로 줄어 작은 초과분도 수십 일이 되고, 초과분이 남은 평년 값(10/30~12/31)보다 크면 "한 해 치 넘음"이 된다.
- 모의 계산: 1~10월 평균 +1℃ → 5월 말에는 6~9일 빠름, 10월 말에는 대부분 "한 해 치 넘음". 태백은 연평균 +0.15℃만 높아도 "한 해 치 넘음".
- 계산(croplib-dp `core/heat_sun.py`)은 맞다. 표시 방식만 바꾼다.

## 결정

1. 기본 정보는 **평년 대비 적산온도 차이**로 보여 준다: `+180℃`, `-42℃`, `0℃`. 차이 = `round(gdd_cum) − round(gdd_normal_cum)` (같은 날, 마지막 관측일). `domain/heat.ts` 의 `heatDiff`.
2. 단위는 사이트 전체에서 **"℃"만** 쓴다 ("℃·일" 모두 "℃").
3. "평년과 비슷" 같은 묶음 없이 **항상 숫자로** 보여 준다 (작은 차이도 `+5℃`). 큰 글씨는 `평년보다 +180℃`, 같으면 `평년과 같아요`.
4. 온도 화면 **단계 카드**에 도달일 비교 꼬리표(`5일 빠름` / `6일 지연` / `평년과 같음`)를 붙인다. 일수 = 평년 도달일 − 올해 도달일. 종합표에는 넣지 않는다. 기호(±, ▲▼) 대신 글자를 쓰는 이유: 위쪽 `+252℃`는 "+ = 앞섬"인데 날짜 차는 빠를수록 날짜가 앞서므로 기호로 쓰면 `−5일`이 빠름이 되어 부호 뜻이 거꾸로 되기 때문이다.
5. 작물 공통 단계값을 `{500, 1000, 1500, 2000, 2500, 3000}` 으로 늘린다 (마이그레이션 `20261030000000_common_gdd_stages.sql`, 시드 파일도 같은 값).
6. 사과·배추 단계값과 작물별 누적 시작일은 11/06 이후 별도 이슈.
7. DB `lead_days` 열은 계약에 그대로 두고 화면에서만 쓰지 않는다 (croplib-dp 변경 없음).

## 화면

- 종합 카드·전국 표: `+180℃`. 휴대폰 온도 탭 막대: 가운데 0, 한쪽 끝 = 300℃ (1℃ = 1/6 %), 최소 1.5%, 최대 50%.
- 온도 화면 지역 비교: 값과 막대를 ℃ 차이로. 최소 눈금은 낮음 100℃ · 높음 200℃(이전 4일·8일과 같은 1:2), 넘으면 넓힌다. 카드 제목은 "지역 비교 · 평년 대비 적산온도" (음수도 있으므로 "앞섰나"는 쓰지 않음).
- 생육 속도 카드 작은 설명에서 "쌓인 따뜻함" 삭제.

## 정리한 것

`leadVerdict`, `leadShort`(domain·services), "평년 한 해 치를 넘었어요" 문구, `annualNormal`(12/31 읽기)을 지웠다. "쌓인 햇빛"(햇빛 화면)은 이번에 건드리지 않았다.
