# 0033: 모바일 앱은 Capacitor로, 배포된 웹 주소를 불러오는 방식

- 날짜: 2026-11-01
- 상태: 확정

## 배경

- CropMon을 Android(Play 스토어)·iOS(App Store) 앱으로 출시한다 (상위 이슈 #63).
- 웹은 지금 구조(서버 렌더링 + `use cache`, 서버 캐시)로 11/06에 공개한다. 앱 때문에 웹 구조를 바꾸지 않는다.
- 앱에서만 필요한 것은 푸시 알림, 백그라운드 지오펜스(밭 방문 기록), 로컬 알림이다. 웹 브라우저로는 안정적으로 할 수 없다.

## 결정

1. **Capacitor** 로 앱을 만들고, 앱은 **배포된 웹 주소(farmos-cropmon.vercel.app)를 불러온다.** 화면은 웹 그대로다.
2. 네이티브 기능은 **푸시 알림(FCM, iOS는 FCM → APNs) · 지오펜스 · 로컬 알림** 세 가지만 붙인다.
3. 지금의 4층 구조(app → services → domain, services → infra)를 앞으로도 Next.js에 묶이지 않게 지킨다 (아래 원칙).

## 버린 안

- **TWA(웹을 감싼 Android 앱)**: iOS를 만들 수 없고, 백그라운드 위치(지오펜스)도 쓸 수 없다.
- **정적 내보내기로 전환**(브라우저가 DB를 직접 읽기): 서버 렌더링·`use cache` 로 만든 서버 캐시 구조를 잃고, 읽기 권한 설계도 다시 해야 한다. 11/06 공개 일정에도 부담이다.

## 원칙

1. `src/services`, `src/infra` 는 Next.js(`next`, `next/*`)를 불러오지 않는다. 테스트 파일도 같다. ESLint가 자동으로 막는다 (`npm run lint`).
2. Next.js 서버 기능(`next/cache`, `next/headers`, `use cache` 등)은 `src/app` 에만 둔다.
3. 새 판정 규칙은 `src/domain` 의 순수 함수로 둔다. 앱·알림·서버 어느 쪽에서도 같은 규칙을 다시 쓸 수 있게 하기 위해서다.

## 범위

- 이번 변경은 원칙과 자동 검사만 만든다. 화면·기능 코드는 바꾸지 않는다. 현재 services·infra 에는 Next.js 코드가 없어 기존 코드는 그대로 통과한다.

## 아직 정하지 않은 것

#63 "확인 필요 (결정 전)" 항목과 이어진다. 정해지면 이 결정을 고치지 않고 새 결정 문서로 남긴다.

- **앱 소스 위치**: CropMon 저장소 안 별도 폴더 vs 새 저장소(예: krpeace/cropmon-app)
- **정식 도메인**: 앱이 배포 주소에 묶이므로 앱 출시 전에 정식 도메인을 쓸지 정해야 한다
- **위치정보법 확인**: 위치기반서비스사업 신고 대상 여부, 신고 주체(개인 프로젝트), 위치정보 이용 동의·약관
