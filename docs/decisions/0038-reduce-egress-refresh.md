# 0038. 켜 둔 화면의 반복 읽기 줄이기와 30분 캐시

- 날짜: 2026-11-08
- 상태: 확정 (이슈 #80)

## 왜

11/3~11/6 Supabase egress가 매일 약 490MB(무료 한도 5GB 중 2.5GB 소진)에 달했다. 조사 결과, 첫 화면의 5초 주기 자동 순환(`AutoRotate`)이 24시간 내내 `router.replace`를 실행했고, 판정 표 캐시의 stale(60초) 주기마다 Supabase DB 재검증이 발생한 것이 원인이었다 (croplib-dp 이슈 #66).

농업기술센터 지도사 사무실 모니터나 관제 화면처럼 첫 화면을 24시간 계속 켜 두는 사용을 기본 전제로 하여, 네트워크 요청과 DB 조회를 최소화하도록 구조를 개선한다.

## 결정

- **판정 표 캐시(board.ts cacheLife) 30분 조정:**
  - `loadBoard`(`getStationBoard`)와 `loadGrowth`(`getHomeGrowth`) 둘 다 `cacheLife({ stale: 1800, revalidate: 1800, expire: 86400 })` 적용.
  - 공공데이터 수집은 하루 2회(02시, 17시), 적산온도·일사 수집은 하루 1회(09:20)이므로 30분 캐시로도 수집 완료 시각(02:15, 17:15) 기준 최대 30분 이내에 최신 자료가 자연스럽게 반영되며 화면 지연이 없다.
  - **DB 읽기 상한:** Next.js 기본 `use cache`는 서버 인스턴스(프로세스)별 인메모리 LRU 캐시이므로, **서버 인스턴스 1개당 하루 최대 48회, 약 14~18MB (평균 약 17MB)**로 상한이 제한된다 (24시간 ÷ 30분 = 48회. 운영 97곳 확대 실측 기준 1회 캐시 채움 약 0.29~0.38MB × 48회 ≈ 13.9~18.4MB). 인스턴스가 2~3개 수준인 현 규모에서는 월 1~1.5GB로 무료 한도(5GB) 내에서 안전하며, 훗날 방문자가 급증해 인스턴스가 크게 늘면 `'use cache: remote'`나 엣지 CDN 캐시(s-maxage/ISR)로 전환한다.
- **자동 순환의 클라이언트 전환 (5초 순환 시 서버 요청 0회):**
  - 첫 화면은 대표 10곳의 판정 표와 생육 자료를 처음 한 번에 모두 받는다.
  - 10개 대표 지점의 뷰 데이터를 미리 구성해 클라이언트 컴포넌트(`HomeBoardClient`)로 넘기고, 클라이언트 상태(`useState`)로 5초마다 다음 지점으로 전환한다.
  - `router.replace` 대신 `window.history.replaceState`를 사용하여 서버 요청(RSC 요청) 없이 브라우저 주소창(`?station=...`)만 부드럽게 갱신한다. 5초 순환 시 네트워크 요청은 0회다.
  - 사용자가 전국 표의 행이나 헤더를 직접 누르는 동작(클릭)은 기존과 완전히 동일하게 `<Link>`로 이동하여 동작을 유지한다.
- **탭 가시성 연동 (document.hidden):**
  - `document.visibilityState === "hidden"`일 때는 5초 자동 순환 타이머와 30분 자료 갱신을 즉시 일시 정지한다.
  - 탭이 다시 `visible`이 되면 자동 순환을 재개하며, 마지막 갱신으로부터 30분이 경과했으면 즉시 1회 백그라운드 갱신(`router.refresh()`)을 실행한다.
- **켜 둔 화면의 자료 갱신 주기:**
  - 포그라운드 활성 탭은 30분에 한 번만 `router.refresh()`를 호출하여 서버 최신 자료를 백그라운드에서 다시 받아온다.
