## 배경

L2(결정 0061)가 배관(`/auth/login` · `/auth/callback` · `/auth/signout` · 로그인 필요 주소 · 스위치 `MEMBERS_ENABLED`)을 깔았다. 이번에는 **사람이 보는 쪽**을 붙인다: 어느 화면에서든 "로그인" → 시트 → 공급자 → **보던 화면으로 돌아옴** + 알림. **스위치를 끄면(운영 지금 상태) 지금 알파와 똑같다**(기존 e2e가 끔 서버에서 그대로 통과하고, 끔 전용 e2e가 더 못 박는다).

## 결정

### 1. 헤더가 "스위치 켬/끔 · 로그인함"을 아는 법 — 표시 쿠키 `cm_m`

공개 화면은 정적 · `use cache`(결정 0038)라서 서버가 이것을 HTML에 못 싣는다. **프록시가 심는 작은 쿠키 + 첫 그리기 전에 도는 작은 스크립트 + CSS로 하나만 보이기.** 공개 화면의 빌드 결과(정적/부분 정적)는 이 PR 앞뒤로 **같다**(`next build` 경로 표 비교, PR 본문).

- **값**(`src/domain/members-state.ts`, 개인 값 없음): `a`(켬 · 비로그인) · `i`(켬 · 로그인함), 네이버가 켜져 있으면 뒤에 `n`(`an` · `in`). **쿠키가 없으면 끔 = 지금 알파.** 모르는 값(`zzz` · `A` · `ai`…)도 끔으로 읽는다.
- 자바스크립트가 읽어야 하므로 **HttpOnly 아님**, 경로 `/`, `SameSite=Lax`, https일 때만 `Secure`, **만료 없음**(브라우저를 닫으면 사라지고 다음 방문 때 프록시가 다시 심는다).
- **프록시(`src/proxy.ts`)가 유일한 쓴이**다. 매 요청에서 "있어야 할 값"을 정해(`wantedMembersCookie`) **지금 쿠키와 다를 때만** 쓴다(`membersCookieAction` — 같으면 아무것도 안 함).
  - **끔**: 요청에 `cm_m`이 **있을 때만** 지운다. 없으면 아무것도 안 한다 → 쿠키 없는 방문자는 지금 알파와 같다(**새 쿠키 0 · Supabase 호출 0**, e2e `members-off`가 `Set-Cookie` 없음을 봄). **켰다가 끈 뒤**에도 첫 요청에서 지워진다.
  - **켬**: 로그인 쿠키(`sb-…-auth-token`)가 없으면 `a`(Supabase 호출 없음). 있으면 지금 하던 세션 확인(`updateProxySession`)의 결과로 `i` 또는 `a` → **Supabase 호출이 늘지 않는다.** 만료돼 로그인이 풀렸으면 `i`를 `a`로 고친다.
  - **콜백 · 로그아웃은 쿠키를 만지지 않는다.** 로그인 성공 → 콜백이 `next`로 돌려보냄 → 그 요청을 프록시가 보고 `i`로 바꾼다. 로그아웃(303) → 프록시가 `a`로 바꾼다. 폐지 지점 돌려보내기(`st=116`) 응답은 만지지 않는다(돌아간 요청에서 심음).
  - 프록시 matcher는 정적 파일(`/_next/static` · `/_next/image` · 아이콘 · `/brand/`)과 `/api/`를 이미 뺀다 → 쿠키는 **문서 · 화면 이동(RSC) 요청**에서만 쓰인다.
- **첫 화면 깜박임 없음**: `layout.tsx` `<head>`의 `MEMBERS_SCRIPT`(`buildMembersScript()`, `THEME_SCRIPT`와 같은 방식)가 쿠키를 읽어 `<html data-members="anon|in" data-naver="1">`을 단다. 쿠키가 없거나 모르는 값이면 **아무 속성도 안 단다**(알파 모양). `try`로 감싸 쿠키를 못 읽어도 화면을 막지 않는다(시험이 못 박음). 응답의 `Set-Cookie`는 문서 응답과 같이 와서 스크립트가 도는 시점에 이미 읽힌다.
- 헤더 오른쪽 자리(`shell/LoginSlot.tsx`)는 **세 모양을 모두 HTML에 넣고** `globals.css`(층 밖 규칙)가 `data-members`로 **하나만 보이게** 한다: ① 속성 없음 = 알파("로그인"+데스크톱 "곧 열려요" 배지) ② `anon` = "로그인" ③ `in` = 프로필 아이콘(`aria-label="내 계정"`). 숨긴 모양은 **`display:none`** 이라 화면 읽기에서도 빠진다(`opacity` · `visibility`로 숨기지 않음) — e2e가 접근성 이름으로 "로그인" 단추가 정확히 하나임을 본다. 데스크톱 헤더의 다크 모드 단추는 `in`이면 숨긴다(7절).
- 시트 내용(안내 창 ↔ 로그인 시트)은 열 때 `useMembersState()`가 `<html>` 속성을 읽어 정한다. 서버에서 그릴 때는 항상 끔이라 서버 HTML과 어긋나지 않는다. 뒤로 가기(bfcache)로 되살아난 화면은 `pageshow`에서 쿠키를 다시 읽고 "로그인 중" 표시를 지운다.
- **한계**: 쿠키를 위조해도(`i`) 헤더 모양만 바뀐다. 개인 값 · 데이터는 없고 진짜 막이는 서버 · RLS다. 끔이면 위조 쿠키는 지워지고 무시된다.
- **쿠키 안내 문구**: 켬일 때 방문자 모두가 기능 쿠키 1개를 받는다. 이번에는 이 결정과 `docs/SOCIAL_LOGIN.md`에만 적고 `/privacy`는 건드리지 않았다(검토 채팅 결정 — 방침 문구는 약관 채팅이 정리).
- **확인할 위험(병합 뒤 Vercel 미리보기)**: 로컬은 `next start`라서 **Vercel이 정적 응답에도 프록시가 단 `Set-Cookie`를 붙이는지**는 못 본다. `docs/SOCIAL_LOGIN.md` 8장 확인 목록에 넣었다. 안 붙으면 이 설계를 고쳐 이슈에 알린다.

**다른 방법과 비교**

| 방법                             | 장점                                                                     | 단점                                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 표시 쿠키(채택)                  | 화면은 정적 그대로 · 추가 요청 0 · 깜박임 없음 · Supabase 추가 호출 없음 | 켬일 때 방문자 모두에게 작은 기능 쿠키 1개(끔일 때는 0)                                                                     |

### 2. 로그인 성공 표시 `login=ok`

콜백이 성공하면 돌아갈 주소에 **`login=ok`** 를 붙인다(`withLoginNotice(next, "ok")`, 타입 `LoginNotice = "ok" | "cancelled" | "failed"`). 화면이 "로그인했어요" 알림을 한 번 띄우고 **주소에서 `login`만** 지운다. 결정 0061 3절의 "실패 · 취소만 표시"를 갱신했다.

### 3. 알림(토스트) — 공통 부품

`src/app/_components/ui/Toast.tsx`의 `showToast("문장")` + `<ToastHost />`(layout에 한 번). 로그인이 처음 쓰고 앞으로 "탈퇴했어요" · "기록을 지웠어요"도 같은 부품을 쓴다. `role="status"` · `aria-live="polite"`인 **자리는 항상 그려 두고** 안에 문장만 넣고 뺀다(자리가 새로 생기며 들어온 문장이 안 읽히는 기기가 있어서). 4초 뒤 사라진다(`TOAST_MS`), 한 번에 하나, 탭바 · 아래 안전 영역 위(`--tabbar-h` + `--tabbar-safe-bottom` + 12px, 데스크톱은 아래 24px).

`LoginNotice`(`shell/LoginNotice.tsx`, layout의 `<Suspense>` 안)가 주소의 `login=ok|failed|cancelled`를 읽는다: ok → "로그인했어요", failed → "로그인을 마치지 못했어요. 잠시 뒤 다시 해 주세요", **cancelled → 아무 말 없음**. 읽은 뒤 `history.replaceState`로 `login`만 지운다(나머지 검색어 · `#`는 그대로, 새로고침 · 공유 주소에서 다시 안 뜸). `login=1`(시트 열기)은 알림이 아니다.

### 4. 로그인 시트

- **휴대폰(폭 1024 미만)**: 아래에서 올라오는 시트 — 결정 0050의 `BottomSheet`를 그대로 쓴다(× 대신 머리의 "닫기", 덮개를 누르면 닫힘, 끌기 손잡이 있음). **데스크톱**: 가운데 창(폭 520 = `max-w-130`, **끌기 손잡이 없음**), 제목 줄은 안에서 스크롤해도 위에 붙고(sticky) × 가 잘리지 않는다. 바깥 · Esc로 닫히고 포커스를 연 단추로 돌려준다.
- 버튼 셋 **카카오 · 네이버 · Google** 순서(`LOGIN_PROVIDERS`), 높이 52(`fh-52` — 글씨가 커져도 안 잘림), 모서리 12, 같은 너비, 문구는 시안의 "카카오 로그인" · "네이버 로그인" · "Google 계정으로 로그인". **`<a href="/auth/login?provider=…&next=…">`** (`<Link>`의 미리 불러오기가 로그인 시작을 먼저 보내지 않게, 결정 0061).
- `next`: 지금 보던 주소(경로 + 검색어, `st` · `crop` 선택 포함, `login` · `next`는 뺌). 시트가 `?login=1&next=…`로 열렸으면 그 `next`. 화면에서도 `validateRedirectPath`를 지난다(`loginSheetNext` · `loginRequestNext` · `loginButtonHref`, 서버도 두 번 검사).
- **로그인 중**: 누른 버튼에 진행 표시(`aria-busy`), 나머지는 흐리게(`aria-disabled` · `pointer-events-none` · `tabindex=-1`) · 눌러도 이동 안 함(두 번 누름 막기). bfcache로 되살아나면 진행 표시를 지운다.
- 시트가 열린 동안 휴대폰 맥락 바의 "로그인"은 숨는다(`invisible`, 자리 유지).
- **`/?login=1&next=…`로 오면 시트를 연다**(L2의 로그인 필요 주소 보내기). 닫으면 `login` · `next`를 주소에서 지운다(`history.replaceState`, 새로고침해도 다시 안 열림). **스위치 끔이면** 같은 주소가 와도 로그인 시트가 아니라 **지금 안내 창**("로그인은 2027년 1월 1일부터 열려요")이 뜬다 — 그 창의 DOM은 예전과 똑같다.
- 시트 안내문은 시안 문구 그대로("로그인하면 내 밭 단위로 봐요" · "아이디·비밀번호 가입은 없어요…"). **약관 안내 한 줄은 시안에 문구가 없어** "로그인하기 전에 이용약관과 개인정보처리방침을 확인해 주세요." (`/terms` · `/privacy` 링크)로 썼다 — 동의 문구는 L4(동의 화면)가 정한다.

### 5. 네이버 = 시험 과제 (기본 "준비 중")

- 서버 변수 **`NAVER_LOGIN_ENABLED`**(정확히 `"true"`일 때만, `naverLoginEnabled(env)`). 켜는 일은 **다시 빌드 없이** 서버 변수만 바꾸고 다시 배포한다(위 `cm_m`의 `n`으로 화면에 전달).
- **서버에서도 막는다**: 꺼져 있으면 `/auth/login?provider=custom:naver`는 **모르는 공급자와 같이 400**(`isAllowedProvider(value, naverEnabled)` — 공급자 판단은 서버의 이 한 곳). 화면의 "준비 중"이 보이는 모양만 바꾸는 것이 아니라 실제로 막는다(공급자를 설정하지 않은 채 열려 있으면 실패 흐름만 생겨서). 단위 시험 + e2e(3100 · 3101에서 404/400, 3102에서 302)로 못 박았다. 결정 0061 3절의 "목록에는 넣어 둠"을 갱신했다.
- "준비 중" 버튼은 같은 자리 · 같은 크기, 흐리게, `disabled`, 링크 아님.
- 네이버가 실제로 되는지(사용자 지정 공급자 · 응답 모양 중계 필요 여부)는 **이 PR 범위 밖**이고 설정 순서와 알려진 함정을 `SOCIAL_LOGIN.md`에 적었다. **12/15까지 안 되면 1월**(순서표 #144).

### 6. 이 PR이 정한 것: e2e 서버 셋

같은 빌드를 서버 변수만 달리해 띄운다: **3100 끔**(알파) · **3101 켬** · **3102 켬 + 네이버**. 가짜 로그인 흉내(전역 값)가 섞이지 않게 프로젝트가 차례로 돈다(desktop · mobile → members-on → members-on-mobile → members-naver).

### 7. 내 계정 시트 틀

로그인했으면 "로그인" 자리가 **프로필 아이콘**이 되고 누르면 내 계정 시트(휴대폰은 아래 시트, 데스크톱은 가운데 창). **틀만**: 시안 v0.4.6 사용자 메뉴 순서 — 알림 · 농장 설정 · 작물 설정 · 화면 구성 · 글씨 크기 · 다크 모드 / 회원 정보 · 알림 설정 / 로그아웃. 있는 화면(`/layout` · `/font-size` · 다크 모드)만 연결하고 나머지는 회색 "준비 중"(aria-disabled). 로그아웃은 `POST /auth/signout?next=<지금 주소>` 폼. 회원 정보 · 회원탈퇴는 L6.

**다크 모드**: 시안("비회원은 지금 자리, 회원은 사용자 메뉴 안")대로 회원이면 데스크톱 헤더의 해/달 단추가 사라지고(`data-members-hide="in"`) 시트 안 줄(`ThemeRow`, 더보기와 같은 부품)에서 바꾼다. 비회원(끔 · 켬 모두)은 지금 자리 그대로.

### 9. 뒤따라 확인 (병합 조건 아님)

- **실제 공급자로 로그인**(결정 0061 6절): 가짜 서버는 HS256 흉내라 실제 서명 방식(ES256 · 공개 열쇠)은 이 PR로 증명되지 않는다. 사용자가 카카오 · 구글 개발자 앱 + Supabase 공급자 설정을 하면 **Vercel 미리보기 환경에만 `MEMBERS_ENABLED=true`** 를 넣어 로그인 · 실패 · 취소를 해 보고 이슈에 결과를 남긴다. 미리보기도 운영 DB를 쓰므로 시험 계정은 O3에서 지운다.
- 미리보기에서 `cm_m` 확인 4가지(`docs/SOCIAL_LOGIN.md` 8장).
- 카카오 공식 심볼 받아 넣기(위) — **O3 전 필수**.
- 휴대폰 실기(홈 막대 · 키보드는 시험으로 못 봄)는 O3. 스위치가 꺼져 있어 운영에서는 볼 것이 없다.

## 시험

- 단위: `members-state`(쿠키 값 읽기 · 만들기 · 다를 때만 쓰기 · 끔에서 있을 때만 지우기 · 첫 그리기 스크립트(모르는 값 · 오류에도 안 던짐)), `login-sheet`(`next` 만들기 · `login=1&next` · 위험한 값 · 버튼 주소 · 검색어 지우기 · 버튼 순서), `toast`(표시 읽기 · 문구), `auth`(`login=ok` · `isAllowedProvider` 네이버 스위치), `members-switch`(네이버), `proxy`(끔 · 켬 · 쿠키 없음 호출 0 · 로그인함 · 만료 · 켰다가 끔 · 네이버 `n` · 보안 속성), 경로 처리기(콜백 `login=ok` · 네이버 400 · 302).
- e2e **끔**(3100): 쿠키 없는 방문 `Set-Cookie` 없음, 헤더 알파 그대로, "곧 열려요" 안내 창, `login=1`이 있어도 지금 안내, 남은 `cm_m` 지워짐, 네이버 404.
- e2e **켬**(3101, `members-sheet`): 쿠키 · 헤더 · 접근성 이름 하나, 시트 열기/닫기(보던 화면 · 주소 그대로), 버튼 순서 · `href` · 같은 크기, 네이버 준비 중, 진행 표시 · 두 번 누름 막기, 성공/취소/실패 알림 · 주소 정리 · 새로고침, 헤더 프로필 · 다크 모드 단추 사라짐, `/farm/settings` → 시트 → 로그인 뒤 그 주소, 내 계정 시트 · 제목 줄 고정 · 로그아웃 → "로그인".
- e2e **켬 휴대폰**(`login-sheet-mobile`, 390): 아래 시트 · 덮개 · 탭 대상, **390×370에서 네이버 버튼이 탭바에 안 가림**, 글씨 150% 안 넘침, 알림이 탭바 위, 내 계정 시트.
- e2e **네이버 켬**(3102): `cm_m=an`, 302, 링크가 되고 로그인되어 돌아옴.
