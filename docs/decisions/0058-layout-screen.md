# 결정 0058: 화면 구성 화면 `/layout` — 메뉴 켜고 끄기 · 순서 바꾸기 (바로 적용) (이슈 #176, S5)

- 날짜: 2026-11-19
- 상태: 확정
- 관련 이슈: #176 (순서표 #144의 S5). 결정 0046(메뉴 ID · 저장 규칙 `resolveMenus`)을 이어받는다.
- 기준: 시안 v0.4.3 "탭 순서 — 화면 구성"(코드로 확인), 디자인 규칙 v0.4.6 12절 "화면 구성".
- **끌기 시작 방식은 0060으로 바뀜**(휴대폰은 길게 눌러야 시작, 손잡이 `touch-action: none` 없앰). 아래 4절의 "손잡이로만 잡으며 · 포인터를 대는 순간 시작" 설명은 그 앞의 것이다.

## 배경

셸 뼈대(#145, 결정 0046)는 하단 탭 · 더보기 · 데스크톱 메뉴 줄을 설정값(메뉴 ID 순서 + 끈 메뉴)에서 그리지만, 그 값을 바꾸는 화면이 없어서 아무도 메뉴를 끄거나 순서를 바꿀 수 없었다. 이 화면만 만든다. **저장 규칙(`SavedMenus` v1, `resolveMenus`)은 바꾸지 않는다.**

## 결정

### 1. 주소 `/layout` — 2단계 화면

`EXTRA_SCREENS`에 `"/layout": { kind: "title", title: "화면 구성", back: true }`(휴대폰 맥락 바에 뒤로 화살표 + 제목). 더보기의 "화면 구성" 줄(준비 중이던 것)과 맨 아래 "숨긴 메뉴 n개 · 화면 구성에서 다시 켜기" 줄(`aria-disabled` 버튼이던 것)이 `withSelection("/layout", selection)` 링크가 된다(고른 작물 · 지역을 이어 감). 데스크톱은 `/font-size`처럼 주소로만 열린다(들어가는 길은 로그인 이슈의 "내 계정"). 데스크톱에서는 본문 폭을 720px(`max-w-180`, 약관 화면과 같음)로 제한한다(`/font-size`는 폭 제한이 없다 — 따로 맞출 일).

### 2. 화면 모양 (시안대로, 시안과 다른 점은 아래 3)

위에서 아래로: 안내 문장 → **"하단 탭 미리 보기"**(켠 메뉴 위에서 4개 + 더보기, 실제 탭바와 같은 아이콘 · 이름, 목록을 바꾸면 바로 바뀜) → **서비스 메뉴 10줄**(설정값 순서 그대로, **끈 메뉴도 목록에 남음** — 다시 켤 수 있어야 하므로) → **"기본값"** 버튼 + 저장 위치 안내 한 줄("이 기기에 저장돼요. 로그인하면 계정에 저장돼요." — 시안 문구 그대로, 회원 계정 저장은 L5에서 이 줄과 저장만 바꾼다).

- 줄마다: 아이콘(24) · 이름 · (탭이면) "탭 1"~"탭 4" 배지 · 위/아래 단추 · 스위치 · 손잡이(오른쪽 끝, 44×44). **종합**은 스위치 대신 회색 "항상 사용" 배지(끌 수 없고 순서만 바꾼다). 끈 줄은 이름 · 아이콘을 흐리게(0.4). 줄 높이 `fh-56`(44 이상).
- **구분선**: 켠 메뉴 **넷째 줄 바로 아래** "↑ 여기까지 하단 탭 · 아래는 더보기"(시안 문구). 켠 메뉴가 4개 이하이면 구분선 없음(켠 것 모두가 탭). 끈 메뉴는 탭 번호 · 구분선 계산에서 빠진다(물을 끄면 관측이 탭 4로 올라옴).
- 종합을 옮기면 탭 번호도 따라간다(`resolveMenus`가 켠 메뉴를 저장 순서대로 위에서 4개 쓰므로. 더보기 목록에서는 종합이 늘 맨 위). 데스크톱 메뉴 줄은 순서를 바꾸지 않고 늘 기본 순서이며 끈 메뉴만 숨긴다(셸 설계 4-3, 지금 `resolveMenus` 그대로).
- **저장 버튼 없음, 바로 적용**(글씨 크기 화면과 같음). 글씨 크기(`--fz`)를 따르고, 줄 안 요소(아이콘 · 이름 · 배지 · 단추 · 스위치 · 손잡이)가 150%에서도 서로 겹치지 않는다(시험이 상자 겹침을 잰다).

### 3. 시안과 다른 점 (다음 디자인 의뢰 때 설계 채팅에 알림)

1. **위/아래(▲▼) 단추를 줄마다 더했다** — 끌기를 못 하는 사람(화면 읽기 · 키보드 · 손이 불편한 사용자)도 순서를 바꿀 수 있어야 해서다. 맨 위 줄의 ▲ · 맨 아래 줄의 ▼는 흐리게 + `aria-disabled`. 눌리는 곳은 높이 44 × 폭 36. 안내 문장에도 "▲ ▼ 를 눌러"를 덧붙였다.
2. **"탭 n" 배지를 이름 옆이 아니라 이름 아래 줄에** 둔다 — 390 폭에서 ▲▼가 들어가 한 줄에 다 못 담아서다. (시안은 이름 옆.) 130% 이상에서도 같은 모양이라 `big:` 변형이 필요하지 않았다.
3. 스위치 켜짐 색은 시안의 초록(`rgb(52 199 89)`)이 아니라 이 화면 앞에 있는 다른 스위치(더보기 다크 모드 · 휴대폰 설정 따르기)와 같은 `bg-brand`다.
4. 끄는 동안 구분선은 숨긴다(줄이 구분선을 넘어 움직이면 헷갈리므로).

### 4. 순서 바꾸기

- **계산은 `src/domain/menus-layout.ts`의 순수 함수**: 목록 줄 · 탭 번호 · 구분선 위치, 옮기기(위 · 아래 · 맨 위 · 맨 아래 · 임의 자리, 종합도 옮겨짐, 끝에서 더 안 감), 끄기/켜기(종합은 못 끔), 기본값, 끌어서 놓을 자리(`nearestIndex`), 알림 문구. 단위 시험에 저장 → 읽기 **왕복**(`parseSavedMenus` → `resolveMenus`가 `layoutModel`과 어긋나지 않음)이 있다.
- **끌기는 의존성 없이 직접 만들었다**(`shell/layout-drag.ts`). 줄이 10개 고정이고 손잡이로만 잡으며 위치 계산이 순수 함수여서 `@dnd-kit` 같은 라이브러리(패키지 3개 + 하위 의존성, 번들 수십 KB)가 필요하지 않았고, 약관 화면 때처럼 공급망 표면을 넓히지 않으려는 판단이다. 포인터 이벤트(마우스 · 터치 · 펜 공통), 손잡이에 `touch-action: none`(끄는 동안 화면이 같이 스크롤되지 않음), **포인터 캡처**(손가락이 줄 밖 · 화면 위아래 끝으로 나가도 끌기가 안 끊김), 끄는 줄은 손가락을 따라가고 사이의 줄은 한 칸씩 비켜 놓을 자리가 보이며(연두 바탕 · 그림자), `pointercancel` · 캡처 잃음 · Esc는 취소(순서 그대로). 줄이 10개라 자동 스크롤은 두지 않았다 — 150%에서 목록이 한 화면을 넘으면 맨 아래 줄을 한 번에 맨 위로 끌 수 없으므로 그때는 ▲ 단추(또는 손잡이 Home)를 쓴다(시험이 ▲ 아홉 번으로 맨 위까지 올라가는 것을 확인).
- **끌기 없는 길 두 가지**: 손잡이 키보드(위/아래 화살표 한 칸, Home 맨 위, End 맨 아래 — 옮긴 뒤에도 같은 손잡이에 초점이 남음)와 줄마다 ▲▼ 단추(누른 뒤에도 같은 단추에 초점). 바꾼 뒤 `aria-live`(`role="status"`)로 짧은 알림: "물을 2번째로 옮겼어요" / "물을 껐어요" / "물을 켰어요" / "기본값으로 되돌렸어요". 받침에 따라 "을/를"을 고른다.

### 5. 저장 — 기존 설정값 형식 그대로, 쓰기는 한곳

- 쓰는 값은 기존 `SavedMenus` `{ v: 1, order, off }` 그대로(판 번호를 올리지 않는다). `order`에는 10개 ID 모두, `off`에는 끈 ID(종합은 절대 안 넣음), 중복 없음, 없는 ID 없음 — `resolveMenus`가 읽는 규칙과 어긋나지 않는다.
- **쓰기 함수는 `shell/menu-store.ts`에**(`saveMenus` · `resetMenus`). `storage` 이벤트는 다른 탭에서만 오므로, 같은 탭의 구독자(하단 탭 · 더보기 · 데스크톱 메뉴 줄 · 화면 구성)에게는 쓸 때 이벤트로 직접 알린다(글씨 크기 `font-scale-store.ts`와 같은 방식). 저장소가 막힌 환경에서는 쓰기가 조용히 실패하고 이번 화면 동안 메모리 값으로 계속 동작한다. **회원 계정 저장(L5)은 이 파일의 읽기 · 쓰기만 바꿔 끼운다.**
- **"기본값" = 저장값을 지운다**(`removeItem`). 기본값을 "써 두지" 않는 이유: 앞으로 메뉴가 늘거나 기본 순서가 바뀌면 기본값을 고른 사람은 새 기본을 따라가게 하려는 것이다(결정 0046의 "없는 ID는 끝에 켬"과도 맞음). 같은 이유로 **저장할 값이 기본 순서 · 모두 켬과 같으면 쓰지 않고 지운다**(`savedOrNull` — 예: 물을 끄고 다시 켜면 저장값이 사라진다). 시안에 되묻는 창이 없어서 두지 않았다.

### 6. 첫 그리기 — 깜박임 없음

이 화면은 **저장값을 읽은 뒤에야 목록을 그린다**(`useMenusReady`: 서버 · 첫 그리기는 false). 저장값이 있는 기기에서 목록이 기본 순서로 잠깐 보였다 바뀌는 일이 없고(시험이 줄이 처음 나타나는 순간의 순서와 서버 HTML에 목록이 없음을 확인), 목록 자리는 높이를 미리 잡아(`min-h`) 아래 "기본값" · 안내가 밀리지 않는다. 다른 화면(탭바 등)은 결정 0046 그대로 서버 기본값 → 기기 저장값이다.
