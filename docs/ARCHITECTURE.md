# 구조 (ARCHITECTURE)

## 큰 그림

```
croplib-dp (Python, 별도 저장소)  →  Supabase (DB)  →  이 저장소 (Next.js 화면)  →  Vercel (배포)
      수집·계산                        저장                    보여 주기                   공개
```

이 저장소는 계산하지 않습니다. DB에 저장된 값을 읽어서 보여 주기만 합니다. 공공 API 수집과 계산은 croplib-dp가 맡고, 둘은 `docs/DATA_CONTRACT.md`의 약속으로만 이어집니다.

## 폴더 4개

| 폴더           | 하는 일                                       | 예                                 |
| -------------- | --------------------------------------------- | ---------------------------------- |
| `src/domain`   | 표시·판정 규칙. 순수 함수만 둡니다.           | "17시간 넘게 갱신이 없으면 멈춤"   |
| `src/services` | 일의 순서. 자료를 읽고 화면용으로 정리합니다. | "관측소 자료 읽기 → 신선도 붙이기" |
| `src/infra`    | 바깥 연결. Supabase 같은 외부 서비스.         | "Supabase에서 표 읽기"             |
| `src/app`      | Next.js 화면과 API.                           | 홈 페이지                          |

그 밖에:

- `src/mocks` — 예시 값. `src/mocks/meta.ts`(발표 회차 등)와 `src/mocks/farm.ts`(내 농장 데모용 240개 계산 표, `FARM_SAMPLES`)가 있습니다.
- **내 농장 데모 화면** (이슈 #31, 결정 0018): 2027년 회원제 정식 오픈 전까지 시안과 똑같이 보여 주는 정적 미리보기 화면입니다. 화면에서 계산하지 않고, 시안 물수지 흉내 계산을 미리 돌려 뽑아 둔 240개 표(`src/mocks/farm.ts`)에서 `지점|작물|흙번호` 키로 읽기만 합니다. 주소 맞추기와 흙 12종 목록은 `src/domain/farm-preview.ts`의 `farmMatch(addr)` 순수 함수(테스트 있음)가 맡고, 화면은 클라이언트 컴포넌트(`src/app/_components/farm/FarmScreen.tsx`) 하나입니다. CSV 올리기는 파일 이름만 표시하며, "예시 파일로 보기"로 정적 보고서를 열고 다시 올리기로 초기화할 수 있습니다.
- **DB에서 읽는 쪽**: 물 화면(`src/services/water.ts`)이 처음입니다. 읽기는 `src/infra/supabase/water-source.ts`(공개 키, 필요한 열만, 8초 제한, 자동 재시도 끔), 이름·날짜 붙이기는 `src/domain/water-outlook.ts`가 합니다. DB에 닿지 못하면 쪽은 멈추지 않고 "자료 없음"과 이유를 보여 줍니다. 쪽을 요청마다 그리도록 `connection()`을 부릅니다. 지역 칩 점 색(`src/services/station-status.ts`, `src/infra/supabase/status-source.ts`)과 온도·햇빛 자료 상자의 관측 시각도 DB에서 읽습니다. 헤더는 모든 쪽에 나오므로 `SiteHeaderWithStatus`가 서버에서 읽어 30분 동안 재사용(`use cache`, 결정 0038)하고, 브라우저 쪽 헤더에 넘깁니다. 종합 화면 물 카드·전국 표도 같은 판정 표(`getStationBoard`, 캐시는 `src/app/_components/shell/board.ts` 한 곳)를 씁니다. 판정 표의 사과·배추·토양 칸은 모두 같은 지점 범위(운영 97곳)로 만들어, 헤더의 지역 목록 배지와 선택 줄이 대표 밖 지점에서도 같은 판정을 읽습니다(`statusesOf`는 보드의 칸을 그대로 따르고, 범위가 대표 10곳인 호출은 10곳 그대로, 운영 97곳 밖 지점은 "자료 없음", 이슈 #138). 전국 표 행은 대표 10곳 설계 그대로입니다. 온도·햇빛 카드와 전국 표 생육 칸은 지점 10곳의 마지막 관측일 적산온도·적산일사(`src/services/growth-latest.ts`, 온도·햇빛 화면의 지역 비교와 같은 읽기)를 판정 표와 따로 30분 동안 재사용합니다(`loadGrowth`, 같은 `board.ts`, 결정 0038). 헤더는 이 값을 쓰지 않습니다. 종합 화면의 5초 주기 자동 순환은 서버 요청 없이 클라이언트 상태로만 돌며, 탭이 숨겨지면 멈추고 30분 주기로만 최신 자료를 백그라운드 갱신합니다 (결정 0038).
- **지점 사전**: `src/infra/stations.ts` 고정 목록(기상청 ASOS 105곳: 현행 운영 97곳 + 폐지·휴지 보존 8곳, 번호·이름·시도·대표 여부·운영 여부·일사 관측 여부). 주소창 읽기와 지역 검색에 바로 쓰려고 DB 를 묻지 않으며, DB 사전 자료와 같은지는 `seed.test.ts`가 검사합니다.

- **온도 화면** (온1): 읽기는 `src/infra/supabase/heat-source.ts`(물 화면과 같은 방식), 화면용 정리는 `src/services/temperature.ts`, 문구·단계 도달일 찾기는 `src/domain/heat.ts`. 조각은 `src/app/_components/temperature/`: `TemperatureBoard`(순서·자료 상자), `SpeedCard`(생육 속도·단계 카드), `HeatChartCard`(누적 그래프, 좌표는 `heat-chart.ts`), `CompareCard`(저온요구량·지역 비교). 고른 지점과 지역 비교는 따로 읽어, 한쪽이 실패해도 다른 쪽은 보입니다. 지역 비교는 대표 10곳에 더해, 지금 고른 지점이 대표 밖이면 그 지점 1곳을 함께 읽어 맨 위에 구분선과 함께 띄웁니다 (결정 0043).
- **햇빛 화면** (온1): 읽기는 `src/infra/supabase/sun-source.ts`, 화면용 정리는 `src/services/sunlight.ts`, 평년 대비 %·월별 합·가장 적은 달·문구는 `src/domain/sun.ts`. 조각은 `src/app/_components/sunlight/`: `SunlightBoard`(순서·자료 상자), `SunCards`(올해 쌓인 햇빛·월별·지역 비교·재지 않는 지점). 누적 그래프는 온도 화면의 `HeatChartCard`(제목을 받음)를 같이 쓰고, 막대 좌표는 `sun-chart.ts`. 그 지점 `sun_daily` 줄이 없으면 "햇빛을 재지 않는 지점"입니다(DB 기준). 재지 않는 지점이면 가까운 운영 지점 8곳 중 올해 `sun_daily` 줄이 있는 2곳을 대신 볼 지점으로 보여 준다(거리순은 `src/domain/nearby.ts`). 읽기 실패 시 대표 실측 지점 중 가까운 곳으로 대신한다 (결정 0044). 지역 비교는 온도 화면과 같이 대표 10곳에 지금 고른 대표 밖 지점 1곳을 맨 위에 붙입니다 (결정 0043).

Playwright 가 먼저 띄웁니다. **날짜 규칙**: 달력 날짜(예: 04-01)를 고정해 쓰지 않고, 작기는 "오늘" 기준 상대 날짜(사과 = 오늘 안, 배추 = 오늘 밖)라 어느 날 돌려도 같은 결과입니다. 날짜를 바꿔 돌려 보려면 `E2E_TODAY=YYYY-MM-DD npm run test:e2e` (서버 쪽은 `e2e/fake-clock.mjs`, 시험·브라우저 쪽은 `e2e/fixtures.ts` 의 `e2eNow()`·브라우저 시계가 같은 날로 맞춤). 한국 날짜가 1월 1~3일이면 올해 자료가 거의 없어 `E2E_TODAY`를 주지 않아도 자동으로 그해 1월 4일로 돌립니다 (`playwright.config.ts`).

## 화면 공통 규칙

- **디자인 토큰**: 색·글꼴·글자 크기·모서리·그림자·배치 기준 폭은 `src/app/tokens.css` 한 곳에 둡니다. 화면은 토큰 이름(`bg-brand`, `text-15`, `rounded-card` …)만 씁니다. Tailwind 기본 색·글자 크기·모서리는 지워 두어, 토큰에 없는 값은 효과가 없습니다.
- **지역·작물·토양 선택**: 주소창 `?st=<지점 번호>&crop=<common|apple|cabbage>`에 남겨 모든 메뉴에 이어집니다. 읽고 쓰는 규칙은 `src/domain/selection.ts`에 있습니다. 기본 작물은 `"common"`(`작물 공통`)이며, 현행 운영(`isActive: true`) 지점 97곳을 모두 허용하고 값이 없거나 잘못되었거나 폐지·휴지 지점(`isActive: false`)이면 춘천(101)·작물 공통으로 돌립니다. 작물 공통일 때는 토성 12종 선택을 `&soil=<코드>`(기본값 `"loam"` 양토이면 생략)로 주소창에 남기고, 사과·배추로 바꾸면 `soil`을 지웁니다. 종합 화면의 5초 자동 전환(`home/AutoRotate.tsx`)은 **데스크톱(폭 1024 이상)에서만** 돕니다 — 휴대폰에서는 타이머도 돌지 않고 "n / 10"·중지/시작 버튼·진행 막대도 그리지 않습니다(`matchMedia`로 폭을 읽고, 서버·첫 그리기는 "돌지 않음"에서 시작, 폭이 바뀌면 따라감. 기준 폭은 `DESKTOP_MIN_WIDTH`, 결정 0053). 대표 10곳 밖 지점을 고르면 자동 전환은 멈추고("대표 지점 밖"), 아직 물 계산 시나리오가 없는 화면(종합·물·온도)은 "이 지점은 아직 물 계산을 하지 않아요. 가까운 대표 지점을 골라 보세요"를 안내합니다. 재배 방식은 사과·배추일 때만 `&kc=<번호>`(FAO-56 Table 12 순서, `crop_kc_sets.set_no`)로 붙으며, 지역을 바꾸면 그대로, 작물을 바꾸면 빠집니다. 물 화면만 기준 날짜 `&d=YYYY-MM-DD`(오늘이면 없음)와 발표 회차 `&run=02|17`을 더 붙이고, 다른 메뉴로 가면 빠집니다.
- **주소창 읽기**: `cacheComponents` 설정 때문에 주소창 값을 읽는 부분은 `<Suspense>` 안에 둡니다. 쪽 파일은 `ShellPage`/`HomeHead`에 `searchParams`를 넘기기만 합니다.
- **폭**: px로 고정하지 않습니다. 내용 최대 폭(`--page-max` 1440)과 가장자리 여백(`--page-gutter`)은 토큰에 있고, 2열→1열이 바뀌는 폭은 `--breakpoint-desktop`(1024), 대표 10개 칩이 단일 버튼으로 접히는 폭은 `--breakpoint-wide`(1280)입니다.
- **메뉴(셸)**: 메뉴의 고정 ID·이름·주소·상태(운영/준비 중)와 "설정값 → 보여 줄 메뉴" 규칙은 `src/domain/menus.ts`(`MENU_DEFS`, `resolveMenus`)가 갖고, 설정값은 기기(`localStorage` 키 `cropmon-menus`, `{"v":1,"order":[…],"off":[…]}`)에서 `shell/menu-store.ts` 의 `useMenus()` 가 읽습니다(저장소가 막혔거나 값이 깨졌거나 모르는 판이면 기본값, 읽을 때는 덮어쓰지 않음 — 쓰는 곳은 화면 구성 화면(`/layout`)뿐이고 `saveMenus` · `resetMenus` 가 같은 파일에 있음, 아래 항목. 첫 그리기는 기본값, 저장값은 화면이 뜬 뒤 적용). 데스크톱(1024 이상)은 `shell/SiteHeader.tsx` 의 상단 메뉴 줄(기본 순서 고정, 끈 메뉴만 숨김, 폭 1440 미만은 글자만, 결정 0046), 휴대폰은 `shell/TabBar.tsx` 의 하단 탭바(켠 메뉴 위에서 4개 + 더보기 맨 오른쪽 고정)입니다 — **화면 아래 끝에 붙은 전체 폭 유리 막대**(좌우·아래 여백 0, 모서리 0, 위쪽에만 머리카락 선, 그림자 없음, 탭 줄 높이 `--tabbar-h` 54 + 아래 안전 영역을 안쪽 여백으로 더함, `fixed`, `viewportFit: cover`)이고, 아래 안전 영역은 `tokens.css` 의 `--tabbar-safe-bottom` 한 곳(바닥글 여백도 이 값)이며, 좌우 안전 영역도 안쪽 여백입니다(결정 0054, 예전 떠 있는 캡슐은 0026 · 0046). 더보기(`/more`, `shell/MoreList.tsx`)는 켠 메뉴 목록과 "숨긴 메뉴 n개" 줄을 보여 줍니다(지역·작물 줄 없음). 새 쪽 관측·농사정보·병해충·일지(`/outlook` `/farminfo` `/pest` `/diary`)는 토양·시세와 같은 "준비 중" 본문(`ShellPage`)입니다. 두 `nav` 의 `aria-label` 은 같은 "메뉴"입니다. 소개·로그인 창(z-40)과 작물·지역 고르기 판의 덮개(z-40)가 탭바(z-30)를 덮습니다. 결정은 `docs/decisions/0026-mobile-tabbar.md`, `docs/decisions/0046-menu-ids-and-saved-layout.md`.

## 방향: 안쪽은 바깥을 모른다

```
app  →  services  →  domain
             ↓
           infra
```

- 화살표는 "불러다 쓴다"는 뜻입니다. 거꾸로는 불러다 쓰지 않습니다.
- **domain은 바깥을 모릅니다.** 화면(React, Next.js), DB(Supabase), 네트워크를 불러오지 않습니다. 시각이 필요하면 직접 시계를 보지 않고 값으로 받습니다. 예를 들어 `getFreshness(마지막갱신, 지금)`은 "지금"을 인자로 받습니다.
- 이렇게 하면 domain 규칙은 DB나 화면 없이 테스트만으로 확인할 수 있고, DB나 화면이 바뀌어도 규칙은 그대로 남습니다.
- 이 원칙은 ESLint가 자동으로 검사합니다. `src/domain`에서 화면·DB·다른 폴더 코드를 불러오면 `npm run lint`가 실패합니다.

## 앱 대비 (결정 0033)

모바일 앱은 Capacitor가 배포된 웹 주소를 불러오는 방식이라 웹 구조는 그대로입니다. 네이티브로 붙이는 것은 푸시·지오펜스·로컬 알림뿐입니다.

- `src/services`, `src/infra` 는 `next`, `next/*` 를 불러오지 않습니다 (테스트 포함). ESLint가 자동으로 검사합니다.
- Next.js 서버 기능(`next/cache`, `next/headers`, `use cache` 등)은 `src/app` 에만 둡니다.
- 새 판정 규칙은 `src/domain` 순수 함수로 둡니다.

## 운영 예약 (결정 0014)

croplib-dp 수집은 Supabase pg_cron 이 정해진 시각에 GitHub 워크플로를 실행시킨다(`ops.dispatch_workflow`, 토큰은 Vault `github_dispatch_token`). 운영용 이름공간 `ops` 는 화면·회원이 볼 수 없다. 최근 실행 요청 결과는 `select * from ops.dispatch_recent;`.

## 리전 (결정 0034)

Supabase 는 서울(ap-northeast-2), Vercel 함수도 서울(icn1)에 둔다. 두 곳이 다른 리전이면 화면 요청마다 먼 길을 오가 느려지므로, 한쪽을 바꿀 때는 다른 쪽도 같은 리전인지 확인한다. 프로젝트를 새로 만들어 옮기는 순서는 결정 0034 에 있다.
